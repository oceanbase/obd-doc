# 交互式安装 OceanBase 数据库

obd 自 V3.2.0 起支持交互式安装 OceanBase 数据库，本文介绍具体操作。

## 前提条件

在开始之前，请确保您已满足以下条件：

* 所用用户为 root 用户，或拥有 sudo 权限。

* 需使用 OceanBase All in One 安装 obd，且 obd 需为 V3.2.0 或之后版本。

## 操作步骤

### 步骤一：下载并解压 OceanBase All in One

从 [OceanBase 软件下载中心](https://www.oceanbase.com/softwarecenter) 下载最新的 OceanBase All in One，推荐使用最新版本的安装包。执行如下命令解压。

```shell
[admin@test001 ~]$ tar -xzf oceanbase-all-in-one-*.tar.gz
```

### 步骤二：启动交互式安装

进入 OceanBase All in One 的安装目录，执行如下命令启动交互式安装流程。

```shell
[admin@test001 oceanbase-all-in-one]$ bash bin/standalone.sh
```

您需在交互式安装流程中输入如下内容。

1. 填写当前用户信息

   进入交互式安装流程后，需在打印内容的对应位置输入并二次确认当前用户的登录密码，具体如下

   ```shell
   Enter the current user password : *******
   Re-enter the current user password : *******
   ```

   若已为当前用户设置免密登录，可直接单击键盘上 `Enter` 跳过。输入当前用户密码后，程序会自动安装 obd，并将 OceanBase All in One 中包含的组件安装包复制到 obd 本地镜像库。

2. 配置集群信息

   <!-- 后续流程是解压安装包，还是上传安装包到obd 的本地镜像库呀 -->
   安装包复制完成后，会提供交互式问题，您需在对应位置设置 OceanBase 集群的集群名、端口、租户名、租户密码等信息，具体如下：

   ```shell
   Enter the cluster name (letters, numbers, and underscores are supported):  #设置集群名，支持字母、数字和下划线，未设置时默认为 standalone
   <!-- 需要确认具体格式，如是否支持第一位或最后一位为下划线、支持集群名的最大或最小位数
   目前部署验证是没有强制要求必须包含的，纯字母也是可以部署的 -->
   Enter the MySQL port (default: 2881):       #设置 MySQL 端口，相当于配置文件中的 mysql_port，未设置时默认为 2881
   Enter the RPC port (default: 2882):         #设置 RPC 端口，相当于配置文件中的 rpc_port，未设置时默认为 2882
   Enter the OBSHELL port (default: 2886):     #设置 obshell 端口，相当于配置文件中的 obshell_port，未设置时默认为 2886
   Enter the tenant name (default: test; allowed characters: letters, numbers, and underscores):  #设置租户名，支持字母、数字和下划线，未设置时默认为 test
   <!-- 这里说明是否需要和集群名统一，多了 allowed characters:  -->
   Enter the tenant password :     #设置 root@test 用户密码，未设置时默认为空
   Re-enter the tenant password:   #二次确认 root@test 用户密码
   Enter the installation directory: (default: /home/root/test)  #设置 OceanBase 集群的安装目录，相当于配置文件中的 home_path，未设置时默认为 /home/${user_name}/${cluster_name}
   <!-- 这三个默认值都是在 ：后面，和上文格式不一样，是否需要统一-->
   Enter the data directory: (default: /data/1)      #设置存储 SSTable 等数据的目录，相当于配置文件中的 data_dir，未设置时默认为 /data/1  
   Enter the log directory: (default: /data/log1)    #设置存储日志的目录，相当于配置文件中的 redo_dir，未设置时默认为 /data/log1
   Do you need to install monitoring? (y/n):         #控制是否安装监控，输入 y 后，程序会安装 obagent、prometheus 和 grafana 组件，输入 n 将仅安装 OceanBase 数据库
   ```

3. （可选）配置监控信息

   若您在 `Do you need to install monitoring? ` 中输入 `y`，您需设置监控相关信息，具体如下：

   ```shell
   Follow the prompts to enter the configuration.
   Enter the OBAgent monitoring service port (default: 8088):   #设置 OBAgent 监控服务端口，相当于配置文件中的 monagent_http_port，未设置时默认为 8088
   Enter the OBAgent management service port (default: 8089):   #设置 OBAgent 管理服务端口，相当于配置文件中的 mgragent_http_port，未设置时默认为 8089
   Enter the PROMETHEUS port (default: 9090):    #设置 Prometheus 端口，未设置时默认为 9090
   Enter the GRAFANA port (default: 3000):       #设置 Grafana 端口，未设置时默认为 3000
   Enter the GRAFANA login password (must be longer than 5 characters) (default: oceanbase):    #设置 Grafana 登录密码，密码需超过五个字符，未设置时默认为 oceanbase
   <!-- 有其他要求么，比如支持的特殊字符 -->
   ```

4. 确认配置

   程序会输出您刚刚设置的配置，您需确认这些配置是否正确，示例如下：

   ```shell
   Saved configurations:
   cluster name: obtest
   mysql port: 2881
   rpc port: 2882
   obshell port: 2886
   tenant name: obmysql
   tenant password: ********
   home path: /root/obtest
   data dir: /data/1
   log dir: /data/log1
   OBAgent monitoring service port: 8088
   OBAgent management service port: 8089
   PROMETHEUS port: 9090
   GRAFANA port: 3000
   GRAFANA login_password: ********
   Are you sure that these configurations are correct？(y/n): 
   ```

   您需在确认位置输入 `y` 或 `n`：若您输入为 `y`，程序会开始根据配置部署 OceanBase 集群，您可根据下文步骤继续部署；若您输入为 `n`，部署流程会直接结束。

5. 设置集群负载类型

   您可在下文输出位置设置集群负载类型，各个负载类型的介绍可参见 [配置文件说明](../400.user-guide/100.configuration-file-description.md) 中 OceanBase 数据库下的 scenario 配置介绍。

   ```shell
   Open ssh connection ok
   Scenario not specified, please specify the scenario you want.
   1. express_oltp
   2. complex_oltp
   3. olap
   4. htap (default)
   5. kv
   Please input the scenario [default: 4]:  #设置集群负载类型，仅需输入各个负载类型前的数字，未设置时默认为 htap 类型
   ```

6. 选择是否更改参数
   这里选择 y 和 n 都是继续部署呀，没有区别哎

7. 设置租户负载类型

   您可在下文输出位置设置租户负载类型，各个负载类型的介绍可参见 [配置文件说明](../400.user-guide/100.configuration-file-description.md) 中 OceanBase 数据库下的 scenario 配置介绍。

   ```shell
   Tenant optimization scenario not specified, please specify the scenario you want to optimize.
   1. express_oltp
   2. complex_oltp
   3. olap
   4. htap (default, follow cluster)
   5. kv
   Please input the scenario you want to optimize [default: 4]:   #设置租户负载类型，仅需输入各个负载类型前的数字，未设置时默认跟随集群负载类型
   ```

### 步骤三：验证部署结果

1. 查看集群列表

   可执行 `obd cluster list` 命令查看集群列表，输入如下，存在部署名为 `obtest` 的集群且状态为 `running`，表示集群处于运行中。

   ```shell

   +--------+---------------------------+-----------------+
   | Name   | Configuration Path        | Status (Cached) |
   +--------+---------------------------+-----------------+
   | obtest | /root/.obd/cluster/obtest | running         |
   +--------+---------------------------+-----------------+
   ```

4. 连接 OceanBase 集群

   您可复制 obd cluster display 命令中输出的连接串连接 OceanBase 数据库的 sys 租户，也可根据配置的租户名和密码连接用户租户。连接 OceanBase 数据库的具体介绍可参见官网《OceanBase 数据库》文档 [通过 OBClient 连接 OceanBase 租户](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002013251)。

   ```shell
   obclient -h10.10.10.1 -P2881 -uroot@obmysql -p
   ```
