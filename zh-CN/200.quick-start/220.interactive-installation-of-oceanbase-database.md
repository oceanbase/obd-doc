# 交互式安装 OceanBase 数据库

obd 自 V3.2.0 起支持交互式安装 OceanBase 数据库，本文介绍具体操作。

## 前提条件

在开始之前，请确保您已满足以下条件：

* 所用用户为 root 用户，或拥有 sudo 权限。

* 需使用 OceanBase All in One 安装 obd，且 obd 需为 V3.2.0 或之后版本。

* 当前机器可以访问待创建 OceanBase 数据库的机器。

### 步骤一：下载并解压单机版安装包

获取单机版安装包，执行如下命令解压。

<main id="notice" type='explain'>
   <h4>说明</h4>
   <p>目前 OceanBase 未提供单机版安装包的下载途径，您需联系技术支持人员获取对应安装包。</p>
</main>
<!-- 需根据最终命名修改描述和命令 -->
```shell
[admin@test001 ~]$ tar -xzf standalone-all-in-one.tar.gz
```

### 步骤二：启动交互式安装

进入 OceanBase All in One 的安装目录，执行如下命令启动交互式安装流程。

```shell
[admin@test001 oceanbase-all-in-one]$ bash bin/standalone.sh
```

您需在交互式安装流程中输入如下内容。

1. 填写当前用户信息

   进入交互式安装流程后，需在打印内容的对应位置输入待安装 OceanBase 数据库的机器 IP 及密码，并二次确认当前用户的登录密码，输出如下：
   <!-- 是可以输入为其他机器的，不局限于本机器对不
   输入的是安装 obd 以及 OB 集群的机器 IP 对不 -->
   ```shell
   Enter the IP (default: 10.10.10.1) (only support local IP):
   Enter the current user password : *******
   Re-enter the current user password : *******
   ```

   若已为当前用户设置免密登录，可直接单击键盘上 `Enter` 跳过。输入当前用户密码后，程序会自动安装 obd，并将 OceanBase All in One 中包含的组件安装包复制到 obd 本地镜像库。

2. 配置集群信息

   安装包复制完成后，会提供交互式问题，您需在对应位置设置 OceanBase 集群的集群名、端口、租户名、租户密码等信息，具体如下：

   ```shell
   #设置集群名，支持大小写字母、数字和下划线，不区分首字符类型。未设置时默认为 standalone
   Enter the cluster name (default: standalone; allowed characters: letters, numbers, and underscores): test
   <!-- 需要确认具体格式，支持集群名的最大或最小位数 -->
   #设置集群的 SQL 端口，相当于配置文件中的 mysql_port，未设置时默认为 2881
   Enter the OB SQL port (default: 2881): 
   #设置集群的 RPC 端口，相当于配置文件中的 rpc_port，未设置时默认为 2882
   Enter the OB RPC port (default: 2882): 
   #设置集群的 obshell 端口，相当于配置文件中的 obshell_port，未设置时默认为 2886
   Enter the OBShell port (default: 2886): 
   #设置集群可用 CPU 总数，未设置时 obd 会自动检测
   Enter the OB cpu count (default: 8):
   #设置集群所用内存，相当于配置文件中的 memory_limit
   Enter the OB memory limit (default: 29, unit: G):
   #设置 OceanBase 集群的安装目录，相当于配置文件中的 home_path，未设置时默认在用户家目录下创建集群同名文件夹
   Enter the OB installation directory (default: /root/test): 
   #设置存储 SSTable 等数据的目录，相当于配置文件中的 data_dir，未设置时默认为 /data/1/${cluster_name}
   Enter the OB data directory (default: /data/1/test):       
   #设置存储日志的目录，相当于配置文件中的 redo_dir，未设置时默认为 /data/log1/${cluster_name}
   Enter the OB log directory (default: /data/log1/test): 
   #设置集群的数据磁盘大小，相当于配置文件中的 datafile_size   
   Enter the OB datafile maxsize (default: 184, unit: G): 
   #设置集群的日志磁盘大小，相当于配置文件中的 log_disk_size
   Enter the OB log disk size (default: 87, unit: G): 
   #设置租户名，支持大小写字母、数字和下划线，不区分首字符类型。未设置时默认为 test
   Enter the tenant name (default: test; allowed characters: letters, numbers, and underscores): 
   <!-- 确定支持的最大和最小字符数 -->
   #设置租户的 root 用户密码，未设置时默认为空
   Enter the tenant password: 
   #二次确认 root 用户密码
   Re-enter the tenant password: 
   #设置待创建租户的可用 CPU，未设置时默认使用集群剩余全部可用 CPU
   Enter the tenant cpu (default: 6): 
   #设置待创建租户的可用内存，未设置时默认使用集群剩余全部可用内存
   Enter the tenant memory (default: 5, unit: G): 
   #设置待创建租户的可用日志磁盘大小
   Enter the tenant log disk size(default: 16, unit: G): 
   #控制是否安装监控，输入 y 后，程序会安装 obagent、prometheus 和 grafana 组件，输入 n 将仅安装 OceanBase 数据库
     Do you need to install Monitoring Component(OBAgent, Prometheus, Grafana)? (y/n)(default: y): 
   ```

3. （可选）配置监控信息

   若您在 `Do you need to install Monitoring Component` 中输入 `y`，您需设置监控相关信息，具体如下：

   ```shell
   Follow the prompts to enter the configuration.
   #设置 OBAgent 监控服务端口，相当于配置文件中的 monagent_http_port，未设置时默认为 8088
   Enter the OBAgent monitoring service port (default: 8088): 
   #设置 OBAgent 管理服务端口，相当于配置文件中的 mgragent_http_port，未设置时默认为 8089
   Enter the OBAgent management service port (default: 8089): 
   #设置 Prometheus 端口，未设置时默认为 9090
   Enter the Prometheus port (default: 9090): 
   #设置 Grafana 端口，未设置时默认为 3000
   Enter the Grafana port (default: 3000): 
   #设置 Grafana 登录密码，密码需超过五个字符，未设置时默认为 oceanbase
   Enter the Grafana login password (must be longer than 5 characters) (default: oceanbase): 
   <!-- 有其他要求么，比如支持的特殊字符 -->
   ```

4. 确认配置

   程序会输出您刚刚设置的配置，您需确认这些配置是否正确，示例如下：

   ```shell
   #Saved configurations:
   cluster name: test
   mysql port: 2881
   rpc port: 2882
   obshell port: 2886
   cpu count: 8
   memory limit: 8G
   home path: /root/test
   data dir: /data/1/test
   log dir: /data/log1/test
   datafile maxsize: 20G
   log disk size: 20G
   tenant name: obmysql
   tenant password:
   tenant cpu: 6
   tenant memory: 2G
   tenant log disk size: 3G
   OBAgent monitoring service port: 8088
   OBAgent management service port: 8089
   Prometheus port: 9090
   Grafana port: 3000
   Grafana login_password: oceanbase

   Are you sure that these configurations are correct？(y/n)(default: y): 
   ```

   您需在确认位置输入 `y` 或 `n`：若您输入为 `y`，程序会开始根据配置部署 OceanBase 集群，您可根据下文步骤继续部署；若您输入为 `n`，部署流程会直接结束。

5. 设置集群负载类型
   <!-- 验证到这一步，部署报错了，所以没有继续走下去 -->
   您可在下文输出位置设置集群负载类型，各个负载类型的介绍可参见 [配置文件说明](../400.user-guide/100.configuration-file-description.md) 中 OceanBase 数据库下的 `scenario` 配置介绍。

   ```shell
   Open ssh connection ok
   Scenario not specified, please specify the scenario you want.
   1. express_oltp
   2. complex_oltp
   3. olap
   4. htap (default)
   5. kv
   #设置集群负载类型，仅需输入各个负载类型前的数字，未设置时默认为 htap 类型
   Please input the scenario [default: 4]: 
   ```

6. 选择是否更改参数
   <!-- 这里选择 y 和 n 都是继续部署呀，没有区别哎 -->

7. 设置租户负载类型

   您可在下文输出位置设置租户负载类型，各个负载类型的介绍可参见 [配置文件说明](../400.user-guide/100.configuration-file-description.md) 中 OceanBase 数据库下的 `scenario` 配置介绍。

   ```shell
   Tenant optimization scenario not specified, please specify the scenario you want to optimize.
   1. express_oltp
   2. complex_oltp
   3. olap
   4. htap (default, follow cluster)
   5. kv
   #设置租户负载类型，仅需输入各个负载类型前的数字，未设置时默认跟随集群负载类型
   Please input the scenario you want to optimize [default: 4]: 
   ```

### 步骤三：验证部署结果

1. 查看集群列表

   可执行 `obd cluster list` 命令查看集群列表，输入如下，存在部署名为 `obtest` 的集群且状态为 `running`，表示集群处于运行中。

   ```shell

   | Name   | Configuration Path        | Status (Cached) |
   +--------+---------------------------+-----------------+
   | obtest | /root/.obd/cluster/obtest | running         |
   +--------+---------------------------+-----------------+
   ```
