# 备份与恢复

obd 自 V3.2.0 起支持通过命令进行租户备份与恢复的功能，本文详细介绍如何操作。

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>使用 obd 命令进行备份与恢复时，涉及集群需是被 obd 管理的集群，否则 obd 无法获取集群的信息。obd 部署的集群默认由 obd 管理，非 obd 部署的集群可执行接管操作进行接管。接管的详细操作可参见 <a href='../300.command-line-operations/450.takeover-cluster.md'>使用 obd 接管集群</a>。</p>
</main>

## 前提条件

在开始之前，请确保您已满足以下条件：

* 您已安装 V3.2.0 或之后版本 obd，建议安装最新版本。安装 obd 的详细操作您可参见 [安装 obd](../../200.quick-start/100.install-obd.md)。

* 待备份或恢复的租户所在集群中存在 obshell，且 obshell 处于正常运行状态。

* 已配置合适的备份目的端。

## 租户备份

1. 执行备份

   :::tab

   tab 执行全量备份

   ```shell
   obd cluster tenant backup test obmysql 10.10.10.1 'file:///data/nfs/backup/data' 'file:///data/nfs/backup/log'
   ```

   tab 执行增量备份

   ```shell
   obd cluster tenant backup test obmysql 10.10.10.1 'file:///data/nfs/backup/data' 'file:///data/nfs/backup/log' -m incremental
   ```

   :::

   此处以使用 NFS 作为备份目的端，对部署名为 `test` 的集群的 `obmysql` 租户进行备份为例。您需根据实际情况修改示例，建议使用 OSS 作为备份的目的端。

2. 查看备份任务

   ```shell
   obd cluster tenant backup-show test obmysql 10.10.10.1
   ```

   此处以备份租户为部署名 `test` 集群中的 `obmysql` 租户，OBServer 节点为 `10.10.10.1` 为例，您需根据实际情况修改示例。输出如下，`task_status` 列状态为 `COMPLETED` 表示备份成功。

   ```shell
   +---------------------------------------------------------------------------------------------------------+
   |                               backup task details of backup tenant obmysql                              |
   +-----------+----------------------------------+----------------------------------+-------------+---------+
   | tenant_id | start_timestamp                  | end_timestamp                    | task_status | comment |
   +-----------+----------------------------------+----------------------------------+-------------+---------+
   | 1002      | 2025-03-12T15:34:20.450999+08:00 | 2025-03-12T15:35:53.267108+08:00 | COMPLETED   | -       |
   +-----------+----------------------------------+----------------------------------+-------------+---------+
   ```

3. （可选）取消备份任务

   ```shell
   obd cluster tenant backup-cancel test obmysql 10.10.10.1
   ```

   执行取消备份命令后，可等几分钟后执行 `obd cluster tenant backup-show` 命令查看备份任务是否已取消，输出如下，`task_status` 列状态为 `CANCELED` 表示备份任务已取消。

   ```shell
   +--------------------------------------------------------------------------------------------------------------------+
   |                                    backup task details of backup tenant obmysql                                    |
   +-----------+----------------------------------+----------------------------------+-------------+--------------------+
   | tenant_id | start_timestamp                  | end_timestamp                    | task_status | comment            |
   +-----------+----------------------------------+----------------------------------+-------------+--------------------+
   | 1002      | 2025-03-12T17:40:02.359938+08:00 | 2025-03-12T17:40:55.408552+08:00 | CANCELED    | Operation canceled |
   +-----------+----------------------------------+----------------------------------+-------------+--------------------+
   ```

## 租户恢复

1. 执行恢复

   ```shell
   obd cluster tenant restore obtest restore_1 10.10.10.2 'file:///data/nfs/backup/data' 'file:///data/nfs/backup/log' zone1 2G 2
   ```

   示例中以 NFS 为备份目的端，在部署名为 `obtest` 的集群中创建 `restore_1` 租户，并将备份数据恢复到该租户为例，您需根据实际情况修改示例。

2. 查看恢复任务

   ```shell
   obd cluster tenant restore-show obtest restore_1 10.10.10.2
   ```

   此处以恢复租户为部署名 `obtest` 集群中的 `restore_1` 租户，OBServer 节点为 `10.10.10.2` 为例，您需根据实际情况修改示例。输出如下，`task_status` 列状态为 `SUCCESS` 表示恢复成功。

   ```shell
   +---------------------------------------------------------------------------------------------------------+
   |                              restore task details of restore tenant obtest                              |
   +-----------+----------------------------------+----------------------------------+-------------+---------+
   | tenant_id | start_timestamp                  | end_timestamp                    | task_status | comment |
   +-----------+----------------------------------+----------------------------------+-------------+---------+
   | 1         | 2025-03-12T17:10:10.017513+08:00 | 2025-03-12T17:15:10.645282+08:00 | SUCCESS     | -       |
   +-----------+----------------------------------+----------------------------------+-------------+---------+
   ```

3. 查看集群租户

   ```shell
   obd cluster tenant show obtest
   ```

   输出如下：

   ```shell
   +-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
   |                                                                                     tenant base info                                                                                    |
   +-------------+-------------+--------------------+--------------+---------+---------+-------------+---------------------+---------------------+---------------+-------------+-------------+
   | tenant_name | tenant_type | compatibility_mode | primary_zone | max_cpu | min_cpu | memory_size | max_iops            | min_iops            | log_disk_size | iops_weight | tenant_role |
   +-------------+-------------+--------------------+--------------+---------+---------+-------------+---------------------+---------------------+---------------+-------------+-------------+
   | sys         | SYS         | MYSQL              | RANDOM       | 3.0     | 3.0     | 1G          | 9223372036854775807 | 9223372036854775807 | 2G            | 3           | PRIMARY     |
   | restore_1   | USER        | MYSQL              | RANDOM       | 2.0     | 2.0     | 2G          | 9223372036854775807 | 9223372036854775807 | 6G            | 2           | STANDBY     |
   +-------------+-------------+--------------------+--------------+---------+---------+-------------+---------------------+---------------------+---------------+-------------+-------------+
   +------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
   |                                                                                                 standby tenant standby info                                                                                                  |
   +---------------------+---------------+-----------------+----------------------------+----------+------------------------------------------------------------------------+-------------------+------------------+--------------+
   | standby_tenant_name | tenant_status | sync_status     | sync_scn_timestamp         | err_code | error_comment                                                          | switchover_status | switchover_epoch | log_mode     |
   +---------------------+---------------+-----------------+----------------------------+----------+------------------------------------------------------------------------+-------------------+------------------+--------------+
   | restore_1           | RESTORE       | RESTORE SUSPEND | 2025-03-12 17:08:10.369983 | 0        | Restore suspend, the log stream has synchronized to recovery until scn | NORMAL            | 0                | NOARCHIVELOG |
   +---------------------+---------------+-----------------+----------------------------+----------+------------------------------------------------------------------------+-------------------+------------------+--------------+
   +---------------------------------------------------+
   |           standby tenant`s primary info           |
   +---------------------+-----------------------------+
   | standby_tenant_name | primary_tenant_info         |
   +---------------------+-----------------------------+
   | restore_1           | file:///data/nfs/backup/log |
   +---------------------+-----------------------------+
   ```

4. （可选）取消恢复任务

   可执行如下命令取消租户恢复任务，需注意，仅可取消非 SUCCESS 状态的恢复任务。

   ```shell
   obd cluster tenant restore-cancel obtest restore_1 10.10.10.2
   ```

   命令执行成功后，可执行 `obd cluster tenant show` 命令查看集群中的租户（输出中无 `obtest` 租户），或执行 `obd cluster tenant restore-show` 命令查看恢复任务（报错无对应租户）。
