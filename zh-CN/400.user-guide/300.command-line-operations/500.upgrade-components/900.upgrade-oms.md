# 升级 OMS

本文介绍如何通过 obd 的图形化界面操作升级 OMS。

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>目前 obd 仅支持升级 OMS 社区版。</p>
</main>

## 前提条件

在开始之前，请确保您已满足以下条件：

* 待升级的 OMS 的部署方式为使用 obd 部署。

* 您已安装 obd V4.0.0 或之后版本，建议安装最新版本，详细信息请参考 [安装 obd](../../../200.quick-start/100.install-obd.md)。

## 操作步骤

### 步骤一：获取升级所需安装包

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>如待升级的 OMS 为多节点 OMS，每个节点都需要执行如下操作。</p>
</main>

1. 下载安装包

   访问 [OceanBase 软件下载中心](https://www.oceanbase.com/softwarecenter)，搜索 **OceanBase 迁移服务**，根据实际情况下载所需安装包，并将安装包上传至 obd 中控机器任一目录下。

2. 加载下载的 OMS 安装包至 Docker 容器的本地镜像仓库

   ```shell
   [admin@test001 ~]$ sudo docker load -i oms_4.2.11-ce.tar.gz
   ```

3. 验证加载是否成功

   ```shell
   [admin@test001 ~]$ sudo docker images
   ```

   输出如下：

   ```shell
   REPOSITORY                                    TAG                 IMAGE ID       CREATED        SIZE
   reg.docker.alibaba-inc.com/oceanbase/oms-ce   feature_4.2.11_ce   26f5f1554fc5   2 months ago   12.5GB
   reg.docker.alibaba-inc.com/oceanbase/oms-ce   feature_4.2.12_ce   28fddcdaf8a0   2 days ago     12.5GB
   ```

### 步骤二：升级 OMS

1. 关闭 HA

   HA 指高可用模块（High Available，简称 HA），为数据传输链路的稳定性和连续性提供保障。升级前需禁用 HA 功能，如果开启了 HA 功能，请先参考如下步骤关闭 HA：

   * 登录 OMS 社区版控制台。

   * 在左侧导航栏，单击 **系统管理** > **系统参数**。

   * 在 **系统参数** 页面，找到 `ha.config`。

   * 单击该参数名称 **取值** 后的编辑图标。

   * 在 **修改取值** 对话框中，设置 `enable` 为 `false`，关闭 HA 功能。

2. 执行升级命令

   执行如下命令升级 OMS。

   ```shell
   obd cluster upgrade myoms -c oms-ce --tag=feature_4.2.12_ce --image-name=reg.docker.alibaba-inc.com/oceanbase/oms-ce --oms-backup-path=/data/oms/meta_backup_data
   ```

   该命令执行过程中需交互式确认一些信息，具体如下：

   1. 确认使用版本

      命令执行时将会输出升级过程中会使用到的 OMS 的镜像包，您需确认是否要使用展示的包。输入 `y` 将继续升级流程，输入 `n` 将退出升级流程。

      ```shell
      +---------------------------------------------------+
      |               Packages Will Be Used               |
      +--------+-------------------+--------------+-------+
      | name   | tag               | hash         | mark  |
      +--------+-------------------+--------------+-------+
      | oms-ce | feature_4.2.11_ce | 26f5f1554fc5 | start |
      | oms-ce | feature_4.2.12_ce | 28fddcdaf8a0 | dest  |
      +--------+-------------------+--------------+-------+
      If you use a non-official release, we cannot guarantee a successful upgrade or technical support when you fail. Make sure that you want to use the above package to upgrade. [y/n]: y
      ```

   2. 确认升级方法

      目前支持 **离线升级** 和 **在线升级** 两种 OMS 升级方式，在 `Enter the number of the oceanbase type you want to use:` 后输入升级方式前的数字，即可选择对应升级方式。

      * 离线升级：通过部署新版镜像容器来替换旧版容器，升级过程中运行链路将出现短暂中断。
      * 在线升级：在原有容器内直接替换组件包实现升级，确保运行链路全程无中断。

      ```shell
      Backup OMS meta databases using mysqldump ok
          Two types of OMS upgrade methods. Please choose one:
          1) Offline upgrade: Start a new container with the new image to replace the container with the old version image. The running migration tasks will be interrupted during the upgrade process.
          2) Online upgrade: Replace the component packages in the original container with those from the new image. The running migration tasks will not be affected.
      Enter the number of the oceanbase type you want to use: 2
      ```

   3. 指定存放升级文件路径

      若升级方式选择 **在线升级**，需要指定存放升级文件的路径。如果待升级的 OMS 中存在多个节点，您需为每一个节点都指定一次。

      ```shell
      10.10.10.1:Please specify a local directory(minimum 20GB) for exporting files from the OMS image. (Default: /data/oms/upgrade_docker_files):
      ```

   确认如上信息后，obd 将开始升级 OMS。

### 步骤三：验证

1. 确认机器状态

   升级完成后，您可登录 OMS 社区版控制台，在左侧导航栏，单击 **运维监控** > **机器**。在 **机器列表** 页面查看机器列表是否正常。同时，请确认机器的状态均为 **在线**。

2. 确认 OMS 版本

   登录 OMS 社区版控制台后，将光标悬停在页面右上角 **帮助中心**，单击 **关于 OMS**，将弹窗显示 OMS 信息，确认 OMS 版本是否为升级的目标版本。
