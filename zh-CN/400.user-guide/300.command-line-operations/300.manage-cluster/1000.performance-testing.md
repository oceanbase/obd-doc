# 性能测试

本文介绍如何使用 obd 命令对 OceanBase 集群进行性能测试。

<main id="notice" type='explain'>
  <h4>说明</h4>
  <ul>
  <li>
  <p>使用 obd 命令进行性能测试时，待测试的集群需是被 obd 管理的集群，否则 obd 无法获取集群的信息。obd 部署的集群默认由 obd 管理，非 obd 部署的集群可执行接管操作进行接管。接管的详细操作可参见 <a href='../400.takeover-cluster/450.takeover-cluster.md'>使用 obd 接管集群</a>。</p>
  </li>
  <li>
  <p>您也可选择基于官方测试工具手动逐步进行性能测试，详细操作可参见官网《OceanBase 数据库》文档 <a href="https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000001247760">参考指南/性能测试</a> 章节。</p>
  </li>
  </ul>
</main>

## 环境准备

测试前请按照如下要求准备您的测试环境：

* JDK：建议使用 1.8u131 及以上版本。

* make：可执行 `yum install make` 命令安装。

* gcc：可执行 `yum install gcc` 命令安装。

* OBClient：详细信息，请参考 [OBClient 文档](https://github.com/oceanbase/obclient/blob/master/README.md)。

* OceanBase 数据库：需部署 OceanBase 数据库，并创建执行测试的租户及用户。部署 OceanBase 数据库的操作可参见 [通过图形化界面部署 OceanBase 集群](../../200.ui-operations/200.use-ui-deploy-oceanbase.md)，创建租户可使用 `obd cluster tenant create` 命令，详细介绍可参见 [集群命令组](../../../300.obd-command/100.cluster-command-groups.md) 中 **obd cluster tenant create** 部分内容。

* iops：建议磁盘 iops 在 10000 以上。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <ul>
  <li>
  <p>部署集群时，建议不要使用 <code>obd cluster autodeploy</code> 命令，该命令为了保证稳定性，不会最大化资源利用率（例如不会使用所有内存），建议单独对配置文件进行调优，最大化资源利用率。</p>
  </li>
  <li>
  <p>sys 租户是管理集群的内置系统租户，请勿直接使用 sys 租户进行测试。</p>
  </li>
  </ul>
</main>

## TPC-H 测试

### TPC-H 概述

TPC-H（商业智能计算测试）是美国交易处理效能委员会（TPC，Transaction Processing Performance Council）组织制定的用来模拟决策支持类应用的一个测试集。目前，学术界和工业界普遍采用 TPC-H 来评价决策支持技术方面应用的性能。这种商业测试可以全方位评测系统的整体商业计算综合能力，对厂商的要求更高，同时也具有普遍的商业实用意义，目前在银行信贷分析和信用卡分析、电信运营分析、税收分析、烟草行业决策分析中都有广泛的应用。

TPC-H 基准测试由 TPC-D（由 TPC 于 1994 年制定的标准，用于决策支持系统方面的测试基准）发展而来的。TPC-H 用 3NF 实现了一个数据仓库，共包含 8 个基本关系，其主要评价指标是各个查询的响应时间，即从提交查询到结果返回所需时间。TPC-H 基准测试的度量单位是每小时执行的查询数（QphH@size），其中 H 表示每小时系统执行复杂查询的平均次数，size 表示数据库规模的大小，它能够反映出系统在处理查询时的能力。TPC-H 是根据真实的生产运行环境来建模的，这使得它可以评估一些其他测试所不能评估的关键性能参数。总而言之，TPC 组织颁布的TPC-H 标准满足了数据仓库领域的测试需求，并且促使各个厂商以及研究机构将该项技术推向极限。

### 操作步骤

您可参照如下步骤使用 obd 对 OceanBase 集群进行 TPC-H 测试。

1. 安装 obtpch

   ```shell
   sudo yum install -y yum-utils
   sudo yum-config-manager --add-repo https://mirrors.aliyun.com/oceanbase/OceanBase.repo
   sudo yum install obtpch
   ```

2. 为 obtpch 创建软连接

   ```shell
   sudo ln -s /usr/tpc-h-tools/tpc-h-tools/ /usr/local/
   ```

3. 执行 TPC-H 测试

   ```obshell
   obd test tpch test --tenant=tpch_mysql -s 100 --remote-tbl-dir=/tmp/tpch100
   ```

   `obd test tpch` 命令的详细介绍可参见 [测试命令组](../../../300.obd-command/300.test-command-group.md) 中 **obd test tpch**。

   执行测试时需注意如下信息：

   * 示例中以待测试的集群名为 `test`，租户名为 `tpch_mysql` 为例，您需根据实际情况进行替换（可执行 `obd cluster list` 命令查看集群名，并执行 `obd cluster tenant show <deploy_name>` 命令查看集群中存在的租户）。同时，您也可根据自己的具体情况做一些参数上的调整。

   * 运行 `obd test tpch` 后，系统会详细列出运行步骤和输出，数据量越大耗时越久。

   * `remote-tbl-dir` 远程目录需具备足够能存储 TPC-H 测试数据的容量，建议单独一块盘存储加载测试数据。

   * `obd test tpch` 命令会自动完成所有操作，无需其他额外任何操作，包含测试数据的生成、传送、OceanBase 数据库参数优化、加载和测试。当中间环节出错时，您可通过配置参数进行重试，例如：配置 `--test-only` 跳过数据的生成和传送，直接进行加载和测试。

## TPC-C 测试

### TPC-C 概述

TPC-C 是一个对 OLTP（联机交易处理）系统进行测试的规范，使用一个商品销售模型对 OLTP 系统进行测试。详细信息可参见 [TPC-C 中文简介](https://github.com/domino-succ/tpcc-hbase/wiki/%E4%B8%AD%E6%96%87-TPC-C%E7%AE%80%E4%BB%8B)。

### 操作步骤

您可参照如下步骤使用 obd 对 OceanBase 集群进行 TPC-C 测试。

1. 安装 obtpcc

   ```shell
   sudo yum install -y yum-utils
   sudo yum-config-manager --add-repo https://mirrors.aliyun.com/oceanbase/OceanBase.repo
   sudo yum install obtpcc java
   ```

2. 执行 TPC-C 测试

   ```obshell
   obd test tpcc test --tenant=tpcc_mysql --warehouses=10  --run-mins=1
   ```

   `obd test tpcc` 命令的详细介绍可参见 [测试命令组](../../../300.obd-command/300.test-command-group.md) 中 **obd test tpcc**。

   执行测试时需注意如下信息：

   * 示例中以待测试的集群名为 `test`，租户名为 `tpcc_mysql` 为例，您需根据实际情况进行替换（可执行 `obd cluster list` 命令查看集群名，并执行 `obd cluster tenant show <deploy_name>` 命令查看集群中存在的租户）。同时，您也可根据自己的具体情况做一些参数上的调整。

   * 运行 `obd test tpcc` 后，系统会详细列出运行步骤和输出，数据量越大耗时越久。

   * `obd test tpcc` 命令会自动完成所有操作，无需其他额外任何操作，包含测试数据的生成、传送、OceanBase 数据库参数优化、加载和测试。当中间环节出错时，您可通过配置参数进行重试，例如：配置 `--test-only` 跳过数据的生成和传送，直接进行加载和测试。

## Sysbench 测试

### Sysbench 概述

Sysbench 是一个基于 LuaJIT 的可编写脚本的多线程基准测试工具，可以执行 CPU、内存、线程、IO 和数据库等方面的性能测试，常用于评估测试各种不同系统参数下的数据库负载情况，不需要修改源码，通过自定义 lua 脚本就可以实现不同业务类型的测试。Sysbench 主要包括以下几种测试：

* CPU 性能

* 磁盘 IO 性能

* 调度程序性能

* 内存分配及传输速度

* POSIX 线程性能

* 数据库性能（OLTP 基准测试）

### 操作步骤

您可参照如下步骤使用 obd 对 OceanBase 集群进行 Sysbench 测试。

1. 安装 ob-sysbench

   ```shell
   sudo yum install -y yum-utils
   sudo yum-config-manager --add-repo https://mirrors.aliyun.com/oceanbase/OceanBase.repo
   sudo yum install ob-sysbench
   ```

2. 执行 Sysbench 测试

   ```obshell
   obd test sysbench test --tenant=sysbench_mysql --script-name=oltp_read_only.lua,oltp_write_only.lua,oltp_read_write.lua --table-size=1000000 --threads=32,64,128,256,512,1024 --rand-type=uniform
   ```

   执行测试时需注意如下信息：

   * 示例中以待测试的集群名为 `test`，租户名为 `sysbench_mysql` 为例，您需根据实际情况进行修改。您可执行 `obd cluster list` 命令查看集群名，并执行 `obd cluster tenant show <deploy_name>` 命令查看集群中存在的租户。

   * 示例脚本中大幅参数使用的是默认值，您可根据自己的具体情况做一些参数上的调整。详细的命令介绍可参见 [测试命令组](../../../300.obd-command/300.test-command-group.md) 中 **obd test sysbench**。
