# 部署 AI
<!-- 确认下介绍的话要统一部署， -->
本文以 x86 架构的 CentOS Linux 7.9 镜像作为环境介绍如何使用 obd 配置文件部署 OceanBase 迁移服务（OceanBase Migration Service，OMS）。

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>目前 obd 仅支持管理 OMS 社区版 V4.2.11 及以上版本。</p>
</main>

## 前提条件

在开始之前，请确保您已满足以下条件：

* 您已安装 obd V4.1.0 或之后版本，建议安装最新版本，详细信息请参考 [安装 obd](../../../200.quick-start/100.install-obd.md)。

* 待部署的机器已安装 Docker，且 Docker 需为 V24.0 或之后版本。
* 待部署的机器已安装 Docker Compose。
* 至少需要 4vCPU、16 GB 内存、50 GB 磁盘的可用资源。需要注意，要求中的内存限制是指执行 `free -g` 命令后，输出中的 `available` 列对应的值

* 若计划单独部署 OMS，需确保已准备用于存储 OMS 社区版元信息的数据库，该数据库可以是 MySQL 或 OceanBase 数据库，建议您使用 OceanBase 数据库社区版。
  
  <main id="notice" type='explain'>
    <h4>说明</h4>
    <p>为提升系统可靠性，建议 MetaDB 实施高可用数据库方案，这将有效保障 OMS 核心服务的 7x24 小时稳定运行，降低业务中断风险。</p>
  </main>

* 若同时部署 OceanBase 集群作为 MetaDB，需确保 OBServer 节点机器支持 AVX 指令集（仅 x86 架构服务器有此限制）。可执行 `lscpu | grep Flags | grep avx` 命令查看是否支持 AVX 指令集。
  
  <main id="notice" type='explain'>
    <h4>说明</h4>
    <p>当使用 x86 架构机器时，若待部署的 OceanBase 数据库版本在以下范围中，不再限制机器是否支持 AVX 指令集：</p>
    <ul>
    <li>对于 V4.2.x 版本，要求为 V4.2.5.6 或之后版本。</li>
    <li>对于 V4.3.x 版本，要求为 V4.3.5.4 或之后版本。</li>
    <li>对于 V4.4.x 版本，要求为 V4.4.1.0 或之后版本。</li>
    </ul>
  </main>

* 离线部署场景下，若同时部署 OceanBase 集群作为 MetaDB，且使用 ARM 架构服务器部署，需查看 OBServer 节点机器是否支持 LSE 指令集，可执行 `lscpu | grep Flags | grep atomics` 命令查看是否支持。若机器不支持 LSE 指令集，需下载带 `nonlse` 的 OceanBase 数据库安装包，并使用 `obd mirror clone` 命令将安装包上传到 obd 本地镜像库。
  
  <main id="notice" type='explain'>
    <h4>说明</h4>
    <p>OceanBase All in One 包中未包含带有 <code>nonlse</code> 的 OceanBase 数据库安装包。</p>
  </main>

* 同时部署 OceanBase 集群作为 MetaDB 时，需确保 obd 镜像库中有部署所需组件安装包（如 OceanBase 数据库）。
  
  若 obd 所在机器可以连接外部网络，部署时会自动从远程镜像库获取社区版组件安装包。若 obd 所在机器无法连接外部网络，可访问 [OceanBase 软件下载中心](https://www.oceanbase.com/softwarecenter) 获取所有安装包，并执行 `obd mirror clone` 命令上传至 obd 本地镜像库，上传后可执行 `obd mirror list local` 命令查看本地镜像库中的安装包。

## 操作步骤

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>本文以 x86 架构的 CentOS Linux 7.9 镜像环境为例提供操作指导。</p>
</main>

### 步骤一：加载安装包

1. 获取安装包

   可访问官网 [OceanBase 软件下载中心](https://www.oceanbase.com/softwarecenter) 下载 all-in-one 安装包。

2. 解压安装包

   ```shell
   [admin@test001 ~]$ tar -xzf oceanbase-all-in-one-*.tar.gz
   [admin@test001 ~]$ cd oceanbase-all-in-one/bin/
   [admin@test001 bin]$ ./install.sh
   [admin@test001 bin]$ source ~/.oceanbase-all-in-one/bin/env.sh
   ```

3. 加载 maas 和 PowerRAG 安装包至 Docker 容器的本地镜像仓库

   ```shell
   [admin@test ~]$ sudo docker load -i xxxxx
   ```

4. 验证加载是否成功

   ```shell
   [admin@test ~]$ sudo docker images
   ```

   输出如下：

   ```shell
   
   ```

### 步骤二：修改配置文件

1. 创建配置文件

   执行如下命令创建配置文件，此处以名为 `ai-config.yaml` 为例，您可自定义配置文件名。

   ```shell
   [admin@test ~]$ vim ai-config.yaml
   ```

2. 修改用户信息

   您可复制如下内容，根据自身实际场景进行修改。

   ```yaml
   ## Only need to configure when remote login is required
   user:
     username: admin
   #   password: your password if need
     key_file: /home/admin/.ssh/id_rsa
   #   port: your ssh port, default 22
   #   timeout: ssh connection timeout (second), default 30
   ```

   `username` 为登录到目标机器的用户名，确保您的用户名有家目录的写权限。`password` 和 `key_file` 均用于验证用户，通常情况下只需要填写一个。

   <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>在配置秘钥路径后，如果您的秘钥不需要口令，请注释或者删除 <code>password</code>，以免 <code>password</code> 被视为秘钥口令用于登录，导致校验失败。</p>
   </main>

3. 修改 OceanBase 数据库配置

   您可复制如下内容，根据自身实际场景进行修改。OceanBase 数据库的配置项详细介绍可参见 [配置文件说明](../100.configuration-file-description.md) 中 **配置项说明**。

   ```yaml
   oceanbase-ce:
     # version: 4.3.0.1
     # release: 100000242024032211.el7
     # package_hash: c4a03c83614f50c99ddb1c37dda858fa5d9b14b7
     servers:
       - name: server1
         ip: 10.10.10.1
       - name: server2
         ip: 10.10.10.2
       - name: server3
         ip: 10.10.10.3
     global:
       appname: obcluster
       mysql_port: 2881
       rpc_port: 2882
       home_path: /home/admin/oceanbase
       data_dir: /home/admin/oceanbase/data
       redo_dir: /home/admin/oceanbase/redo
       obshell_port: 2886
       scenario: htap
       cpu_count: 20
       memory_limit: 64G
       system_memory: 30G
       log_disk_size: 192G
       datafile_size: 192GB
       datafile_maxsize: 32G
       enable_syslog_recycle: true
       enable_syslog_wf: false
       max_syslog_file_count: 4 
       root_password: ********
     server1:
       zone: zone1
     server2:
        zone: zone2
     server3:
        zone: zone3
   ```

4. 修改 maas 配置

   您可复制如下内容，根据自身实际场景进行修改。配置项的具体含义可参见 [配置文件说明](../100.configuration-file-description.md) 中 **配置项说明**。

   ```yaml
   maas:
     type: docker # Deployment type, use docker for containerized deployment
     image_name: harbor.oceanbase-dev.com/obmaas/ob-maas-backend # Docker image name for MAAS BACKEND
     tag: v1.2.0 # Docker image tag
     servers:
       - 127.0.0.1 # Server IP address, please don't use hostname, only IP can be supported
     global:
       data_dir: /data # Data directory for MAAS BACKEND
       prometheus_port: 9090 # Prometheus port for MAAS BACKEND
       port: 8001 # MAAS BACKEND port
   ```

5. 修改 PowerRAG 配置

   您可复制如下内容，根据自身实际场景进行修改。配置项的具体含义可参见 [配置文件说明](../100.configuration-file-description.md) 中 **配置项说明**。

   ```yaml
   powerrag:
     depends:
       - oceanbase-ce
     type: dockers
     version: v1.3.0
     servers:
       - 127.0.0.1
     global:
       pkgs_path: /data/1/powerrag/powerrag-v1.3.0.x86_64 #powerrag解压目录
       home_path: /home/admin/powerrag
       volume_mount: /home/admin/powerrag-volume # 用于挂载容器中应用数据或日志目录的公共前缀，默认为: ~/.powerrag/volumes
       compose_project: group1 # compose分组，当一台机器上需要启动多组powerrag服务时使用这个区分，默认为: group1
       enable_gpu: false # 是否开启gpu优化，默认为：false
       defualt_password: ******* #用于redis等密码
       ob_tenant_name: powerrag
       ob_tenant_password: *******
       cache_scheme: mysql
       expose_powerrag_api_port: 2801
   ```

1. 部署 AI

   ```shell
   [admin@test ~]$ obd cluster deploy ai -c ai-config.yaml
   ```

   命令里的 `ai` 为集群名，您可根据实际情况自定义集群名。部署成功后命令行会输出对应的启动命令，输出如下：


   ```shell
   [admin@test ~]$ obd cluster start ai
   ```
