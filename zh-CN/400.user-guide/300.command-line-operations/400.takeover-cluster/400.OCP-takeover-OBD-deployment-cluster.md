# 使用 OCP 接管 obd 部署的集群

本文介绍使用社区版 OCP 接管 obd 部署的 OceanBase 集群时，obd 侧需要做哪些工作。

## 前提条件

在开始之前，请确保您已满足以下条件：

* 已安装 obd ，且 obd 版本为 V1.3.0 或之后版本。建议安装最新版本，详细信息请参考 [安装 obd](../../../200.quick-start/100.install-obd.md)。

* 已安装社区版 OCP，且 OCP 版本为 V3.1.1 或之后版本，建议安装最新版本。

* 每个 OBServer 节点中只有一个 observer 进程。

* OBServer 节点中存在拥有免密 sudo 权限的 `admin` 用户，且已配置中控机到 OBServer 节点 `admin` 用户的 SSH 免密登录。具体操作可参见 [创建用户](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002016075) 和 [设置无密码 SSH 登录](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002016078)。

### 步骤一：检查集群是否满足条件

在使用 OCP 接管 obd 部署的 OceanBase 集群前，您需先使用如下命令检查待接管的 OceanBase 集群是否满足接管条件。如条件不满足，可以根据提示参见下文进行修改。

```shell
obd cluster check4ocp test
```

### 步骤二：修改集群

1. 修改配置文件风格

   默认风格的配置文件不支持配置 IDC 信息，因此需执行如下命令将配置文件风格转换成 cluster 风格。

   ```shell
   obd cluster chst test -c oceanbase-ce --style cluster
   ```

   输出如下：

   ```shell
   Load param plugin ok
   Change style ok
   Trace ID: 724b42f2-21a4-11f0-ad48-00163e088dda
   If you want to view detailed obd logs, please run: obd display-trace 724b42f2-21a4-11f0-ad48-00163e088dda
   ```

2. 设置 IDC 信息

   执行如下命令打开配置文件，为 Zone 添加 IDC 信息。

   ```shell
   obd cluster edit-config test
   ```

   添加 IDC 信息后需执行 `obd cluster reload test` 命令使修改生效。添加 IDC 信息后的配置文件示例如下：

   ```yaml
   ## Only need to configure when remote login is required
   user:
     username: admin
   #   password: your password if need
     key_file: /home/admin/.ssh/id_rsa
   oceanbase-ce:
     style: cluster
     name: test
     config:
       devname: eth0
       scenario: htap
       memory_limit: 64G
       system_memory: 30G
       datafile_size: 200G
       datafile_next: 200G
       datafile_maxsize: 1T
       log_disk_size: 200G
       cpu_count: 16
       rpc_port: 2882
       mysql_port: 2881
       obshell_port: 2886
       home_path: /home/admin/observer
       root_password: ********
     zones:
       zone1:
         idc: idc1   ---添加 IDC 信息，设置 zone1 的 IDC 为 idc1
         servers:
         - name: server1
           ip: xxx.xxx.xxx.xxx
       zone2:
         idc: idc2    ---添加 IDC 信息，设置 zone2 的 IDC 为 idc2
         servers:
         - name: server2
           ip: xxx.xxx.xxx.xxx
       zone3:
         idc: idc3     ---添加 IDC 信息，设置 zone3 的 IDC 为 idc3
         servers:
         - name: server3
           ip: xxx.xxx.xxx.xxx
   ```

3. （可选）配置密码

   使用 OCP 接管集群时需要填写 `sys` 租户下 `root` 用户连接集群的密码，若待接管集群中已配置 root@sys 密码，可忽略该步骤。

   若待接管集群中未配置 root@sys 密码，您可执行如下命令打开配置文件，并为集群配置 `root_password`。

   ```shell
   obd cluster edit-config test
   ```

   在 `oceanbase-ce` > `config` 下配置 `root_password`，示例如下。配置并保存后，您需执行 `obd cluster reload test` 命令使修改生效。

   ```yaml
   oceanbase-ce:
     style: cluster
     name: test
     config:
       root_password: ********
   ```

4. （可选）修改用户

   OCP 要求 observer 进程必须是使用 `admin` 用户启动，且 `admin` 用户需要有免密 sudo 的权限。若待接管集群是使用 `admin` 用户部署（`user` 部分 `username` 配置为 `admin`），可忽略该步骤。

   若待接管集群未使用 admin 用户部署，可执行如下命令打开配置文件，并修改部署用户。

   ```shell
   obd cluster edit-config test
   ```

   修改部署用户为 `admin` 用户，示例如下。修改配置文件后，您需执行 `obd cluster restart test --wp` 命令使修改生效。

   ```yaml
   user:
     username: admin
   #   password: your password if need
     key_file: /home/admin/.ssh/id_rsa
   ```

### 步骤三：使用 OCP 接管集群

使用 OCP 接管 OceanBase 集群的详细操作可参见官网《OceanBase 云平台》文档 [接管集群](https://www.oceanbase.com/docs/common-ocp-1000000002381085)。

使用 OCP 接管 OceanBase 集群后，您需新建 OBProxy 集群并关联已接管的 OceanBase 集群，具体步骤请参见官网《OceanBase 云平台》文档 [创建 OBProxy 集群](https://www.oceanbase.com/docs/common-ocp-1000000002380653)。

如果原 ODP 使用了 VIP，可以将 OCP 上新建的 ODP 逐个添加到 VIP 中，再逐个从 VIP 中下线原 ODP。

#### FAQ

1. 切换新的 ODP，可以复用原来的机器吗？

   如果原来部署了多台 ODP 并且通过 VIP 来访问，可以逐个下线，并且用相同的机器在 OCP 中部署 ODP，再添加回 VIP，通过这种方式实现机器复用。

2. 不切换 ODP 是否可以？

   可以的，原 ODP 仍然可以正常连接接管的 OceanBase 集群，但是还是建议用 OCP 新建 ODP 进行替换，方便以后的运维管理。
