# 升级 OMS

本文介绍如何通过 obd 的图形化界面操作升级 OMS。

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>目前 obd 仅支持升级 OMS 社区版。</p>
</main>

## 前提条件

在开始之前，请确保您已满足以下条件：
<!-- 支持升级任何版本、任何部署方式的 OMS 么 -->
<!-- * 当前待升级 OMS 的版本为 V4.0.3 或之后版本。 -->

* 您已安装 obd V4.1.0 或之后版本，建议安装最新版本，详细信息请参考 [安装 obd](../../200.quick-start/100.install-obd.md)。

## 操作步骤

### 步骤一：获取升级所需安装包

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>如待升级的 OMS 为多节点 OMS，每个节点都需要执行如下操作。</p>
</main>
<!-- 确认下是否需要都执行 -->

1. 下载安装包

   访问 [OceanBase 软件下载中心](https://www.oceanbase.com/softwarecenter)，搜索 **OceanBase 迁移服务**，根据实际情况下载所需安装包，并将安装包上传至 obd 中控机器任一目录下。

   若从下载中心无法获取所需版本安装包，可联系技术支持人员获取对应安装包。

2. 加载下载的 OMS 安装包至 Docker 容器的本地镜像仓库

   ```shell
   [admin@test001 ~]$ sudo docker load -i oms_4.2.11-ce.tar.gz
   ```

3. 验证加载是否成功

   ```shell
   [admin@test001 ~]$ docker images
   ```

   输出如下：
   <!-- 不同时间导入的不同镜像，ID 和 created 显示应该都是不一样的吧
   话说 obd 部署完 OMS 后，OMS 节点的 docker，以及 docker 中的 OMS 镜像是可以删除的么 -->
   ```shell
   REPOSITORY                                    TAG                 IMAGE ID       CREATED      SIZE
   reg.docker.alibaba-inc.com/oceanbase/oms-ce   feature_4.2.11_ce   26f5f1554fc5   2 days ago   12.5GB
   reg.docker.alibaba-inc.com/oceanbase/oms-ce   feature_4.2.12_ce   26f5f1554fc5   2 days ago   12.5GB
   ```

### 步骤二：启动升级程序

1. 启动升级

   ```shell
   [admin@test001 ~]$ obd web upgrade
   ```

   输出如下，浏览器中访问输出中的 IP 地址即可进入升级向导页面，单击 **开始升级**。

   ```shell
   start OBD WEB in 0.0.0.0:8680
   please open http://10.10.10.1:8680/#/updateWelcome
   ```

   <main id="notice" type='explain'>
     <h4>说明</h4>
     <ul>
     <li>
     <p>白屏界面默认使用 8680 端口，您可使用 <code>obd web upgrade -p &lt;PORT&gt;</code> 命令指定端口。</p>
     </li>
     <li>
     <p>在阿里云或其他云环境下，可能出现程序无法获取公网 IP，从而输出内网地址的情况，此 IP 非公网地址，您需要使用正确的地址访问白屏界面。</p>
     </li>
     <li>
     <p><code>obd web</code> 命令绑定在 0.0.0.0 上，在多网卡部署的情况下，您可通过任意一个可访问的 IP 访问白屏界面。</p>
     </li>
     </ul>
   </main>

2. 选择升级产品

   在显示的 **欢迎使用 OceanBase 升级向导** 界面选择 **OceanBase 数据迁移** 模块，单击 **升级** 按钮，即可开始升级 OMS 的操作。

### 步骤三：升级 OMS

obd 同时支持升级非 obd 部署的 OMS，本节按照待升级 OMS 的部署方式分为 **obd 部署** 和 **非 obd 部署** 两种方法进行介绍，您可根据实际情况选择合适的升级操作。
<!-- 升级有 在线升级 和 离线升级 的区别么 -->
:::tab

tab obd 部署

1. 升级配置

   您可在 **升级配置** 页面选择待升级 OMS 的部署名称、升级的目标版本及升级方式，具体介绍如下。

   ![](900.update-oms-01)

   | 参数  | 说明  |
   |------|--------|
   | 原部署方式 | 根据待升级 OMS 的部署方式选择 **obd 部署** 或 **非 obd 部署**。 |
   | 部署名称  | 通过下拉列表选择待升级 OMS 的部署名称。可通过在命令行中执行 `obd cluster list` 查看部署名称（`Name` 列字段）。 |
   | 目标版本  | 通过下拉列表选择升级的目标版本。  |
   | 升级方式  | 支持 **停服升级** 和 **在线升级** 两种升级方式：<ul><li><b>停服升级</b>：通过部署新版镜像容器来替换旧版容器，升级过程中运行链路将出现短暂中断。</li><li><b>在线升级</b>：在原有容器内直接替换组件包实现升级，确保运行链路全程无中断。</li></ul>  |
   | 存放升级文件路径 | 仅在选择 **在线升级** 方式时需要配置，支持自定义。自定义路径时需配置为以 `/` 开头的绝对路径，且只能包含字母、数字和特殊字符（<code>-_:@/.</code>）。 |

2. 配置确认

   **配置确认** 页面会展示您在 **升级配置** 页面填写的信息，您需检查并确认配置信息是否正确。若存在错误配置，可单击 **上一步** 返回 **升级配置** 页面进行修改；确认无误后，可单击 **下一步** 开始预检查。

   ![](900.update-oms-02)

3. 预检查

   若检查通过，单击 **下一步** 即可开始升级 OMS；若检查失败，支持对失败项进行修复或忽略。

   * 若选择修复，待修复完成后单击 **重新检查**，系统将重新执行环境预检查程序。

   * 若选择忽略，单击 **忽略全部未通过项**，此时未通过的检查项 **检查状态** 将变更为 **已忽略**，可单击 **下一步** 开始升级 OMS。
   <!-- 验证下是否多节点会显示多个检查项，尽量使用多节点的截图 -->
   <main id="notice" type='notice'>
     <h4>注意</h4>
     <p>忽略全部未通过项可能会导致升级失败，建议您修复检查失败项后再进行下一步。</p>
   </main>

   ![](900.update-oms-03)

4. 数据备份

   您可在 数据备份 页面选择是否备份关键元信息数据，并设置备份路径（如需备份）。OMS 升级过程中将根据升级需要对元信息及监控数据进行变更，变更操作不可逆，建议对元信息及监控数据进行备份，避免因升级导致的不可预知风险。

   ![](900.update-oms-04)

   | 参数  | 说明  |
   |-------|-------|
   | 备份方式 | 可通过下拉列表选择 **备份关键元信息数据** 或 **不备份**。 |
   | 备份路径  | 仅在选择 备份关键元信息数据 时展示，需指定为当前 obd 所在节点的本地路径，并保证可用空间至少 2 GiB 以上。支持自定义，自定义路径时需配置为以 `/` 开头的绝对路径，且只能包含字母、数字和特殊字符（<code>-_:@/.</code>）。</br>路径设置完成后需单击路径后的 **测试** 按钮，测试路径是否符合要求。 |

   <main id="notice" type='explain'>
     <h4>说明</h4>
     <p>选择 <b>备份关键元信息数据</b> 方式时，备份路径测试通过后才可单击 <b>下一步</b>，单击 <b>下一步</b> 后，obd 将弹窗进行数据备份，备份完成后会自动进入到 <b>OMS 升级</b> 页面。</p>
   </main>

5. OMS 升级

   升级过程中，**OMS 升级** 页面会展示升级日志。升级成功后，您可在页面中执行如下操作：

   * 单击 **升级报告** 后的展开按钮，可查看升级日志。
   * 单击 **OMS 发布记录**，会新开页面打开当前版本的官网 RN 文档。
   * 单击 **去体验新版** 按钮，会新开页面打开 OMS 登录页面。
   * 单击 **退出**，并二次确认后可退出 OMS 升级程序。
  
   若部署失败，您可选择单击 **重新升级**，obd 程序会尝试重新执行失败的升级步骤；也可选择单击 **退出页面**，退出 OMS 升级程序。

   ![](900.update-oms-05)
