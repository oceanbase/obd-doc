# Quick deployment of OCP

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>The operations described in this topic are for quick experience. For information about how to deploy OCP in a production environment, see <a href="../400.user-guide/200.ui-operations/300.deploy-ocp-by-ui.md">Deploy OCP by using the graphical interface</a>. </p>
</main>

## Prerequisites

Before you start, make sure that you meet the following conditions:

* You have installed obd V2.4.0 or later. We recommend that you install the latest version. For more information, see [Install obd](100.install-obd.md).
  
  <main id="notice" type='explain'>
     <h4>Note</h4>
     <p>We recommend that you install OceanBase All in One. OceanBase All in One provides all the components required for deployment (except for the obbinlog component). The components have been tested for compatibility and are the officially recommended versions. </p>
  </main>

* If you deploy an OceanBase cluster as MetaDB, make sure that the OBServer node supports the AVX instruction set (this restriction applies only to servers with the x86 architecture). Run the `lscpu | grep Flags | grep avx` command to check whether the AVX instruction set is supported.
  
  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>If you use servers with the x86 architecture, the restriction on the AVX instruction set does not apply to OceanBase Database of the following versions: </p>
    <ul>
    <li>V4.2.5.6 or later for V4.2.x</li>
    <li>V4.3.5.4 or later for V4.3.x</li>
    <li>V4.4.1.0 or later for V4.4.x</li>
    </ul>
  </main>

* In offline deployment scenarios, if you deploy an OceanBase cluster as MetaDB and use servers with the ARM architecture, check whether the OBServer node supports the LSE instruction set by running the `lscpu | grep Flags | grep atomics` command. If the LSE instruction set is not supported, download an OceanBase Database installation package with the `nonlse` parameter and use the `obd mirror clone` command to upload the package to the local mirror library of obd.
  
  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>The OceanBase All in One package does not contain an OceanBase Database installation package with the <code>nonlse</code> parameter. </p>
  </main>

* The server has at least 8 vCPUs, 26 GB of memory, and 150 GB of disk space. Note that the memory limit refers to the value in the `available` column of the output of the `free -g` command.

* The deployment process will use the following ports by default: `2881`, `2882`, `2883`, `2884`, `2886`, `8080`, and `8680`. Make sure that these ports are not occupied.

* The server where you deploy OCP has the clockdiff command installed. You can run the `clockdiff` command to verify this. If the command is not installed, you need to install it. For more information, see [Install clockdiff](100.install-clockdiff.md).

* The server can access the Internet, or the local mirror library of obd contains the required installation packages.
  
  Run the `obd mirror list local` command to view the installation packages in the local mirror library. If you installed obd by using OceanBase All in One, the local mirror library contains the installation packages of all components required for deployment.

## Step 1: Start the GUI

1. Run the `obd web` command to start the GUI. Click the displayed address to access the GUI of obd.

   ```shell
   [admin@test001 ~]$ obd web
   start OBD WEB in 0.0.0.0:8680
   please open http://10.10.10.1:8680
   ```

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <ul>
     <li>
     <p>The GUI is started on port 8680 by default. You can run the <code>obd web -p &lt;PORT&gt;</code> command to specify the port. </p>
     </li>
     <li>
     <p>In Alibaba Cloud or other cloud environments, the program may fail to obtain a public IP address and output an internal IP address. This IP address is not a public IP address. You need to use the correct address to access the GUI. </p>
     </li>
     <li>
     <p>The <code>obd web</code> command is bound to 0.0.0.0. In a multi-NIC deployment, you can access the GUI through any accessible IP address. </p>
     </li>
     </ul>
   </main>

2. In the operation interface, click **Start the Experience Journey**. In the **Welcome to OceanBase Deployment Wizard** interface that appears, select the **OceanBase Cloud Platform** module. Place the cursor on the **<UI-TERM key="ocp-v2.Component.InstallService.Mounting">Install</UI-TERM>** button and select **Use a New OceanBase Database** to enter the **Welcome to OCP Deployment Wizard** interface.

## Step 2: Configure the deployment

The **Configure Deployment** interface is displayed. You can configure the cluster name of OCP on this interface. The cluster name can be customized and must be unique (you can run the `obd cluster list` command to view the clusters managed by obd).

![Configure Deployment](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/2.10.1/zh-CN/200.quick-start/250.quickly-start-ocp-13.png)

## Step 3: Configure MetaDB

You can configure the information of the MetaDB cluster on the **<UI-TERM key="ocp-v2.Binlog.New.MetadbConfiguration">MetaDB Configuration</UI-TERM>** page, such as the IP address, port, directory, and password of the OBServer node. This section will introduce how to configure these parameters.

1. Deploy user configuration

   The **Deploy User Configuration** module is used to configure the information of the user for deploying OCP. The interface is shown in the following figure. You only need to configure the **<UI-TERM key="ocp-v2.Detail.Component.AddUserDrawer.UserName">Username</UI-TERM>** and **<UI-TERM key="ocp-v2.component.common.ObUserSelect.Password">Password</UI-TERM>**. The configured username must have the permission to execute sudo commands without a password. If you have configured password-free login, you can skip entering the password.

   ![User configuration](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/2.10.1/zh-CN/200.quick-start/250.quickly-start-ocp-03.png)

2. Node configuration

   You can configure the IP address of the host where OCP is deployed on the **OCP Node Configuration** page, and configure the IP address of the OBServer node where MetaDB is deployed on the **Database Node Configuration** page. The interface is shown in the following figure.

   You need to configure the IP addresses of OCP and MetaDB on the page. We recommend that you use an IP address other than `127.0.0.1`. After you enter an IP address, you can press Enter to configure multiple IP addresses. By default, three zones are displayed on the page. You can click **+ Add Zone** or the delete icon after the corresponding zone to add or delete a zone.

   ![Node configuration](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/2.10.1/zh-CN/200.quick-start/250.quickly-start-ocp-11.png)

3. Cluster configuration

   You can configure the root@sys password, directory, and port of the MetaDB database on the **Cluster Configuration** page. The interface is shown in the following figure.

   You can click **Randomly Generate** to set the root@sys password to a random string generated by obd. The page provides default paths, and you can customize the paths. The paths must be absolute paths starting with `/`, and the directories must be empty and have read and write permissions.

   ![Cluster configuration](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/2.10.1/zh-CN/200.quick-start/250.quickly-start-ocp-14.png)

4. OBProxy configuration

   The **OBProxy Configuration** module is used to configure the nodes, ports, and paths of OBProxy. The interface is shown in the following figure. You can configure only one IP address for the **OBProxy Node**. By default, the `obproxy` directory is created in the home directory of the deployment user to serve as the software path of OBProxy. You can customize the path, which must be an absolute path starting with `/`, and you must have read and write permissions for the directory.

   ![OBProxy configuration](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/2.10.1/zh-CN/200.quick-start/250.quickly-start-ocp-06.png)

After you complete all the configurations, click **<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step1.NextStep">Next</UI-TERM>** to go to the **OCP Configuration** page.

## Step 4: Configure OCP

You can configure the service and tenant information of OCP on the **OCP Configuration** page. This section will introduce how to configure these parameters.

1. Service configuration

   You can configure the login password, path, URL, and port of OCP on the **Service Configuration** page. The interface is shown in the following figure. You can click **Randomly Generate** to set the Admin password to a random string generated by obd. The page provides default paths, and you can customize the paths. The paths must be absolute paths starting with `/`, and the directories must be empty and have read and write permissions.

   ![Service configuration](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/2.10.1/zh-CN/200.quick-start/250.quickly-start-ocp-07.png)

2. Resource planning

   OCP services consume computing and storage resources during operation. You can plan resources based on the scale of the objects to be managed on the **Resource Planning** page. The interface is shown in the following figure.

   You can click **Randomly Generate** to set the root password of each tenant to a random string generated by obd.

   ![Resource planning](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/2.10.1/zh-CN/200.quick-start/250.quickly-start-ocp-12.png)

After you complete all the configurations, click **<UI-TERM key="ocp-v2.Cluster.Import.Next">Next</UI-TERM>** to go to the **<UI-TERM key="ocp-v2.Detail.TakeOver.Precheck">Precheck</UI-TERM>** page.

## Step 5: Precheck

You can view all the configuration information on the **<UI-TERM key="ocp-v2.Detail.TakeOver.Precheck">Precheck</UI-TERM>** page. If you find any issues, you can click **<UI-TERM key="ocp-v2.Component.AddSamplingInspectStrategy.PreviousStep">Previous</UI-TERM>** to modify them. After you confirm that the information is correct, you can click **<UI-TERM key="ocp-v2.Cluster.Import.Precheck">Precheck</UI-TERM>** to perform a precheck. The system will verify whether your environment meets all the requirements for installing and configuring MetaDB and OCP.

If the precheck fails, you can choose **<UI-TERM key="ocp-v2.page.Host.AutomaticRepair.1">Auto Repair</UI-TERM>** (for check items that can be automatically repaired) or click **View More Solutions** to jump to the error code documentation and modify the configurations based on the documentation. After you modify all the errors, you can click **<UI-TERM key="ocp-v2.Detail.TakeOver.ReCheck">Recheck</UI-TERM>** to perform a precheck again.

![Precheck](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/2.10.1/zh-CN/400.user-guide/300.deploy-ocp-by-ui-09.png)

After the precheck passes, you can click **<UI-TERM key="ocp-v2.Cluster.Import.Next">Next</UI-TERM>** to go to the **Deployment** page and start deploying OCP.

## Step 6: Deploy

During deployment, the **Deployment** page displays the deployment log. You can view the detailed installation log in the **Deployment Log** module.

* If the deployment fails, view the log to identify the cause of the failure. Contact technical support for assistance, or post a question in the [Q&A section](https://ask.oceanbase.com/) on the website. A professional will provide a solution. After identifying and fixing the issue, click **Redeploy**. In the confirmation window that appears, click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.Confirm">OK</UI-TERM>**. The system will then clean up the failed OCP installation environment and re-execute the installation process.

* If the deployment is successful, click **Copy Information**. After copying and saving the OCP access address and account credentials, click **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">Complete</UI-TERM>** to exit the deployment program.

![Deployment](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/2.10.1/zh-CN/400.user-guide/300.deploy-ocp-by-ui-10.png)

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>After the deployment is successful, you can refer to the <a href="https://www.oceanbase.com/docs/common-ocp-1000000001406231">Post-deployment checks</a> section in the <i>Cloud Platform OCP</i> document to verify whether the deployed OCP can be used normally.</p>
