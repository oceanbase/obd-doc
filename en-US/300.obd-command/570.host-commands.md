# Host commands

obd supports viewing and modifying kernel parameters of machines since V3.2.0. This topic describes the related command groups. You can use the `-h`/`--help` option in each command to view the help information of the command. Similarly, when a command reports an error, you can use `-v`/`--verbose` to view the detailed execution process of the command.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>The <b>target machine</b> in this topic refers to the machine where users are to be initialized, or kernel parameters are to be viewed or modified.</p>
</main>

## obd host user init

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>obd supports initializing users through this command since V3.5.0.</p>
</main>

You can use this command to initialize a specified user on a specified machine. If the specified user does not exist, the corresponding user will be created, and the following initialization settings will be performed for the user:

* **Set ulimit parameters**: Modify system resource limit parameters. For parameters to be modified, see [Configure limits.conf](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002016079) in the OceanBase Database documentation. After the user is created successfully, you can log in to the created user on the target machine and run the `ulimit -a` command to check whether the configuration takes effect.

* **Configure passwordless sudo privileges**: Configure passwordless sudo command execution privileges for the specified user.
  
  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>Passwordless sudo is configured for convenience. You can manually remove passwordless sudo after cluster deployment is complete.</p>
  </main>

* **Enable password login**: Ensure that users can log in to the system using passwords.

* **Modify directory owner**: If the `/data/1` and `/data/log1` directories exist on the target machine, modify the owner of the directories to the specified user.

```shell
obd host user init [options]
```

The following table describes the options:

| Option | Required | Data type | Default value | Description |
|--------|----------|-----------|---------------|-------------|
| -u/--username | No | string | admin | Specifies the username of the user to be initialized. If the specified user does not exist, the corresponding user will be created. |
| -p/--password | No | string | Empty | Sets a new login password for the user to be initialized. This option is required when the specified user does not exist. |
| --host | No | string | 127.0.0.1 | Specifies the host IP where the user to be initialized is located. Currently, only one IP is supported. |

### Usage example

Use obd to initialize the `test` user on the target machine `10.10.10.1` and set a login password for the `test` user:

```shell
obd host user init -u test --host=10.10.10.1 -p ********
```

When this command is executed, it first attempts to log in to the target machine (`10.10.10.1`) using the set user (in this example, `test`). If the connection fails, you need to enter a user with sudo privileges and the password. obd will use the entered user to log in to the target machine and perform initialization operations on the specified user.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>If you use this command to initialize a local user, obd will verify whether the current execution user has passwordless sudo privileges. If the user has privileges, obd will directly use the execution user to perform initialization operations on the specified user.</p>
</main>

Example output:

## obd host precheck

Deploying OceanBase Database has certain requirements for machines, such as Linux kernel version and kernel parameters. You can use this command to check whether the specified user on the target machine meets the deployment requirements. The following items are mainly checked. Only items that do not meet the requirements will be output.

* **Kernel parameter check**: Checks kernel parameters that are recommended to be modified. For specific parameters, see [Configure sysctl.conf](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002016077) in the OceanBase Database documentation.

* **Security settings check**: Checks whether firewall and SELinux functions are disabled.

* **Login settings check**: Checks whether password login is supported.

* **System privileges check**: Checks whether the specified user has passwordless sudo command execution privileges.

* **Network component check**: Checks whether the network component is installed.

* **Memory resource check**: Checks whether the available memory of the machine meets the requirements (greater than 3 GB).

* **Kernel version check**: Checks whether the kernel version of the machine meets the requirements (Linux 3.1.0 or later).

* **Directory owner check**: If the `/data/1` and `/data/log1` directories exist on the target machine, checks whether the owner of the directories is the specified user.

* **Instruction check**: Checks whether the CPU supports AVX instructions on x86 architecture; checks whether the CPU supports LSE instructions on ARM architecture.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>When using x86 architecture machines, if the OceanBase Database version to be deployed is in the following ranges, you can ignore the AVX instruction check results:</p>
    <ul>
    <li>For V4.2.x versions, V4.2.5.6 or later is required.</li>
    <li>For V4.3.x versions, V4.3.5.4 or later is required.</li>
    <li>For V4.4.x versions, V4.4.1.0 or later is required.</li>
    </ul>
  </main>

```shell
obd host precheck [<ssh username>] [<server ip>]
```

Both parameters `ssh username` and `server ip` are optional. The `ssh username` parameter specifies the username for logging in to the target machine. If not configured, it defaults to the current user. The `server ip` parameter specifies the IP of the target machine. Currently, only one IP is supported. If not configured, it defaults to the current host.

The following table describes the options:

| Option | Required | Data type | Default value | Description |
|--------|----------|-----------|---------------|-------------|
| -u/--username | No | string | Login user | Specifies the user as the object of the user check function in the precheck command. If not specified, it defaults to the login user, which is `<ssh username>` in the command. |
| -p/--password | No | string | Empty | Sets the login password of the login user. If the login user on the target machine has a password configured and SSH passwordless login is not set between the current execution user and the login user on the target machine, you need to specify the user password through this option. |
| --ssh-key-file | No | string | Empty by default | Specifies the path of the private key file, which must be configured as an absolute path, for SSH passwordless authentication based on private keys. |

### Usage example

Assume that the target machine does not support password access and only SSH passwordless login to the root user on the target machine is configured (the private key file is the default path `~/.ssh/id_rsa`). You can run the following command. The command execution will use the root user to log in to the target machine `10.10.10.1` and check the test user:

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This is only an example. You can set the login user to any user that can log in to the specified machine. Taking the example in this section, if password access to the test user on the target machine is supported, the example command below has the same effect as the `obd host precheck test 10.10.10.1 -p ******` command.</p>
</main>

```shell
obd host precheck root 10.10.10.1 -u test
```

## obd host init

You can use this command to automatically modify kernel parameters recommended for deploying OceanBase Database, disable firewall and SELinux functions, and modify the owners of the `/data/1` and `/data/log1` directories (if the corresponding directories exist), and install the network component. For kernel parameters to be modified, see [Configure sysctl.conf](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002016077) in the OceanBase Database documentation.

```shell
obd host init [<ssh username>] [<server ip>]
```

Both parameters `ssh username` and `server ip` are optional. The `ssh username` parameter specifies the username for logging in to the target machine. If not configured, it defaults to the current user. Ensure that the login user has sudo privileges. The `server ip` parameter specifies the IP of the target machine. Currently, only one IP is supported. If not configured, it defaults to the current host.

The following table describes the options:

| Option | Required | Data type | Default value | Description |
|--------|----------|-----------|---------------|-------------|
| -u/--username | No | string | Login user | Specifies the user as the object of the user modification function in the init command. If not specified, it defaults to the login user, which is `<ssh username>` in the command. |
| -p/--password | No | string | Empty | Sets the login password of the login user. If the login user on the target machine has a password configured and SSH passwordless login is not set between the current execution user and the login user on the target machine, you need to specify the user password through this option. |
| --ssh-key-file | No | string | Empty by default | Specifies the path of the private key file, which must be configured as an absolute path, for SSH passwordless authentication based on private keys. |

### Usage example

Assume that the target machine does not support password access and only SSH passwordless login to the root user on the target machine is configured (the private key file is the default path `~/.ssh/id_rsa`). You can run the following command. The command execution will use the root user to log in to the target machine `10.10.10.1` and modify the test user:

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This is only an example. You can set the login user to any user that can log in to the specified machine, but ensure that the login user has sudo privileges.</p>
</main>

```shell
obd host init root 10.10.10.1 -u test
```
