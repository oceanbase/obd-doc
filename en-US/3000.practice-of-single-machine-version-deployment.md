# Deploy OceanBase Database Community Edition interactively using obd

This topic describes how to deploy OceanBase Database Community Edition interactively by using obd. It also covers the preparation and configuration of resources before deployment and how to quickly set up an OceanBase Database environment on a single server.

In this example, OceanBase Database and obd are deployed on the same server, and the obagent, Prometheus, and Grafana components are not deployed.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <ul>
  <li><p>Interactive deployment is suitable for deploying OceanBase Database on a single server. It is intended for learning purposes and is not recommended for production environments. </p></li>
  <li><p>obd supports the deployment of OceanBase Database Community Edition and Enterprise Edition. This topic describes how to deploy OceanBase Database Community Edition interactively. </p></li>
  </ul>
</main>

## Server configuration

The server configuration used in this example is as follows:

| Category | Configuration |
| ---- | ---- |
| Number of servers | 1 |
| CPU | 8 x86_64 cores |
| Operating system | CentOS Linux release 8.5.2111 |
| Kernel | 4.18.0-348.7.1 |
| Available memory | 32 GB |
| Disk | SSD storage with 196 GB for installation directory, 2 TB for log directory, and 2 TB for data directory. |

<main id="notice" type='explain'>
  <h4>Note</h4>
  <ul>
  <li><p>For testing and experience scenarios, ensure that the server meets the minimum resource requirements for deploying OceanBase Database (2 cores, 6 GB of memory, and 20 GB of disk space). Note that the memory limit refers to the value in the <code>available</code> column of the output when the <code>free -g</code> command is executed. </p></li>
  <li><p>In environments with a small number of CPU cores, the default minimum CPU_Count set by obd is 8. Configuring too few CPU cores will negatively impact the performance of OceanBase Database. </p></li>
  </ul>
</main>

## Pre-deployment configuration

To ensure a smooth installation and better usage of OceanBase Database Community Edition, the following configurations need to be performed before deployment.

### Directory planning

Deploying OceanBase Database Community Edition requires planning for three directories, and the file system type must be XFS or EXT4.

* Installation directory: This directory stores the OceanBase Database software and system logs during operation. It requires at least 25 GB of space.
* Log storage directory: This directory stores OceanBase Database logs. It requires at least twice the size of the memory, and we recommend that you configure it to be at least three times the size of the memory.
* Data storage directory: This directory stores data. It requires at least twice the size of the memory, and the size depends on the amount of data to be stored.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>If the capacity of a directory on a mount point exceeds 16 TB, only XFS is supported. </p>
</main>

To ensure system stability, we recommend that you use different physical disks for the three directories. If physical resources are limited, OceanBase Database also supports using the same disk for the data storage directory and the log storage directory. However, we do not recommend this configuration for business scenarios with high write pressure.

The IOPS requirements for disks are as follows:

* If the installation directory, log storage directory, and data storage directory are on different disks, each disk must have an IOPS of at least 1000.
* If the installation directory, log storage directory, and data storage directory are on the same disk, the disk must have an IOPS of at least 3000.

```shell
# Configure the filename format and directory for core files

kernel.core_pattern = /data/core-%e-%p-%t
```

After modifying the configuration, execute the following command to load the configuration and make it effective.

```shell
[admin@test001 ~]# sudo sysctl -p
```

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>When the kernel parameter <code>net.ipv4.ip_forward</code> is set to 0, the IP forwarding feature of the system is disabled. If OceanBase Database is deployed on the same host as other Docker containers, this setting will block communication between the containers and the external network, as Docker containers rely on the host's IP forwarding for network connectivity. It is recommended to enable IP forwarding using the following commands:</p>
  <ul>
  <li>Temporarily enable: <code>sysctl -w net.ipv4.ip_forward=1</code></li>
  <li>Permanently enable: Add <code>net.ipv4.ip_forward=1</code> to <code>/etc/sysctl.conf</code>, save the changes, and execute <code>sysctl -p</code> to apply the configuration.</li>
  </ul>
</main>

#### Disable the firewall and SELinux

Continue with the admin user to disable the firewall and SELinux.

* Disable the firewall

  Execute the following commands in sequence to disable the firewall:

  ```shell
  [admin@test001 ~]# sudo systemctl disable firewalld
  [admin@test001 ~]# sudo systemctl stop firewalld
  ```

  After disabling, you can execute the `systemctl status firewalld` command to check the firewall status. The output should be as follows:

  ```shell
  firewalld.service - firewalld - dynamic firewall daemon

  Active: inactive (dead)
    Docs: man:firewalld(1)
  ```

* Disable SELinux

  Execute the following command to open the `/etc/selinux/config` configuration file:

  ```shell
  [admin@test001 ~]# sudo vim /etc/selinux/config
  ```

  In the `/etc/selinux/config` configuration file, modify the corresponding configuration item to the following content:

  ```shell
  SELINUX=disabled
  ```

  Execute the following command or restart the server to apply the changes:

  ```shell
  [admin@test001 ~]# setenforce 0
  ```

  Execute the following command to check if the changes are effective:

  ```shell
  sestatus
  ```

  The output should be as follows, indicating that SELinux is disabled.

  ```shell
  SELinux status:                 disabled
  ```
