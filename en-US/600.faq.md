# FAQ

## How do I specify the version of a component to use?

You can use version declarations in deployment configuration files. For example, if you are using OceanBase-CE version 3.1.0, you can specify the following configuration:

```yaml
oceanbase-ce:
  version: 3.1.3  # Specify version
```

You can obtain component versions through the following commands based on different deployment methods (offline or online):

* For online deployment, use the following command to obtain component versions. The `version` in the output is the version number.
  
  ```shell
  obd mirror list oceanbase.community.stable
  ```

* For offline deployment, use the following command to obtain component versions. The `version` in the output is the version number.
  
  ```shell
  obd mirror list local
  ```

## How do I specify a specific version of a component to use?

You can use `package_hash` or `tag` declarations in deployment configuration files. If you set a `tag` for your compiled OceanBase-CE, you can use `tag` to specify it. For example:

```yaml
oceanbase-ce:
  tag: my-oceanbase
```

You can also specify a specific version through `package_hash`:

```yaml
oceanbase-ce:
  package_hash: 589c4f8ed2662835148a95d5c1b46a07e36c2d346804791364a757aef4f7b60d
```

You can obtain component package hashes through the following commands based on different deployment methods (offline or online):

* For online deployment, use the following command to obtain component package hashes. The `md5` value in the output is the `package_hash`.
  
  ```shell
  obd mirror list oceanbase.community.stable
  ```

* For offline deployment, use the following command to obtain component package hashes. The `md5` value in the output is the `package_hash`.
  
  ```shell
  obd mirror list local
  ```

## I modified the OceanBase-CE code. How do I modify the startup process?

You can modify the startup-related plugins under `~/.obd/plugins/oceanbase-ce/`. For example, if you add a new startup configuration for OceanBase-CE version 3.1.0, you can modify `~/.obd/plugins/oceanbase-ce/3.1.0/start.py`.

## How do I update the obd local mirror in offline mode?

When the machine where obd is installed cannot connect to the public network but you need to update obd or other components, you can perform the following steps:

1. Download the RPM packages you need on a machine that can connect to the public network.

2. Copy the RPM packages to the machine where obd is installed.

3. Add the new RPM packages to the local mirror through the `obd mirror clone` command.

The following example shows how to update the obd mirror in the local repository:

```shell
# First, download the latest obd RPM package on a machine that can connect to the public network
# The latest RPM package link can be obtained from the release notes in the corresponding component's git repository or the OceanBase open source website (https://open.oceanbase.com/softwareCenter/community)
wget https://github.com/oceanbase/obdeploy/releases/download/vx.x.x/ob-deploy-x.x.x-xxx.rpm
# Copy the downloaded RPM package to the machine where obd is installed (obd_server)
sh ob-deploy-x.x.x-xxx.rpm obd_server:~
# Add the downloaded mirror to local
obd mirror clone ob-deploy-x.x.x-xxx.rpm
# Disable the remote mirror source
obd mirror disable remote
```

## How do I resolve the issue where the ODP service cannot start after obd upgrade?

obd initializes the ODP password after upgrade. If you set `obproxy_sys_password`, you need to run the following command to connect to proxysys:

```bash
obclient -h<obproxy_ip> -uroot@proxysys -P<obproxy_port> -p<obproxy_pwd>
```

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>If you cannot connect to proxysys using your own proxysys command, try using an empty password or <code>proxysys</code> to connect.</p>
</main>

Then use the command `alter proxyconfig set obproxy_sys_password = ''` to set the proxysys password to empty, or keep it consistent with the password of `obproxy_sys_password` in the configuration file.

## How do I configure the Java environment?

You can log in to the machine where the Java environment needs to be configured and install the Java environment according to the following methods based on the network connection status of the machine.

### Online installation

On CentOS or RedHat systems, run the following command to install:

```bash
sudo yum install java-1.8.0-openjdk 
```

On Ubuntu or Debian systems, run the following commands to install:

```bash
sudo apt-get update
sudo apt-get install openjdk-8-jre
```

### Offline installation

1. Click to download the required installation packages: [x86_64 architecture](https://github.com/dragonwell-project/dragonwell8/releases/download/dragonwell-extended-8.14.15_jdk8u362-ga/Alibaba_Dragonwell_Extended_8.14.15_x64_linux.tar.gz), [arm architecture](https://github.com/alibaba/dragonwell8/releases/download/dragonwell-extended-8.14.15_jdk8u362-ga/Alibaba_Dragonwell_Extended_8.14.15_aarch64_linux.tar.gz).

2. Upload the downloaded installation package to the corresponding machine and run the following commands in the directory where the installation package is located to extract and install:

   ```bash
   # Extract the resource package
   tar -zxvf Alibaba_Dragonwell_Extended_8*.tar.gz
   # Enter the extracted directory
   cd dragonwell*
   # Create a symbolic link
   ln -s `pwd`/bin/java /usr/bin/java
   ```

## After upgrading OCP using obd, how do I manage the original metadb cluster?

After upgrading OCP using obd, if you want to use obd to manage the original OCP metadb cluster, you can copy the information of the original metadb cluster to the obd directory. Command:

```shell
cp -rf ~/.ocp-installer/cluster/<metadb_cluster_name> ~/.obd/cluster/
```

Where `metadb_cluster_name` represents the name of the original metadb cluster. You need to replace it according to the actual situation.

## After installing OceanBase All in One, obd cannot be used normally. What should I do?

If you have already installed OceanBase All in One and install obd through the obd RPM package, the following prompt appears:

```shell
Detected residual environment variables of oceanbase-all-in-one in the system. Please execute `rm -rf ~/.obd/version && rm -rf ~/.oceanbase-all-in-one/obd && obd env set OBD_INSTALL_PRE / ` under the user who installed all-in-one and rerun.
```

To avoid affecting the normal use of obd, we recommend executing the command in the prompt under the current user to modify the `OBD_INSTALL_PRE` value:

```shell
rm -rf ~/.obd/version && rm -rf ~/.oceanbase-all-in-one/obd && obd env set OBD_INSTALL_PRE /
```
