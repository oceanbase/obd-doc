# Upgrade OMS

This topic describes how to upgrade OMS in the graphical interface of obd.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Currently, obd supports only the upgrade of OMS Community Edition. </p>
</main>

## Prerequisites

Before you start, make sure that you have installed obd V4.1.0 or later. We recommend that you install the latest version. For more information, see [Install obd](../../200.quick-start/100.install-obd.md).

## Procedure

### Step 1: Obtain the installation package required for the upgrade

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>If the OMS to be upgraded is a multi-node OMS, you need to perform the following steps on each node.</p>
</main>

1. Download the installation package

   Go to [OceanBase Download Center](https://en.oceanbase.com/softwarecenter), search for **OceanBase Migration Service**, and download the required installation package. Upload the installation package to any directory of the OBD control machine.

2. Load the downloaded OMS installation package to the local image repository of the Docker container

   ```shell
   [admin@test001 ~]$ sudo docker load -i oms_4.2.12-ce.tar.gz
   ```

3. Verify whether the loading is successful

   ```shell
   [admin@test001 ~]$ sudo docker images
   ```

   The output is as follows:

   ```shell
   REPOSITORY                                    TAG                 IMAGE ID       CREATED        SIZE
   reg.docker.alibaba-inc.com/oceanbase/oms-ce   feature_4.2.11_ce   26f5f1554fc5   2 months ago   12.5GB
   reg.docker.alibaba-inc.com/oceanbase/oms-ce   feature_4.2.12_ce   28fddcdaf8a0   2 days ago     12.5GB
   ```

### Step 2: Disable HA

HA stands for High Available, which is a module that ensures the stability and continuity of data transmission links. Before the upgrade, you need to disable the HA feature. If the HA feature is enabled, please follow the steps below to disable it:

* Log in to the OMS Community Edition console.

* In the left-side navigation pane, choose **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** > **<UI-TERM key="ocp-v2.page.Property.SystemParameters">System Parameters</UI-TERM>**.

* On the **<UI-TERM key="ocp-v2.page.Property.SystemParameters">System Parameters</UI-TERM>** page, find `ha.config`.

* Click the edit icon next to the value of the parameter.

* In the **Modify Value** dialog box, set `enable` to `false` to disable the HA feature.

### Step 3: Start the upgrade program

1. Start the upgrade

   ```shell
   [admin@test001 ~]$ obd web upgrade
   ```

   The output is as follows. You can access the IP address in the output in the browser to go to the upgrade wizard page and click **Start Upgrade**.

   ```shell
   start OBD WEB in 0.0.0.0:8680
   please open http://10.10.10.1:8680/#/updateWelcome
   ```

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <ul>
     <li>
     <p>The default port for the GUI is 8680. You can use the <code>obd web upgrade -p &lt;PORT&gt;</code> command to specify the port.</p>
     </li>
     <li>
     <p>In Alibaba Cloud or other cloud environments, the program may fail to obtain a public IP address and output an intranet IP address. In this case, you need to use the correct public IP address to access the GUI.</p>
     </li>
     <li>
     <p>The <code>obd web</code> command is bound to 0.0.0.0. In a multi-network interface deployment, you can access the GUI through any accessible IP address.</p>
     </li>
     </ul>
   </main>

2. Select the product to be upgraded

   On the **Welcome to OceanBase Upgrade Wizard** page, select the **OceanBase Data Migration** module and click **<UI-TERM key="ocp-v2.Binlog.Component.UpgradeBinlogModal.Upgrade">Upgrade</UI-TERM>** to start the OMS upgrade.

### Step 4: Upgrade OMS

obd supports upgrading OMS deployed without obd. This section describes the upgrade process for **obd-deployed OMS** and **non-obd-deployed OMS** based on the original deployment method of the OMS to be upgraded. You can choose the appropriate upgrade method based on your actual situation.

:::tab

tab obd deployment

1. Configure the upgrade

   On the **Configure Upgrade** page, select the deployment name of the OMS to be upgraded, the target version, and the upgrade method. The details are as follows.

   ![Configure Upgrade](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/900.update-oms-01.png)

   | Parameter | Description |
   |------|--------|
   | Original Deployment Method | Select **obd Deployment** or **Non-obd Deployment** based on the deployment method of the OMS to be upgraded. |
   | Deployment Name  | Select the deployment name of the OMS to be upgraded from the drop-down list. You can execute the `obd cluster list` command in the command line to view the deployment name (the `Name` column). |
   | Target Version  | Select the target version from the drop-down list.  |
   | Upgrade Method  | Supports **<UI-TERM key="ocp-v2.Component.UpgradeDrawer.StopServiceUpgrade">Downtime Upgrade</UI-TERM>** and **Online Upgrade**. <ul><li><b>Stop-and-Upgrade</b>: Replaces the old container with a new container image, which may cause a brief interruption in the running chain during the upgrade. </li><li><b>Online Upgrade</b>: Replaces the component package directly in the existing container to ensure no interruption in the running chain. </li></ul>  |
   | Path for Storing Upgrade Files | Only displayed when **Online Upgrade** is selected. You can customize the path. When customizing the path, configure it as an absolute path starting with `/`, and ensure that it contains only letters, numbers, and special characters (<code>-_:@/.</code>). |

2. Confirm the configuration

   On the **Confirm Configuration** page, you can view the information you entered on the **Configure Upgrade** page. You need to check and confirm that the configuration information is correct. If there are any errors, you can click **<UI-TERM key="ocp-v2.Cluster.Import.PreviousStep">Previous</UI-TERM>** to go back to the **Configure Upgrade** page for modification. If everything is correct, you can click **<UI-TERM key="ocp-v2.Cluster.Import.Next">Next</UI-TERM>** to start the pre-check.

   ![Confirm Configuration](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/900.update-oms-02.png)

3. Perform a pre-check

   If the pre-check is successful, you can click **<UI-TERM key="ocp-v2.Detail.TakeOver.Next">Next</UI-TERM>** to configure the data backup information. If the pre-check fails, you can choose to fix or ignore the failed items.

   * If you choose to fix, after the fix is completed, click **<UI-TERM key="ocp-v2.Detail.TakeOver.ReCheck">Recheck</UI-TERM>** to re-execute the environment pre-check.

   * If you choose to ignore, click **Ignore All Failed Items**, and the **Check Status** of the failed items will change to **Ignored**. You can then click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>** to configure the data backup information.

   <main id="notice" type='notice'>
     <h4>Notice</h4>
     <p>Ignoring all failed items may result in an upgrade failure. We recommend that you fix the failed items before proceeding. </p>
   </main>

   ![Pre-check](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/900.update-oms-03.png)

4. Backup data

   On the **<UI-TERM key="ocp-v2.Backup.Overview.Task.DataBackup">Data Backup</UI-TERM>** page, you can choose whether to back up key metadata and set the backup path (if needed). During the OMS upgrade, the metadata and monitoring data will be changed based on the upgrade requirements. These changes are irreversible. We recommend that you back up the metadata and monitoring data to avoid unexpected risks caused by the upgrade.

   ![Backup Data](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/900.update-oms-04.png)

   | Parameter | Description |
   |-------|-------|
   | Backup Method | Select **Backup Key Metadata** or **No Backup** from the drop-down list. |
   | Backup Path  | Only displayed when **Backup Key Metadata** is selected. You need to specify the local path of the current obd node and ensure that the available space is at least 2 GiB. You can customize the path. When customizing the path, configure it as an absolute path starting with `/`, and ensure that it contains only letters, numbers, and special characters (<code>-_:@/.</code>). </br>After setting the path, click the **Verify** button next to the path to check whether it meets the requirements. |

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <p>When you select <b>Backup Key Metadata</b>, you can click <b>Next</b> only after the backup path is verified. After you click <b>Next</b>, obd will pop up a window to back up the data. After the backup is completed, it will automatically enter the <b>Upgrade OMS</b> page.</p>
   </main>

5. Upgrade OMS

   During the upgrade, the **Upgrade OMS** page will display the upgrade logs. After the upgrade is successful, you can perform the following operations on the page:

   * Click the expand button next to **Upgrade Report** to view the upgrade logs.
   * Click the copy button next to the backup file save address to save the backup file path.
   * Click **Go to New Version** to open the OMS login page in a new tab.

     <main id="notice" type='explain'>
       <h4>Note</h4>
       <p>In Alibaba Cloud or other cloud environments, it may be impossible to obtain a public IP address, leading to access to the internal network address. In this case, the OMS login page may not be displayed normally. </p>
     </main>

   * Click **<UI-TERM key="ocp-v2.Component.AddSamplingInspectStrategy.Exit">Exit</UI-TERM>** and confirm the exit to exit the OMS upgrade program.

   If the deployment fails, you can click **Reupgrade** to attempt to re-execute the failed upgrade step. You can also click **Exit Page** to exit the OMS upgrade program.

   ![Upgrade](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/900.update-oms-05.png)

   On the **<UI-TERM key="ocp-v2.Component.StorageTrend.DataBackup">Data Backup</UI-TERM>** page, you can choose whether to back up critical metadata and specify the backup path (if needed). ### Step 5: Verify

1. Check the status of the servers

   After the upgrade, log in to the OMS Community Edition console. In the left-side navigation pane, choose **O&M Monitoring** > **Server**. On the **Server List** page, check whether the server list is displayed correctly. Make sure that the status of all servers is **<UI-TERM key="ocp-v2.Component.RecoverableTimeRange.Online">Online</UI-TERM>**.

2. Check the OMS version

   Log in to the OMS Community Edition console. Hover the cursor over **Help Center** in the upper-right corner of the page and click **About OMS**. In the dialog box that appears, check whether the OMS version is the target version.
