# Upgrade OMS

This topic describes how to upgrade OMS by using the graphical interface of obd.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Currently, obd supports only the upgrade of OMS Community Edition. </p>
</main>

## Prerequisites

Before you start, make sure that you have installed obd V4.1.0 or later. We recommend that you install the latest version. For more information, see [Install obd](../../200.quick-start/100.install-obd.md).

## Procedure

### Step 1: Obtain the installation package for the upgrade

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>If the OMS to be upgraded is a multi-node OMS, you need to perform the following steps on each node. </p>
</main>

1. Download the installation package

   Go to the [OceanBase Download Center](https://en.oceanbase.com/softwarecenter) and search for **OceanBase Migration Service**. Download the required installation package based on your situation, and upload it to any directory on the OBD control machine.

2. Load the downloaded OMS installation package to the local image repository of the Docker container

   ```shell
   [admin@test001 ~]$ sudo docker load -i oms_4.2.12-ce.tar.gz
   ```

3. Verify whether the installation package is loaded successfully

   ```shell
   [admin@test001 ~]$ sudo docker images
   ```

   The output is as follows:

   ```shell
   REPOSITORY                                    TAG                 IMAGE ID       CREATED        SIZE
   reg.docker.alibaba-inc.com/oceanbase/oms-ce   feature_4.2.11_ce   26f5f1554fc5   2 months ago   12.5GB
   reg.docker.alibaba-inc.com/oceanbase/oms-ce   feature_4.2.12_ce   28fddcdaf8a0   2 days ago     12.5GB
   ```

### Step 2: Disable HA

HA stands for High Available, which ensures the stability and continuity of data transmission links. Before the upgrade, you must disable the HA feature. If the HA feature is enabled, perform the following steps to disable it:    

* Log in to the OMS Community Edition console.    

* In the left-side navigation pane, choose **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** > **<UI-TERM key="ocp-v2.src.util.menu.SystemParameters">System Parameters</UI-TERM>**.    

* On the **<UI-TERM key="ocp-v2.src.util.menu.SystemParameters">System Parameters</UI-TERM>** page, find `ha.config`.    

* Click the edit icon next to the parameter name **Value**.    

* In the **Modify Value** dialog box, set `enable` to `false` to disable the HA feature.

### Step 3: Start the upgrade

1. Start the upgrade

   ```shell
   [admin@test001 ~]$ obd web upgrade
   ```

   The output is as follows. You can access the IP address in the output in a browser to go to the upgrade wizard page and click **Start Upgrade**.

   ```shell
   start OBD WEB in 0.0.0.0:8680
   please open http://10.10.10.1:8680/#/updateWelcome
   ```

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <ul>
     <li>
     <p>The default port for the GUI is 8680. You can use the <code>obd web upgrade -p &lt;PORT&gt;</code> command to specify a port. </p>
     </li>
     <li>
     <p>In Alibaba Cloud or other cloud environments, the program may fail to obtain a public IP address and output an internal IP address. In this case, you need to use the correct IP address to access the GUI. </p>
     </li>
     <li>
     <p>The <code>obd web</code> command is bound to 0.0.0.0. In a multi-NIC deployment, you can access the GUI through any accessible IP address. </p>
     </li>
     </ul>
   </main>

2. Select the product to be upgraded

   On the **Welcome to OceanBase Upgrade Wizard** page, select the **OceanBase Data Migration** module and click **<UI-TERM key="ocp-v2.Binlog.Component.UpgradeBinlogModal.Upgrade">Upgrade</UI-TERM>** to start the OMS upgrade.

### Step 4: Upgrade OMS

obd supports upgrading OMS deployed without obd. This section describes the upgrade methods for **obd deployment** and **non-obd deployment** based on the original deployment method of the OMS to be upgraded. You can choose the appropriate upgrade method based on your actual situation.

:::tab

tab obd deployment

1. Configure the upgrade

   On the **Configure Upgrade** page, you can select the deployment name of the OMS to be upgraded, the target version, and the upgrade method. The following table describes these parameters.

   ![Configure Upgrade](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/900.update-oms-01.png)

   | Parameter | Description |
   |------|--------|
   | Original Deployment Method | Select **obd Deployment** or **Non-obd Deployment** based on the deployment method of the OMS to be upgraded. |
   | Deployment Name  | Select the deployment name of the OMS to be upgraded from the drop-down list. You can execute the `obd cluster list` command in the CLI to view the deployment name (the `Name` column). |
   | Target Version  | Select the target version from the drop-down list.  |
   | Upgrade Method  | You can choose **<UI-TERM key="ocp-v2.Component.UpgradeDrawer.StopServiceUpgrade">Downtime Upgrade</UI-TERM>** or **Online Upgrade**:<ul><li><b>Stop Service Upgrade</b>: Replace the old container with a new image container. The running link will be temporarily interrupted during the upgrade.</li><li><b>Online Upgrade</b>: Replace the component package in the original container to implement the upgrade, ensuring that the running link remains uninterrupted throughout the process.</li></ul>  |
   | Path for Storing Upgrade Files | This parameter is displayed only when you select **Online Upgrade**. You can customize the path. The custom path must be an absolute path starting with `/` and can only contain letters, numbers, and special characters (<code>-_:@/.</code>). |

2. Confirm the configuration

   On the **Confirm Configuration** page, you can view the information you entered on the **Configure Upgrade** page. You need to check and confirm whether the configuration information is correct. If there are errors in the configuration, you can click **<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step2.PreviousStep">Previous</UI-TERM>** to return to the **Configure Upgrade** page to modify the configuration. If the configuration is correct, you can click **<UI-TERM key="ocp-v2.Detail.TakeOver.Next">Next</UI-TERM>** to start the pre-check.

   ![Confirm Configuration](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/900.update-oms-02.png)

3. Perform a pre-check

   If the pre-check is successful, you can click **<UI-TERM key="ocp-v2.Credential.Component.ImportModal.NextStep">Next</UI-TERM>** to configure the data backup information. If the pre-check fails, you can choose to fix or ignore the failed items.

   * If you choose to fix, after the fix is completed, you can click **<UI-TERM key="ocp-v2.Detail.TakeOver.ReCheck">Recheck</UI-TERM>** to re-execute the environment pre-check.

   * If you choose to ignore, you can click **Ignore All Failed Items**. In this case, the **Check Status** of the failed items will change to **Ignored**, and you can click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>** to configure the data backup information.

   <main id="notice" type='notice'>
     <h4>Notice</h4>
     <p>Ignoring all failed items may cause the upgrade to fail. We recommend that you fix the failed items before proceeding to the next step.</p>
   </main>

   ![Pre-check](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/900.update-oms-03.png)

4. Backup data

   On the **<UI-TERM key="ocp-v2.Component.TenantLevelInfoDrawer.DataBackup">Data Backup</UI-TERM>** page, you can choose whether to back up the critical metadata and specify the backup path (if needed). During the OMS upgrade, the metadata and monitoring data will be modified based on the upgrade requirements. These modifications are irreversible. We recommend that you back up the metadata and monitoring data to avoid unexpected risks caused by the upgrade.

   ![Backup Data](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/900.update-oms-04.png)

   | Parameter | Description |
   |-------|-------|
   | Backup Method | You can select **Backup Critical Metadata** or **Do Not Backup** from the drop-down list. |
   | Backup Path  | This parameter is displayed only when you select **Backup Critical Metadata**. You must specify the local path of the current obd node and ensure that the available space is at least 2 GiB. You can customize the path. The custom path must be an absolute path starting with `/` and can only contain letters, numbers, and special characters (<code>-_:@/.</code>). </br>After you specify the path, you must click the **Validate** button to verify whether the path meets the requirements. |

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <p>If you select <b>Backup Critical Metadata</b>, you can click <b>Next</b> only after the backup path is validated. After you click <b>Next</b>, obd will pop up a window to back up the data. After the backup is completed, the system will automatically switch to the <b>Upgrade OMS</b> page.</p>
   </main>

5. Upgrade OMS

   During the upgrade, the **Upgrade OMS** page will display the upgrade logs. After the upgrade is successful, you can perform the following operations on the page:

   * Click the expand icon next to **Upgrade Report** to view the upgrade logs.
   * Click the copy icon next to the backup file save address to save the backup file path.
   * Click **Go to Try New Version** to open the OMS login page in a new tab.

     <main id="notice" type='explain'>
       <h4>Note</h4>
       <p>In an Alibaba Cloud or other cloud environment, the program may fail to obtain the public IP address, and thus access the internal network address. In this case, the OMS login page cannot be displayed normally.</p>
     </main>

   * Click **<UI-TERM key="ocp-v2.Component.AddSamplingInspectStrategy.Exit">Exit</UI-TERM>** and confirm to exit the OMS upgrade program.
  
   If the deployment fails, you can click **Reupgrade** to re-execute the failed upgrade steps. You can also click **Exit Page** to exit the OMS upgrade program.

   ![Upgrade](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/900.update-oms-05.png)

tab non-obd deployment

   ![Configure Upgrade](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/900.update-oms-06.png)

   | Parameter | Description |

After the upgrade is completed, obd will automatically use this deployment name to take over the upgraded OMS cluster. |

   | SSH Port | The default port is 22, and custom ports are supported. |
   | Take Over | Click **Take Over** to have obd take over the OMS based on the connection information. After a successful takeover, the **Connection Information** section will be grayed out and cannot be modified. |
   | OMS Docker Image | After the takeover is successful, you can select the target version from the dropdown list for upgrade. |
   | Upgrade Method | Two upgrade methods are supported: **<UI-TERM key="ocp-v2.Component.UpgradeDrawer.StopServiceUpgrade">Downtime Upgrade</UI-TERM>** and **Online Upgrade**:<ul><li><b>Stop Service Upgrade</b>: Replace the old container with a new container by deploying the new image container. During the upgrade, the running link will experience a brief interruption.</li><li><b>Online Upgrade</b>: Replace the component package directly in the existing container to achieve the upgrade, ensuring that the running link remains uninterrupted throughout the process.</li></ul>  |
   | Path for Storing Upgrade Files | This field is displayed only when **Online Upgrade** is selected. Custom paths are supported. When specifying a custom path, it must be an absolute path starting with `/` and can only contain letters, numbers, and special characters (<code>-_:@/.</code>). |

   The **Configuration Confirmation** page displays the information you entered on the **Upgrade Configuration** page. You need to check and confirm that the configuration information is correct. If there are any errors, you can click **<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step2.PreviousStep">Previous</UI-TERM>** to go back to the **Upgrade Configuration** page for modification. If everything is correct, you can click **<UI-TERM key="ocp-v2.Cluster.Import.Next">Next</UI-TERM>** to start the pre-check.

   ![Configuration Confirmation](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/900.update-oms-10.png)

3. Pre-check

   If the pre-check is passed, you can click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>** to start the OMS upgrade. If the pre-check fails, you can choose to fix the failed items or ignore them.

   * If you choose to fix the failed items, after the fixes are completed, click **<UI-TERM key="ocp-v2.Cluster.Import.ReCheck">Recheck</UI-TERM>**. The system will then re-execute the environment pre-check program.

   * If you choose to ignore the failed items, click **Ignore All Failed Items**. The **Check Status** of the failed items will change to **Ignored**, and you can click **<UI-TERM key="ocp-v2.Credential.Component.ImportModal.NextStep">Next</UI-TERM>** to start the OMS upgrade.

   <main id="notice" type='notice'>
     <h4>Notice</h4>
     <p>Ignoring all failed items may lead to an upgrade failure. It is recommended to fix the failed items before proceeding to the next step.</p>
   </main>

   ![Pre-check](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/900.update-oms-03.png)

   On the **<UI-TERM key="ocp-v2.Component.StorageTrend.DataBackup">Data Backup</UI-TERM>** page, you can choose whether to back up critical metadata and specify the backup path (if needed). During the OMS upgrade, metadata and monitoring data will be modified based on the upgrade requirements. These changes are irreversible, so it is recommended to back up the metadata and monitoring data to avoid unexpected risks caused by the upgrade.

   ![Data Backup](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/900.update-oms-04.png)

   | Parameter  | Description  |
   |-------|-------|
   | Backup Method | You can select **Backup Critical Metadata** or **Do Not Backup** from the dropdown list. |
   | Backup Path  | This field is displayed only when **Backup Critical Metadata** is selected. You need to specify the local path on the node where obd is located and ensure that at least 2 GiB of available space is available. Custom paths are supported. When specifying a custom path, it must be an absolute path starting with `/` and can only contain letters, numbers, and special characters (<code>-_:@/.</code>). </br>After setting the path, click the **<UI-TERM key="ocp-v2.OBProxy.New.Test">Test</UI-TERM>** button next to the path to verify if the path meets the requirements. |

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <p>When you select <b>Backup Critical Metadata</b>, you can click <b>Next</b> only after the backup path test is passed. After clicking <b>Next</b>, obd will pop up a window for data backup. After the backup is completed, it will automatically proceed to the <b>OMS Upgrade</b> page.</p>

5. OMS Upgrade

   During the upgrade, the **OMS Upgrade** page displays the upgrade logs. After the upgrade is successful, you can perform the following actions on the page:

   * Click the expand button next to **Upgrade Report** to view the upgrade logs.

   * Click **Go to New Version** to open the OMS login page in a new tab.

     <main id="notice" type='explain'>

       <p>In Alibaba Cloud or other cloud environments, it is possible for the program to fail to obtain a public IP address, resulting in access to the internal network address. In such cases, the OMS login page may not be displayed properly.</p>
     </main>

   * Click **<UI-TERM key="ocp-v2.Component.AddSamplingInspectStrategy.Exit">Exit</UI-TERM>** and confirm again to exit the OMS upgrade program.
  
   If the deployment fails, you can click **Re-upgrade** to have obd retry the failed upgrade steps. Alternatively, you can click **Exit Page** to exit the OMS upgrade program.

### Step 5: Verify

1. Check the status of the server

   After the upgrade is complete, log in to the OMS Community Edition console. In the left-side navigation pane, choose **O&M Monitoring** > **Server**. On the **Server List** page, check whether the server list is displayed correctly. Also, make sure that the status of all servers is **<UI-TERM key="ocp-v2.page.Overview.Online">Online</UI-TERM>**.

2. Check the OMS version

   Log in to the OMS Community Edition console. Hover the cursor over **Help Center** in the upper-right corner of the page and click **About OMS**. A dialog box appears, displaying the OMS information. Check whether the OMS version is the target version.
