# Deploy OMS

This topic describes how to deploy OceanBase Migration Service (OMS) by using the obd configuration file in a CentOS Linux 7.9 environment based on the x86 architecture.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Currently, obd supports only OMS Community Edition V4.2.11 and later. </p>
</main>

## Prerequisites

Before you start, make sure that you meet the following conditions:

* You have installed obd V4.0.0 or later. We recommend that you install the latest version. For more information, see [Install obd](../../200.quick-start/100.install-obd.md).

* The machine on which you want to deploy OMS meets the deployment requirements. <!-- For more information, see the [Deploy OMS Community Edition](https://www.oceanbase.com/docs/community-oms-cn-1000000004253109) topic in the OceanBase Migration Service documentation on the official website. --> The deployment requirements vary depending on the edition of OMS that you want to deploy. <!-- For more information, see [Deployment requirements](../200.deploy-oms/100.deploy-oms.md). -->

* The machine on which you want to deploy OMS has Docker installed. <!-- For more information, see [Install Docker](https://docs.docker.com/engine/install/). -->

* You have prepared a database to store the metadata of OMS Community Edition. You can use a MySQL or OceanBase Database instance. We recommend that you use OceanBase Database Community Edition.
  
  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>To improve the system reliability, we recommend that you implement a high-availability database solution for MetaDB. This will ensure the 7x24-hour stable operation of OMS core services and reduce the risk of business interruption. </p>
  </main>

## Procedure

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>The following procedure is based on the CentOS Linux 7.9 image for the x86 architecture. The operation interface may vary depending on the environment and the OBOS version. Please refer to the actual interface for specific operations.</p>
</main>

### Step 1: Load the OMS Community Edition package

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>If you plan to deploy OMS on multiple nodes, you need to perform the following steps on each node.</p>
</main>

1. Download the OMS installation package

   You can download the OMS Community Edition installation package from the [OceanBase Software Download Center](https://en.oceanbase.com/softwarecenter). The installation package is usually a `tar.gz` file starting with `oms`, such as `oms_4.2.11-ce.tar.gz`.

2. Load the downloaded OMS installation package into the local image repository of the Docker container

   ```shell
   [admin@test ~]$ sudo docker load -i oms_4.2.11-ce.tar.gz
   ```

3. Verify whether the package is loaded successfully

   ```shell
   [admin@test ~]$ docker images
   ```

   The output is as follows:

   ```shell
   REPOSITORY                                    TAG                 IMAGE ID       CREATED      SIZE
   reg.docker.alibaba-inc.com/oceanbase/oms-ce   feature_4.2.11_ce   26f5f1554fc5   2 days ago   12.5GB
   ```

### Step 2: Start the web interface

1. Run the `obd web` command to start the web interface, and click the displayed address to access the graphical operation interface of obd.

   ```shell
   [admin@test001 ~]$ obd web
   start OBD WEB in 0.0.0.0:8680
   please open http://10.10.10.1:8680
   ```

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <ul>
     <li><p>The web interface uses port 8680 by default. You can use the <code>obd web -p &lt;PORT&gt;</code> command to specify a port.</p></li>
     <li><p>In an Alibaba Cloud or other cloud environment, the program may fail to obtain a public IP address and instead output an internal IP address. In this case, you need to use the correct public IP address to access the web interface.</p></li>
     <li><p>The <code>obd web</code> command is bound to 0.0.0.0. In a multi-network interface deployment, you can access the web interface through any accessible IP address.</p></li>
     <li><p>You can use the nohup or screen command to run the <code>obd web</code> command in the background.</p></li>
     </ul>
   </main>

2. (Optional) Place the cursor on the **Chinese** character in the upper-right corner of the graphical operation interface and click it to switch between Chinese and English interfaces based on the displayed language. The following figure shows the language switcher in the upper-right corner of the interface. The figure shows the Chinese interface. The English interface is similar to the Chinese interface, except that the language switcher displays **English** instead of **Chinese**.

   <!-- <img width="677" height="419.5" src="https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V2.4.0/zh-CN/200.quick-start/300.deploy-ocp-by-ui-12.png" alt="Language switcher"> -->

3. In the operation interface, click **Start Your Trial**. In the **Welcome to OceanBase Deployment Wizard** interface that appears, select the **OceanBase Data Migration** module and click **<UI-TERM key="ocp-v2.Component.InstallService.Mounting">Install</UI-TERM>** to enter the OMS deployment interface.

## Step 4: Configure MetaDB

You can configure MetaDB information on the **<UI-TERM key="ocp-v2.Binlog.New.MetadbConfiguration">MetaDB Configuration</UI-TERM>** page. The following describes the configuration items.

1. Access Configuration

   The **Access Configuration** section is used to configure the access information of MetaDB. The following figure shows the interface.

   <!-- ![Access Configuration](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.0.0/zh-CN/400.deploy-oms-by-ui-02.png) -->

   | Parameter | Description |
   |-------|--------|
   | Access Address | The IP address for accessing MetaDB. |
   | Port | The port for accessing MetaDB, which is `2881` by default. |
   | Access Account | The account for accessing MetaDB, such as `root`. If you use OceanBase Database as MetaDB, you must configure a user in the sys tenant. You do not need to specify the tenant name. |
   | Password | The password for connecting to the MetaDB account. |
   | Validate | Click **Validate** to verify whether the configured information is accessible. |

2. Monitoring Configuration

   This section is optional. If you want OMS to collect and display monitoring data, you must deploy a time-series database. Currently, only InfluxDB V1.8 is supported. <!-- For more information about how to deploy a time-series database, see [Deploy a time-series database](https://www.oceanbase.com/docs/community-oms-cn-1000000004253199).  -->After the deployment, you can configure the access information of the time-series database in this section. The following figure shows the interface.

   <!-- ![Monitoring Configuration](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.0.0/zh-CN/400.deploy-oms-by-ui-03.png) -->

   | Parameter | Description |
   |-------|--------|
   | InfluxDB Address | The IP address for accessing the time-series database.  |
   | Port | The port for accessing the time-series database, which is `8086` by default. |
   | Username | The username for accessing the time-series database. |
   | Password | The password corresponding to the username. |
   | Validate | Click **Validate** to verify whether the configured information is accessible. |

3. More Configurations

   This section is optional. If you want to customize the database names for each service in MetaDB, you can expand this section to configure the database names. The following figure shows the interface.

   <!-- ![More Configurations](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.0.0/zh-CN/400.deploy-oms-by-ui-04.png) -->

   | Parameter   | Description   |
   |--------|--------|
   | drc_rm_db  | The database name for the management console. If not configured, the default value is `oms_rm`, which can be customized. When you deploy OMS, obd creates the corresponding database in MetaDB based on the configuration.  |
   | drc_cm_db  | The database name for the cluster management service. If not configured, the default value is `oms_cm`, which can be customized. When you deploy OMS, obd creates the corresponding database in MetaDB based on the configuration.  |
   | drc_cm_heartbeat_db  | The database name for the heartbeat of the cluster management service. If not configured, the default value is `oms_cm_heartbeat_x`, where `x` starts at 1 and increments by 1 for each region of OMS. This parameter can be customized. When you deploy OMS, obd creates the corresponding database in MetaDB based on the configuration. |

After you complete all the configurations, click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>** to go to the **Configuration Confirmation** page.

## Step 5: Confirm the configuration

On the **Confirm Configuration** page, you can view all the configuration information. If you find any issues, click **<UI-TERM key="ocp-v2.Credential.Component.ImportModal.PreviousStep">Previous</UI-TERM>** to make modifications. After confirming that all the information is correct, click **<UI-TERM key="ocp-v2.Detail.TakeOver.Next">Next</UI-TERM>** to go to the **<UI-TERM key="ocp-v2.Cluster.Import.Precheck">Precheck</UI-TERM>** page. The system will verify whether your environment and configuration meet all the requirements for installing OMS.

## Step 6: Precheck

The **<UI-TERM key="ocp-v2.Cluster.Import.Precheck">Precheck</UI-TERM>** page displays the system check results. If an error is reported during the precheck, you can click **View More Solutions** to go to the error code documentation and modify the error as needed. After all errors are resolved, click **<UI-TERM key="ocp-v2.Detail.TakeOver.ReCheck">Recheck</UI-TERM>** to perform the precheck again.

<!-- ![Precheck](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.0.0/zh-CN/400.deploy-oms-by-ui-05.png) -->

After the precheck is successful, click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>** to go to the **Deploy** page and start deploying OMS.

## Step 7: Deploy

During deployment, the **Deployment** page displays the deployment logs. You can view the detailed installation logs in the **Deployment Logs** module.

* If the deployment fails, check the log information to identify the cause of the failure. <!-- Contact Technical Support for assistance, or post your question in the [Q&A section](https://ask.oceanbase.com/) on the official website. Our on-duty engineers will help you resolve the issue. After identifying and fixing the cause of the installation failure, click **Redeploy**. In the confirmation window that appears, click **<UI-TERM key="ocp-v2.Component.UpgradeDistributedClusterDrawer.Confirm">OK</UI-TERM>**. The system will then clean up the failed OMS installation environment and re-execute the installation process. -->

* If the deployment is successful, click **Copy Info**. After copying and saving the OMS access address and account credentials, click **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">Complete</UI-TERM>** to exit the deployment program.
