# Deploy OMS

This topic describes how to deploy OceanBase Migration Service (OMS) by using an obd configuration file in a CentOS Linux 7.9 environment based on an x86 architecture.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Currently, obd supports only OMS Community Edition V4.2.11 and later. </p>
</main>

## Prerequisites

Before you start, make sure that you meet the following requirements:

* You have installed obd V4.0.0 or later. We recommend that you install the latest version. For more information, see [Install obd](../../200.quick-start/100.install-obd.md).

* The server where you want to deploy OMS meets the deployment requirements. For more information, see the [Deploy OMS Community Edition](https://www.oceanbase.com/docs/community-oms-cn-1000000004253109) section in the OceanBase Migration Service documentation.

* Docker is installed on the server where you want to deploy OMS.

* You have prepared a database for storing the metadata of OMS Community Edition. You can use MySQL or OceanBase Database. We recommend that you use OceanBase Database Community Edition.
  
  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>To improve system reliability, we recommend that you implement a high-availability database solution for MetaDB. This will ensure the 7x24-hour stable operation of OMS core services and reduce the risk of business interruption. </p>
  </main>

* If you want OMS to collect and display monitoring data, you need to deploy and configure a time series database. Currently, only InfluxDB V1.8 is supported. For more information, see the [Deploy a time series database](https://www.oceanbase.com/docs/community-oms-cn-1000000004253199) section in the OceanBase Migration Service documentation.

## Considerations

By default, the High Availability (HA) feature is disabled in OceanBase Migration Service (OMS) Community Edition. To enable HA, you can modify the `ha.config` parameter to set `enable` to `true` after the deployment is complete. For more information, see [Modify the configuration of the high availability feature](https://www.oceanbase.com/docs/community-oms-cn-10000000042531647) in the OceanBase Migration Service documentation.

## Procedure

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This topic provides operation instructions for the CentOS Linux 7.9 x86 architecture image environment. The operation interface may vary depending on the environment and the OBOS version. Please refer to the actual interface. </p>
</main>

### Step 1: Load the OMS Community Edition package

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>If you plan to deploy OMS on multiple nodes, you need to perform the following steps on each node.</p>
</main>

1. Download the OMS installation package

   You can download the OMS Community Edition installation package from the [OceanBase Download Center](https://en.oceanbase.com/softwarecenter). The installation package is usually a `tar.gz` file that starts with `oms`, such as `oms_4.2.11-ce.tar.gz`.

2. Load the downloaded OMS installation package into the local image repository of the Docker container

   ```shell
   [admin@test ~]$ sudo docker load -i oms_4.2.11-ce.tar.gz
   ```

3. Verify whether the package is loaded successfully

   ```shell
   [admin@test ~]$ sudo docker images
   ```

   The output is as follows:

   ```shell
   REPOSITORY                                    TAG                 IMAGE ID       CREATED      SIZE
   reg.docker.alibaba-inc.com/oceanbase/oms-ce   feature_4.2.11_ce   26f5f1554fc5   2 days ago   12.5GB
   ```

### Step 2: Start the GUI

1. Run the `obd web` command to start the GUI. Click the displayed address to access the graphical operation interface of obd. The output is as follows:

   ```shell
   [admin@test001 ~]$ obd web
   start OBD WEB in 0.0.0.0:8680
   please open http://10.10.10.1:8680
   ```

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <ul>
     <li><p>The GUI uses port 8680 by default. You can use the <code>obd web -p &lt;PORT&gt;</code> command to specify a port.</p></li>
     <li><p>If you deploy OMS in Alibaba Cloud or another cloud environment, the GUI may display an internal IP address instead of a public IP address. In this case, you need to use the correct IP address to access the GUI.</p></li>
     <li><p>The <code>obd web</code> command is bound to 0.0.0.0. If you deploy OMS on multiple network cards, you can access the GUI through any accessible IP address.</p></li>
     <li><p>You can use the nohup or screen command to run the <code>obd web</code> command in the background.</p></li>
     </ul>
   </main>

2. (Optional) Move the pointer over the **Chinese** text in the upper-right corner of the GUI. Click the displayed language to switch between Chinese and English. The following figure shows the language switching.

   <img width="677" height="419.5" src="https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V2.4.0/zh-CN/200.quick-start/300.deploy-ocp-by-ui-12.png" alt="Language switching">

3. In the GUI, click **Start Your Trial**. In the **Welcome to OceanBase Deployment Wizard** window, select the **OceanBase Data Migration** module and click **<UI-TERM key="ocp-v2.Component.InstallService.Mounting">Install</UI-TERM>** to go to the OMS deployment interface.

## Step 4: Configure MetaDB

You can configure MetaDB information on the **<UI-TERM key="ocp-v2.Binlog.New.MetadbConfiguration">MetaDB Configuration</UI-TERM>** page. The following describes the configuration items.

1. Access configuration

   The **Access Configuration** section is used to configure the access information of MetaDB. The following figure shows the interface.

   ![Access configuration](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.0.0/zh-CN/400.deploy-oms-by-ui-02.png)

   | Parameter | Description |
   |-------|--------|
   | Access Address | The IP address for accessing MetaDB. |
   | Port | The port for accessing MetaDB. The default value is `2881`. |
   | Access Account | The account for accessing MetaDB, such as `root`. If OceanBase Database is used as MetaDB, the account must be a user in the sys tenant, and the tenant name does not need to be specified. |
   | Password | The password for the account. |
   | Verify | Click **Verify** to verify whether the information can be accessed. |

2. Monitoring configuration

   This section is optional. If you want OMS to collect and display monitoring data, you can configure the access information of the time series database in this section after deploying it. The following figure shows the interface.

   ![Monitoring configuration](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.0.0/zh-CN/400.deploy-oms-by-ui-03.png)

   | Parameter | Description |
   |-------|--------|
   | InfluxDB Address | The IP address for accessing the time series database.  |
   | Port | The port for accessing the time series database. The default value is `8086`. |
   | Username | The username for accessing the time series database. |
   | Password | The password corresponding to the username. |
   | Verify | Click **Verify** to verify whether the information can be accessed. |

3. More configurations

   This section is optional. If you want to customize the database names corresponding to various services in MetaDB, you can expand this section to configure the database names. The following figure shows the interface.

   ![More configurations](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.0.0/zh-CN/400.deploy-oms-by-ui-04.png)

   | Parameter | Description |
   |--------|--------|
   | drc_rm_db  | The database name of the management console. If not configured, the default value is `oms_rm`, which can be customized. When deploying OMS, obd creates the corresponding database in MetaDB based on the configuration.  |
   | drc_cm_db  | The database name of the cluster management service. If not configured, the default value is `oms_cm`, which can be customized. When deploying OMS, obd creates the corresponding database in MetaDB based on the configuration.  |
   | drc_cm_heartbeat_db  | The name of the heartbeat database of the cluster management service. If not configured, the default value is `oms_cm_heartbeat_x`, where `x` starts from 1 and increments based on the number of regions of OMS. It can be customized. When deploying OMS, obd creates the corresponding database in MetaDB based on the configuration. |

After you configure all parameters, click **<UI-TERM key="ocp-v2.Cluster.Import.Next">Next</UI-TERM>** to go to the **Configuration Confirmation** page.

## Step 5: Confirm the configuration

On the **Confirm Configuration** page, you can view all the configuration information. If you find any issues, click **<UI-TERM key="ocp-v2.Detail.TakeOver.PreviousStep">Previous</UI-TERM>** to modify the information. After you confirm that the information is correct, click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>** to go to the **<UI-TERM key="ocp-v2.Cluster.Import.Precheck">Precheck</UI-TERM>** page. The system will verify whether your environment and configuration meet the requirements for installing OMS.

## Step 6: Precheck

On the **<UI-TERM key="ocp-v2.Cluster.Import.Precheck">Precheck</UI-TERM>** page, the system displays the precheck results. If an error is reported, you can click **View More** to go to the error code documentation and modify the error as needed. After all errors are resolved, click **<UI-TERM key="ocp-v2.Detail.TakeOver.ReCheck">Recheck</UI-TERM>** to perform the precheck again.

![Precheck](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.0.0/zh-CN/400.deploy-oms-by-ui-05.png)

After the precheck is passed, click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>** to go to the **Deploy** page and start the OMS deployment.

## Step 7: Deploy

During deployment, the **Deployment** page displays the deployment logs. You can view the detailed installation logs in the **Deployment Log** section.

* If the deployment fails, check the log information to identify the cause of the failure. Contact Technical Support or post your question in the [Q&A section](https://ask.oceanbase.com/) on the website. Our on-duty engineers will assist you in troubleshooting. Once the cause of the installation failure is identified and the issue is fixed, click **Redeploy**. In the confirmation window that appears, click **<UI-TERM key="ocp-v2.Plan.Component.PlanTemplateTable.Confirm">OK</UI-TERM>**. The system will then clear the failed OMS installation environment and re-execute the installation program.

* If the deployment is successful, click **Copy Info** to copy and save the OMS access address and account information. Then, click **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">Complete</UI-TERM>** to exit the deployment program.
