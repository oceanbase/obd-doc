# Deploy OMS

This topic describes how to deploy OceanBase Migration Service (OMS) by using an obd configuration file in a CentOS Linux 7.9 environment based on an x86 architecture.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Currently, obd supports only OMS Community Edition V4.2.11 and later. </p>
</main>

## Prerequisites

Before you start, make sure that you meet the following conditions:

* You have installed obd V4.0.0 or later. We recommend that you install the latest version. For more information, see [Install obd](../../200.quick-start/100.install-obd.md).

* The server where you want to deploy OMS meets the deployment requirements. For more information, see [Deploy OMS Community Edition](https://www.oceanbase.com/docs/community-oms-cn-1000000004253109) in the OceanBase Migration Service documentation.

* Docker is installed on the server where you want to deploy OMS.

* You have prepared a database to store the metadata of OMS Community Edition. You can use a MySQL or OceanBase Database instance. We recommend that you use an OceanBase Database Community Edition instance.
  
  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>To improve system reliability, we recommend that you implement a high-availability database solution for MetaDB. This will ensure the 7x24-hour stable operation of OMS core services and reduce the risk of business interruption. </p>
  </main>

* If you want OMS to collect and display monitoring data, you must deploy and configure a time-series database. Currently, only InfluxDB V1.8 is supported. For more information, see [Deploy a time-series database](https://www.oceanbase.com/docs/community-oms-cn-1000000004253199) in the OceanBase Migration Service documentation.

## Considerations

The High Availability (HA) feature is disabled by default in OceanBase Migration Service Community Edition. To enable HA, you can log in to the OMS console and set the `enable` parameter in the `ha.config` file to `true` after the service is deployed. For more information, see [Modify the HA configuration](https://www.oceanbase.com/docs/community-oms-cn-10000000042531647) in the OceanBase Migration Service documentation.

## Procedure

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>The following instructions are based on the CentOS Linux 7.9 image for the x86 architecture. The operation interface may vary depending on the environment and the OBOS version. Please refer to the actual interface for accurate information.</p>
</main>

### Step 1: Load the OMS Community Edition package

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>If you plan to deploy OMS in a multi-node environment, each node must perform the following steps.</p>
</main>

1. Download the OMS installation package

   You can download the OMS Community Edition installation package from the [OceanBase Download Center](https://en.oceanbase.com/softwarecenter). The installation package is usually a `tar.gz` file starting with `oms`, such as `oms_4.2.11-ce.tar.gz`.

2. Load the downloaded OMS installation package into the local image repository of the Docker container

   ```shell
   [admin@test ~]$ sudo docker load -i oms_4.2.11-ce.tar.gz
   ```

3. Verify whether the loading is successful

   ```shell
   [admin@test ~]$ sudo docker images
   ```

   The output is as follows:

   ```shell
   REPOSITORY                                    TAG                 IMAGE ID       CREATED      SIZE
   reg.docker.alibaba-inc.com/oceanbase/oms-ce   feature_4.2.11_ce   26f5f1554fc5   2 days ago   12.5GB
   ```

### Step 2: Start the graphical interface

1. Execute the `obd web` command to start the graphical interface, and click the provided URL to access the obd graphical interface.

   ```shell
   [admin@test001 ~]$ obd web
   start OBD WEB in 0.0.0.0:8680
   please open http://10.10.10.1:8680
   ```

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <ul>
     <li><p>The default port for the graphical interface is 8680. You can use the <code>obd web -p &lt;PORT&gt;</code> command to specify a port, which must be within the range [1025, 65535].</p></li>
     <li><p>In Alibaba Cloud or other cloud environments, the system may fail to obtain a public IP address and instead display an internal IP address. This IP address is not public, so you need to use the correct address to access the graphical interface.</p></li>
     <li><p>The <code>obd web</code> command is bound to 0.0.0.0. In a multi-network interface deployment, you can access the graphical interface using any accessible IP address.</p></li>
     <li><p>You can use the nohup or screen command to run the <code>obd web</code> command in the background.</p></li>
     </ul>
   </main>

2. (Optional) Place the cursor on the **Chinese** character in the upper-right corner of the graphical interface and click to switch between Chinese and English interfaces based on the displayed language.

   <img width="677" height="419.5" src="https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V2.4.0/zh-CN/200.quick-start/300.deploy-ocp-by-ui-12.png" alt="Language switch">

3. In the interface, click **Start Your Trial**. In the displayed **Welcome to OceanBase Deployment Wizard** interface, select the **OceanBase Data Migration** module, and click **<UI-TERM key="ocp-v2.Component.InstallService.Mounting">Install</UI-TERM>** to enter the OMS deployment interface.

### Step 4: Configure MetaDB

You can configure MetaDB information on the **<UI-TERM key="ocp-v2.Binlog.New.MetadbConfiguration">MetaDB Configuration</UI-TERM>** page. The following describes the configuration items.

1. Access configuration

   The **Access Configuration** section is used to configure the access information of MetaDB. The following figure shows the interface.

   ![Access configuration](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.0.0/zh-CN/400.deploy-oms-by-ui-02.png)

   | Parameter | Description |
   |-------|--------|
   | Access Address | The IP address for accessing MetaDB. |
   | Port | The port for accessing MetaDB. The default value is `2881`. |
   | Access Account | The account for accessing MetaDB. For example, `root`. If you use OceanBase Database as MetaDB, you must configure a user in the sys tenant. You do not need to specify the tenant name. |
   | Password | The password for connecting to the MetaDB account. |
   | Verify | Click **Verify** to check whether the configured information is accessible. |

2. Monitoring configuration

   This section is optional. If you want OMS to collect and display monitoring data, you can configure the access information of the time series database after deploying it. The following figure shows the interface.

   ![Monitoring configuration](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.0.0/zh-CN/400.deploy-oms-by-ui-03.png)

   | Parameter | Description |
   |-------|--------|
   | InfluxDB Address | The IP address for accessing the time series database.  |
   | Port | The port for accessing the time series database. The default value is `8086`. |
   | Username | The username for accessing the time series database. |
   | Password | The password corresponding to the username. |
   | Verify | Click **Verify** to check whether the configured information is accessible. |

3. More configurations

   This section is optional. If you want to customize the database names corresponding to various services in MetaDB, you can expand this section to configure the database names. The following figure shows the interface.

   ![More configurations](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.0.0/zh-CN/400.deploy-oms-by-ui-04.png)

   | Parameter   | Description   |
   |--------|--------|
   | drc_rm_db  | The database name for the management console. If you do not configure this parameter, the default value is `oms_rm`. You can customize this parameter. When you deploy OMS, obd creates the corresponding database in MetaDB based on the configuration.  |
   | drc_cm_db  | The name of the metadata database for the cluster management service. If you do not configure this parameter, the default value is `oms_cm`. You can customize this parameter. When you deploy OMS, obd creates the corresponding database in MetaDB based on the configuration.  |
   | drc_cm_heartbeat_db  | The name of the heartbeat database for the cluster management service. If you do not configure this parameter, the default value is `oms_cm_heartbeat_x`, where `x` starts from 1 and increments based on the number of regions of OMS. You can customize this parameter. When you deploy OMS, obd creates the corresponding database in MetaDB based on the configuration. |

After you configure all parameters, click **<UI-TERM key="ocp-v2.Cluster.Import.Next">Next</UI-TERM>** to go to the **Configuration Confirmation** page.

### Step 5: Configuration confirmation

On the **Configuration Confirmation** page, you can view all the configured information. If you find an error, click **<UI-TERM key="ocp-v2.Credential.Component.ImportModal.PreviousStep">Previous</UI-TERM>** to go back and modify the configuration. After you confirm that all the configurations are correct, click **<UI-TERM key="ocp-v2.Detail.TakeOver.Next">Next</UI-TERM>** to go to the **<UI-TERM key="ocp-v2.Detail.TakeOver.Precheck">Precheck</UI-TERM>** page. The system will verify whether your environment and configurations meet all the requirements for installing OMS.

### Step 6: Precheck

The **<UI-TERM key="ocp-v2.Cluster.Import.Precheck">Precheck</UI-TERM>** page displays the check results. If an error occurs during the precheck, you can click **View More Solutions** to go to the error code documentation and modify the configuration based on the documentation. After you fix all the errors, click **<UI-TERM key="ocp-v2.Detail.TakeOver.ReCheck">Recheck</UI-TERM>** to perform the precheck again.

![Precheck](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.0.0/zh-CN/400.deploy-oms-by-ui-05.png)

After the precheck is passed, click **<UI-TERM key="ocp-v2.Detail.TakeOver.Next">Next</UI-TERM>** to go to the **Deployment** page and start the deployment of OMS.

### Step 7: Deployment

During the deployment, the **Deployment** page displays the deployment logs. You can view the detailed installation logs in the **Deployment Logs** section.

* If the deployment fails, view the log information to identify the cause of the failure and contact technical support for assistance, or post a question in the [Q&A section](https://ask.oceanbase.com/) on the official website. Our on-duty engineers will assist you in solving the problem. After you locate and fix the issue, click **Redeploy**. In the confirmation window that appears, click **<UI-TERM key="ocp-v2.Component.UpgradeDistributedClusterDrawer.Confirm">OK</UI-TERM>**. The system will clean up the failed OMS installation environment and re-execute the installation program.

* If the deployment is successful, click **Copy Information**. After you copy and save the access address and account information of OMS, click **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">Complete</UI-TERM>** to exit the deployment program.
