# Deploy OCP

This topic describes how to deploy OceanBase Cloud Platform (OCP) by using the obd graphical interface, and takes the creation of a new OceanBase Database as the MetaDB of OCP as an example.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Currently, obd supports only OCP Community Edition V4.2.1 and later and OCP Enterprise Edition V4.3.5 and later. </p>
</main>

## Terminology

* OceanBase Database

  A fully self-developed enterprise-level native distributed database. For more information, see [OceanBase Database documentation](https://www.oceanbase.com/docs/oceanbase-database-cn).

* obd

  OceanBase Deployer, an installation and deployment tool for OceanBase Database. For more information, see [OceanBase Deployer documentation](../../100.what-is-obd.md).

* OBProxy

  OceanBase Database Proxy, a proxy server for OceanBase Database. It is also known as ODP. For more information, see [OceanBase Database Proxy documentation](https://www.oceanbase.com/docs/odp-doc-cn).

* OCP

  OceanBase Cloud Platform, a cloud platform for OceanBase Database. For more information, see [OceanBase Cloud Platform documentation](https://www.oceanbase.com/docs/oceanbase-ocp-cn).

* MetaDB

  A key component of OCP that provides underlying storage capabilities for managing metadata and monitoring data. OCP-Server calls MetaDB data to provide full lifecycle management services for OceanBase Database.

* Load balancing management

  Primarily used for user access to OCP/OceanBase clusters. It is recommended to deploy VIP/DNS addresses when deploying multiple nodes of OCP/OBProxy. If not configured, the system will default to the first IP address for the connection string.

## Prerequisites

Before you start, make sure that you meet the following conditions:

* You have installed obd V2.4.0 or later. We recommend that you install the latest version. For more information, see [Install obd](../../200.quick-start/100.install-obd.md).

* If you deploy OceanBase Database as MetaDB, make sure that the server supports the AVX instruction set (only x86 servers are subject to this restriction). Run the `lscpu | grep Flags | grep avx` command to check whether the server supports the AVX instruction set.

* If you deploy OceanBase Database as MetaDB in an offline deployment scenario and deploy it on an ARM server, make sure that the server supports the LSE instruction set. Run the `lscpu | grep Flags | grep atomics` command to check whether the server supports the LSE instruction set. If the server does not support the LSE instruction set, download the OceanBase Database installation package with the `nonlse` parameter and use the `obd mirror clone` command to upload the installation package to the local image library of obd.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>The OceanBase All in One package does not contain the OceanBase Database installation package with the <code>nonlse</code> parameter. </p>
  </main>

* The user and server resources for deploying OCP meet the requirements. For more information, see the [Installation Planning](https://www.oceanbase.com/docs/common-ocp-1000000002078408) section in the OceanBase Cloud documentation.

* The clockdiff command is installed on the server where you want to deploy OCP.

* The version of MetaDB must be V4.2.1 BP8 or V4.3.5 BP3. If you deploy OCP by using a new OceanBase Database cluster, make sure that the image library of obd contains the OceanBase Database software package of V4.2.1 BP8 or V4.3.5 BP3. We recommend that you use OceanBase Database V4.2.1 BP8 or V4.3.5 BP3 as MetaDB.

## Procedure

### Step 1: Obtain the installation package

1. Download the installation package

   Visit the [OceanBase Download Center](https://en.oceanbase.com/softwarecenter) and search for **OceanBase Cloud**. Download the required installation package based on your needs and upload it to any directory on the obd control machine.

   If you cannot find the required version of the installation package on the download center, contact technical support for assistance.

2. Decompress the installation package

   In the directory where the installation package is located, execute the following command to decompress it:

   ```shell
   [admin@test001 ~]$ tar -xzf ocp-all-in-one-*.tar.gz
   ```

3. (Optional) Uninstall the original obd

   If the obd is installed using the All in One package, you can execute the following command to uninstall the current obd:

   ```shell
   [admin@test001 ~]$ cd ocp-all-in-one/bin && bash uninstall.sh
   ```

4. Start the installation program

   In the `bin` directory of the ocp-all-in-one installation directory, execute the `install.sh` script to start the obd installation program.

   ```shell
   [admin@test001 bin]$ bash install.sh
   ```

   This script installs obd and copies all installation packages in the `rpms` directory of the installation directory to the local image library of obd, while closing the remote image library. After the execution is successful, the following output will be displayed. You can copy and execute the `source ~/.oceanbase-all-in-one/bin/env.sh` command in the output to apply the environment configuration.

   ```shell
   add auto set env logic to profile: /home/admin/.bash_profile
   #########################################################################################
    Install Finished
   =========================================================================================
   Setup Environment:              source ~/.oceanbase-all-in-one/bin/env.sh
   Quick Start:                    obd demo
   Use Web Service to install:     obd web
   Use Web Service to upgrade:     obd web upgrade
   More Details:                   obd -h
   =========================================================================================
   ```

### Step 2: Start the GUI

1. Execute the `obd web` command to start the GUI. Click the displayed address to access the graphical operation interface of obd.

   ```shell
   [admin@test001 ~]$ obd web
   start OBD WEB in 0.0.0.0:8680
   please open http://10.10.10.1:8680
   ```

     <h4>Note</h4>
     <ul>

     </li>
     <li>
     <p>In Alibaba Cloud or other cloud environments, the program may not be able to obtain the public IP address, and the internal IP address will be displayed. You need to use the correct address to access the GUI.</p>
     </li>
     <li>
     <p>The <code>obd web</code> command is bound to 0.0.0.0. In a multi-network card deployment, you can access the GUI through any accessible IP address.</p>
     </li>
     <li>
     <p>You can use the nohup or screen command to set the <code>obd web</code> command to run in the background.</p>
     </li>
     </ul>

2. (Optional) Place the cursor on the **Chinese** character in the upper right corner of the graphical operation interface and click to switch between Chinese and English interfaces based on the displayed language.

   <img width="677" height="419.5" src="https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V2.4.0/zh-CN/200.quick-start/300.deploy-ocp-by-ui-12.png" alt="Language switch">

Place the cursor on the **<UI-TERM key="ocp-v2.Component.InstallService.Mounting">Install</UI-TERM>** button and select the corresponding installation method based on the display to enter the **Welcome to OCP Deployment Wizard** interface.

For more details, see [Deploy OCP by using the GUI](https://www.oceanbase.com/docs/common-ocp-1000000004276697) in the 《OCP Cloud Platform》.

You can configure the information of the MetaDB cluster, such as the IP address, port, directory, and password of the OBServer node, on the **<UI-TERM key="ocp-v2.Binlog.New.MetadbConfiguration">MetaDB Configuration</UI-TERM>** page. This section will introduce the configurations in detail.

   The **Deploy User Configuration** module is used to configure the user information for deploying OCP. The following figure shows the interface.

   ![User configuration](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/2.10.1/zh-CN/400.user-guide/300.deploy-ocp-by-ui-03.png)

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <p>To avoid conflicts of operating system users, we recommend that you configure independent operating system users for MetaDB and OCP. </p>

   | Parameter | Description |
   |--------|----------|
   | Username | The username of the operating system user for installing the software. The username can be customized. The username can contain only letters, digits, and periods, and its length must be no more than 20 characters. Make sure that the username exists on all hosts and has the permission to execute sudo without a password.  |
   | Password (Optional) | The password of the username. If the user has been configured to execute sudo without a password, you can skip this parameter. |
   | SSH Port | The default port is 22. You can customize the port. |
   | Use Running User | If you enable this option, the **Running Username** field appears, in which you can configure an independent operating system user for OCP. |

If you do not configure this parameter, the system will use the first IP address to set up the connection string. You can select whether to use a VIP or a DNS (domain name) for access from the drop-down list under <b>Access Method</b>:<ul><li>If you select to use a VIP, you need to configure the <b>IP Address</b> and <b>Access Port</b> of the VIP.</li><li>If you select to use a DNS, you need to configure the corresponding <b>Domain Name</b>.</li></ul><main id="notice" type='notice'><h4>Notice</h4><p>obd does not provide load balancing deployment. ### Step 6: View the configuration

You can view all the configuration information on the **Configuration Confirmation** page. If you find any issues, you can click **<UI-TERM key="ocp-v2.Cluster.Import.PreviousStep">Previous</UI-TERM>** to modify them. After confirming that the configurations are correct, click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>** to perform the **<UI-TERM key="ocp-v2.Detail.TakeOver.Precheck">Precheck</UI-TERM>**. The system will verify whether your environment and configurations meet all the requirements for deploying OCP.

### Step 7: Perform the precheck

The **<UI-TERM key="ocp-v2.Detail.TakeOver.Precheck">Precheck</UI-TERM>** page displays the system check results. If the precheck fails, you can select **<UI-TERM key="ocp-v2.page.Host.AutomaticRepair.1">Auto Repair</UI-TERM>** for issues that can be automatically repaired, or click **View More Solutions** to jump to the error code documentation and modify the configurations as needed. After all errors are resolved, you can click **<UI-TERM key="ocp-v2.Cluster.Import.ReCheck">Recheck</UI-TERM>** to perform the precheck again.

![Precheck](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/300.deploy-ocp-by-ui-09.png)

After the precheck is successful, click **<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step1.NextStep">Next</UI-TERM>** to proceed to the **Deployment** page and start the OCP deployment.

### Step 8: Deploy

During the deployment, the **Deployment** page will display the deployment logs. You can view the detailed installation logs in the **Deployment Logs** section.

* If the deployment fails, please check the log information to identify the cause of the failure and contact technical support for assistance, or post your question in the [Q&A section](https://ask.oceanbase.com/) on the official website. Once the cause of the installation failure is identified and the issue is resolved, click **Redeploy**. In the confirmation window that appears, click **<UI-TERM key="ocp-v2.Plan.Component.PlanTemplateTable.Confirm">OK</UI-TERM>**. The system will then clean up the failed OCP installation environment and re-execute the installation program.

* If the deployment is successful, you can click **Copy Information** to copy and save the OCP access address and account information. Then, click **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">Complete</UI-TERM>** to exit the deployment program.
