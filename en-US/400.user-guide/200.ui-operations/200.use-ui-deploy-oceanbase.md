# Deploy an OceanBase cluster

This topic describes how to deploy an OceanBase cluster by using the obd graphical interface in a CentOS Linux 7.9 environment based on the x86 architecture.

## Background information

obd supports GUI deployment of OceanBase Database and related components, such as OBAgent and ODP, since V2.0.0. You can deploy a single cluster by following the configuration guidance on the GUI.

## Terms

* OceanBase Database

  OceanBase Database is an enterprise-level, self-developed, native distributed database. For more information, see [OceanBase Database documentation](https://www.oceanbase.com/docs/oceanbase-database-cn).

* OceanBase Database Proxy (ODP)

  OceanBase Database Proxy (ODP) is a dedicated proxy server for OceanBase Database, also known as OBProxy. For more information, see [OceanBase Database Proxy documentation](https://www.oceanbase.com/docs/odp-doc-cn).

* OBAgent

  OBAgent is a monitoring and data collection framework for OceanBase Database. It supports both push and pull data collection modes to meet different application scenarios.

* OceanBase Configserver (obconfigserver)

  OceanBase Configserver (obconfigserver) provides metadata registration, storage, and query services for OceanBase Database. For more information, see [ob-configserver](https://github.com/oceanbase/ob-configserver/tree/main).

* Grafana

  Grafana is an open-source data visualization tool that visualizes various metrics from data sources to help you understand the system's operational status and performance metrics. For more information, see [Grafana official website](https://grafana.com/).

* Prometheus

  Prometheus is an open-source service monitoring system and time-series database. It provides a general data model and fast data collection, storage, and query interfaces. For more information, see [Prometheus official website](https://prometheus.io/).

* Alertmanager

  Alertmanager is an open-source alert management system that processes alerts from monitoring systems such as Prometheus and provides deduplication, grouping, routing, and muting features. For more information, see [Prometheus official website](https://prometheus.io/).

## Prerequisites

Before you start, make sure that the following conditions are met:

* Your server meets the software and hardware requirements. For more information, see [Software and hardware requirements](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002013498) in the OceanBase Database documentation.

* To deploy only OceanBase Database, you need at least 2 vCPUs, 6 GB of memory, and 20 GB of disk space. Note that the memory limit refers to the value of the `available` column in the output of the `free -g` command.

* To deploy OceanBase Database and all components, you need at least 4 vCPUs, 10 GB of memory, and 25 GB of disk space. We recommend that you use 16 GB or more of memory. Note that the memory limit refers to the value of the `available` column in the output of the `free -g` command.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>When the number of CPU cores is small, the minimum CPU_Count value set by default by obd is 8. A low CPU core count will negatively impact the performance of OceanBase Database. </p>
</main>

## Prepare the software

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This section describes how to obtain the Community Edition installation package of OceanBase Database. If you plan to deploy the Enterprise Edition, contact Technical Support to obtain the installation package and execute the <code>obd mirror clone</code> command to upload the installation package to the local image library of obd. </p>
</main>

When you use obd to deploy OceanBase Database, you can choose to deploy it online or offline.

* Online deployment: The machine where obd is installed must have access to the external network. No installation package is required for deployment. During deployment, obd will automatically download the required installation package from the remote image repository.

* Offline deployment: No external network access is required during deployment. You must upload the required installation package to the local image library of obd in advance. We recommend that you directly download the all-in-one installation package of the required version when you choose offline deployment.

Different deployment methods require different software preparation methods. You can choose a suitable method based on your actual situation.

### Online deployment

When you choose online deployment, you can install obd on the control node by using the commands in this section.

```shell
[admin@test001 ~]$ sudo yum install -y yum-utils
[admin@test001 ~]$ sudo yum-config-manager --add-repo https://mirrors.aliyun.com/oceanbase/OceanBase.repo
[admin@test001 ~]$ sudo yum install -y ob-deploy
[admin@test001 ~]$ source /etc/profile.d/obd.sh
```

### Offline deployment

When you choose offline deployment, you can download and install the all-in-one installation package by using the commands in this section.

You can download the latest all-in-one installation package from the [OceanBase Database Download Center](https://en.oceanbase.com/softwarecenter) and copy it to the control node. Run the following commands to decompress and install the package:

```shell
[admin@test001 ~]$ tar -xzf oceanbase-all-in-one-*.tar.gz
[admin@test001 ~]$ cd oceanbase-all-in-one/bin/
[admin@test001 bin]$ ./install.sh
[admin@test001 bin]$ source ~/.oceanbase-all-in-one/bin/env.sh
```

### Step 1: Start the GUI

1. Start the GUI

   Run the `obd web` command in the command-line interface to start the GUI. Click the displayed address to access the GUI.

   ```shell
   [admin@test001 ~]$ obd web
   start OBD WEB in 0.0.0.0:8680
   please open http://10.10.10.1:8680
   ```

     </li>

### Step 5: Review configuration

You can view all configuration information on the **Review Configuration** page. If you find any problems, you can click **<UI-TERM key="ocp-v2.Credential.Component.ImportModal.PreviousStep">Previous</UI-TERM>** to make changes. The system will validate whether your environment and configuration meet all the requirements for deploying an OceanBase cluster.

When you select **<UI-TERM key="ocp-v2.Cluster.New.DeploymentMode">Deployment Mode</UI-TERM>** as **Distributed** and configure at least 2 zones, the **Review Configuration** page will display the cluster topology diagram. You can click **<UI-TERM key="ocp-v2.src.util.menu.TopologicalGraph">Topology</UI-TERM>** to view the diagram.

### Step 6: Precheck

The **<UI-TERM key="ocp-v2.Detail.TakeOver.Precheck">Precheck</UI-TERM>** page displays the check results. If a precheck fails, you can choose **<UI-TERM key="ocp-v2.page.Host.AutomaticRepair.1">Auto Repair</UI-TERM>** for checks that can be automatically fixed or click **View More Schemes** to jump to the error code documentation to modify them manually. After all errors are resolved, you can click **<UI-TERM key="ocp-v2.Detail.TakeOver.ReCheck">Recheck</UI-TERM>** to re-precheck.

![Precheck](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/200.use-ui-deploy-oceanbase-06.png)

If the precheck is successful, you can click **Deploy** to start deploying the OceanBase cluster.

### Step 7: Deployment

![Deployment](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.0.0/zh-CN/200.use-ui-deploy-oceanbase-06.png)

Here's what you can do:

* After the deployment is successful, you can copy the displayed connection strings to connect to the corresponding components. In a command-line interface, you can log in to the OceanBase cluster as the root@sys user after executing the connection string for the OceanBase Database component, and you can log in to the ODP as the root@proxysys user after executing the connection string for the OBProxy component.

* You can click the connection strings of the Prometheus, Grafana, AlertManager, and obshell Dashboard components to jump to the login pages of these components. You can log in by using the account and password displayed on the deployment page.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>If your program cannot obtain a public IP address in Alibaba Cloud or another cloud environment, it will output an intranet IP address. This IP address is not a public IP address, so you must use the correct IP address to access the graphical interface.</p>
  </main>

* You can expand the icons before the names of the components in **Deployment Report** to view the deployment log. You can click **Details** in the list of the component. ## Related operations

### Manage a cluster after deployment

You can run the following commands to manage the cluster deployed by using obd. For more information, see [Cluster commands](../../300.obd-command/100.cluster-command-groups.md).

```shell
# View the list of clusters.
[admin@test001 ~]$ obd cluster list

# View the status of the cluster named myoceanbase.
[admin@test001 ~]$ obd cluster display myoceanbase

# Stop the cluster named myoceanbase.
[admin@test001 ~]$ obd cluster stop myoceanbase

# Destroy the cluster named myoceanbase.
[admin@test001 ~]$ obd cluster destroy myoceanbase
```

### Deploy components of a specific version

If you deploy components by using the all-in-one installation package, the package is iterated based on the version of OceanBase Database. If other components in the package have newer versions, you can download the latest versions of these components from [OceanBase Download Center](https://en.oceanbase.com/softwarecenter), upload them to the local image repository, and obd automatically retrieves the latest versions from the local image repository during deployment.

1. Go to the directory where the component installation package is stored and add the installation package to the local image repository.

   ```shell
   [admin@test001 rpm]$ obd mirror clone *.rpm
   ```

2. View the list of installation packages in the local image repository.

   ```shell
   [admin@test001 rpm]$ obd mirror list local
   ```
