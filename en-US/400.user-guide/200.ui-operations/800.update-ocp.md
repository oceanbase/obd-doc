# Upgrade OCP

This topic describes how to upgrade OCP by using the graphical interface of obd.

## Prerequisites

Before you start, make sure that the version of OCP to be upgraded is V4.0.3 or later.

## Considerations

When you upgrade OCP deployed in Docker containers, take note of the following:

* Make sure that all OCP containers are in normal operation. If multiple OCP containers are available, start only one of the containers and stop the others.

* The name of the OCP container in a running state must contain the `ocp-all-in-one` field. If the field is not included, you need to rename the container.

* If OCP was deployed in a multi-node configuration in Docker, you must perform a scaling-out operation to retain the multi-node configuration after the upgrade. For more information, see [Step 3: Scale out OCP](#（optional）step-3-scale-out-ocp).

## Procedure

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>OBOD supports upgrading OCP Enterprise Edition and OCP Community Edition. This topic describes how to upgrade OCP Community Edition. </p>
</main>

### Step 1: Obtain the installation package for upgrade

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>If the OCP to be upgraded is deployed as a Docker container, you must download and install the ocp-all-in-one package into the OCP container in the running state.</p>
</main>

1. Download the installation package

   Go to the [OceanBase Download Center](https://en.oceanbase.com/softwarecenter) and search for **OceanBase Cloud Platform**. Download the required installation package based on your actual situation and upload it to any directory on the obd control machine.

   If you cannot obtain the required version of the installation package from the download center, contact Technical Support for assistance.

2. Decompress the installation package

   In the directory where the installation package is located, execute the following command to decompress it:

   ```shell
   [admin@test001 ~]$ tar -xzf ocp-all-in-one-*.tar.gz
   ```

3. (Optional) Uninstall the original obd

   If the obd is installed using the All in One package, you can execute the following command to uninstall the current obd.

   ```shell
   [admin@test001 ~]$ cd ocp-all-in-one/bin && bash uninstall.sh
   ```

4. Start the installation program

   In the `bin` directory of the ocp-all-in-one installation directory, execute the `install.sh` script to start the obd installation program.

   ```shell
   [admin@test001 bin]$ bash install.sh
   ```

   This script installs obd and copies all installation packages in the `rpms` directory of the installation directory to the local image library of obd, while closing the remote image library. After the execution is successful, the following output is displayed. You can copy and execute the `source ~/.oceanbase-all-in-one/bin/env.sh` command in the output to apply the environment configuration.

   ```shell
   add auto set env logic to profile: /home/admin/.bash_profile

   #########################################################################################
    Install Finished
   =========================================================================================
   Setup Environment:              source ~/.oceanbase-all-in-one/bin/env.sh
   Quick Start:                    obd demo
   Use Web Service to install:     obd web
   Use Web Service to upgrade:     obd web upgrade
   More Details:                   obd -h
   =========================================================================================
   ```

### Step 2: Upgrade OCP

1. Start the upgrade.

   ```shell
   [admin@test001 ~]$ obd web upgrade
   ```

   The following information is displayed. You can access the upgrade wizard by accessing the IP address in your browser and click **Start Upgrade**.

   ```shell
   start OBD WEB in 0.0.0.0:8680
   please open http://10.10.10.1:8680/#/updateWelcome
   ```

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <ul>
     <li>
     <p>The blank screen interface uses port 8680 by default. You can run the <code>obd web upgrade -p &lt;PORT&gt;</code> command to specify a port, which is within the range of [1025, 65535].</p>
     </li>
     <li>
     <p>In Aliyun or other cloud environments, the application might fail to obtain a public IP address, resulting in the use of an internal IP address. This IP is not a public IP address, so you must use the correct address to access the graphical interface.</p>
     </li>
     <li>
     <p>The <code>obd web</code> command binds to 0.0.0.0. In a multi-interface deployment, you can use any accessible IP address to access the Web interface. </p>
     </li>
     </ul>
   </main>

2. Select an upgrade product.

   On the **Welcome to OceanBase Upgrader** page, choose the **OceanBase Cloud** module and click **<UI-TERM key="ocp-v2.Arbitration.ArbitrationGroup.UpgradeArbitrationGroup.Upgrade">Upgrade</UI-TERM>**. This starts the upgrade of OceanBase Cloud.

3. Deploy the configuration file.

   On the Deploy page, select the OCP cluster to be upgraded and its target version. The system will automatically retrieve the names of all clusters managed by OBLOADER. You can select the required cluster from the **Deployment Name** drop-down list. If the cluster you want to upgrade has not been managed by OBLOADER (for example, a cluster deployed by using Docker), you can enter the name of the cluster here. After the cluster is upgraded, OBLOADER will automatically manage the OCP cluster.

   ![deploy](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/800.update-ocp-06.png)

   After the settings are completed, you can click **<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step1.NextStep">Next</UI-TERM>** to go to the **Connectivity Test** page.

4. Verify the MetaDB connectivity.

   When you upgrade OCP that is deployed with Docker, you must manually enter the MetaDB configuration information. If the OCP to be upgraded is managed by obd, the current page automatically retrieves the MetaDB configuration information. You must check whether the information in the **Connection** section is consistent with the expected environment before the upgrade. After confirming that the MetaDB connection information is correct, enter the **Access Password** and click **<UI-TERM key="ocp-v2.page.Credential.Cluster.Verification">Verify</UI-TERM>**. The system verifies whether MetaDB can be connected.

   ![metadb](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V3.2.0/zh-CN/200.ui-operations/800.update-ocp-07.png)

5. Configure an operating system user.

   After validating the MetaDB connectivity, you need to fill in the operating system user to facilitate automated configuration by the installer.

   ![user](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V3.2.0/zh-CN/200.ui-operations/800.update-ocp-08.png)

### (Optional) Step 3: Scale out OCP

1. Prepare the configuration file for scaling out OCP.

   ```shell
   [admin@test001 ~]$ vim ocp-scale-out.yaml
   ```

   The content of the file is as follows. The servers.name configuration cannot be repeated in the original OCP cluster:

   ```yaml
   ocp-server-ce:
     servers:
       - name: server2
         ip: 10.10.10.2
       - name: server3
         ip: 10.10.10.3
     server2:
       home_path: /home/admin/ocp
       soft_dir: /home/admin/ocp/software
       log_dir: /home/admin/ocp/logs
       port: 8080
       memory_size: 8G
     server3:
       home_path: /home/admin/ocp
       soft_dir: /home/admin/ocp/software
       log_dir: /home/admin/ocp/logs
       port: 8080
       memory_size: 8G
   ```
