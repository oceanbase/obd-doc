# Upgrade OCP

This topic describes how to upgrade OCP by using the graphical interface of obd.

## Prerequisites

Before you start, make sure that the current OCP version to be upgraded is V4.0.3 or later.

## Considerations

When you upgrade OCP deployed in a Docker container, you must take note of the following:

* Make sure that all OCP containers are in a normal state. If there are multiple OCP containers, keep only one container running and stop the others.

* A started OCP container should have the `ocp-all-in-one` field in its name. If it does not, rename the container.

* If OCP was originally deployed on multiple nodes using Docker, you need to expand OCP after the upgrade. For details, see **Step 3: Scale out OCP**.

## Procedure

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>OBLOADER supports upgrading OCP Enterprise Edition and OCP Community Edition. This topic describes how to upgrade OCP Community Edition. </p>
</main>

### Step 1: Download the installation package

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>If the OCP to be upgraded is deployed as a Docker container, you need to download and install the ocp-all-in-one package into the running OCP container.</p>
</main>

1. Download the installation package

   Go to [OceanBase Download Center](https://en.oceanbase.com/softwarecenter), search for **OceanBase Cloud Platform**, download the required installation package based on your actual situation, and upload the installation package to any directory on the OBDA control machine.

   If you cannot obtain the required version of the installation package from the download center, contact technical support for assistance.

2. Decompress the installation package

   In the directory where the installation package is located, execute the following command to decompress it:

   ```shell
   [admin@test001 ~]$ tar -xzf ocp-all-in-one-*.tar.gz
   ```

3. (Optional) Uninstall the original obd

   If the obd is installed using the All in One package, you can execute the following command to uninstall the current obd.

   ```shell
   [admin@test001 ~]$ cd ocp-all-in-one/bin && bash uninstall.sh
   ```

4. Start the installation program

   In the `bin` directory of the ocp-all-in-one installation directory, execute the `install.sh` script to start the obd installation program.

   ```shell
   [admin@test001 bin]$ bash install.sh
   ```

   This script installs obd and copies all installation packages in the `rpms` directory of the installation directory to the local image library of obd, while closing the remote image library. After the execution is successful, the following output will be displayed. You can copy and execute the `source ~/.oceanbase-all-in-one/bin/env.sh` command in the output to apply the environment configuration.

   ```shell
   add auto set env logic to profile: /home/admin/.bash_profile

   #########################################################################################
    Install Finished
   =========================================================================================
   Setup Environment:              source ~/.oceanbase-all-in-one/bin/env.sh
   Quick Start:                    obd demo
   Use Web Service to install:     obd web
   Use Web Service to upgrade:     obd web upgrade
   More Details:                   obd -h
   =========================================================================================
   ```

### Step 2: Upgrade the OCP cluster

1. Start the upgrade

   ```shell
   [admin@test001 ~]$ obd web upgrade
   ```

   The output appears as follows. Access the IP address from the output in a browser to go to the Upgrade Wizard page, and then click **Start Upgrade**.

   ```shell
   start OBD WEB in 0.0.0.0:8680
   please open http://10.10.10.1:8680/#/updateWelcome
   ```

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <ul>
     <li>
     <p>The default port of the Web UI is 8680. Run the <code>obd web upgrade -p &lt;PORT&gt;</code> command to specify the port of the Web UI, where the value of <code>PORT</code> is in the range of [1025, 65535].</p>
     </li>
     <li>
     <p>In an Alibaba Cloud or other cloud environment, the system may output an intranet IP address if the public IP address cannot be obtained. You need to use the correct public IP address to access the web interface. </p>
     </li>
     <li>
     <p>The <code>obd web</code> command is bound to 0.0.0.0, which allows access to the GUI interface from any accessible IP address in a multi-adapter deployment.</p>
     </li>
     </ul>
   </main>

2. Select the product to upgrade.

   Select the **OceanBase Cloud Platform** module on the displayed **Welcome to OceanBase Upgrade Wizard** page and click **<UI-TERM key="ocp-v2.Arbitration.ArbitrationGroup.UpgradeArbitrationGroup.Upgrade">Upgrade</UI-TERM>**. This way, you can start to upgrade OCP.

3. Deployment Configuration

   On the deployment configuration page, select the OCP cluster to be upgraded and the target version. The system automatically retrieves all cluster names managed by the OBDS service. From the **Deployment Name** drop-down list, select the cluster you want to upgrade. If the cluster to be upgraded is not currently managed by the OBDS service, for example, a Docker-deployed cluster, you can customize the cluster name. After the cluster is upgraded, the OBDS service will automatically take over the OCP cluster.

   <!-- ![deploy](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/800.update-ocp-06.png) -->

   After the settings are complete, click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>** to go to the **Connectivity Test** page.

4. Validate connectivity with MetaDB

   When you upgrade an OCP cluster deployed by using Docker, you need to manually specify MetaDB parameters. If the OCP cluster to be upgraded is managed by obd, the system automatically retrieves MetaDB parameters. Verify whether the information in **Connection Information** is consistent with the expected parameters of the destination environment. After verifying that the MetaDB connection information is correct, enter **Access Password** and click **<UI-TERM key="ocp-v2.page.Credential.OBProxy.Verification">Verify</UI-TERM>**. The system verifies whether MetaDB can be connected.

   <!-- ![metadb](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V3.2.0/zh-CN/200.ui-operations/800.update-ocp-07.png) -->

5. Configure the operating system user

   After you verify the MetaDB connectivity, you need to specify an operating system user for automated configuration.

   <!-- ![user](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V3.2.0/zh-CN/200.ui-operations/800.update-ocp-08.png) -->

   | Parameter | Description |
   |-------|-------|
   | User Name | The user that is provided must have sudo privileges for the host operating system to allow the installation process to perform automated configuration. |
   | SSH port | The default port is 22, but you can use a custom port number. |
   | Password  | Enter the password of **<UI-TERM key="ocp-v2.Cluster.Component.OBProxyClusterAndUserSelect.UserName">Username</UI-TERM>**. You can skip this option if no password is required for the host. After you configure this option, click **<UI-TERM key="ocp-v2.src.constant.external.Validation">Verify</UI-TERM>** to test the connectivity.  |

   After the configuration is completed, click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>** to proceed to the **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.EnvironmentPreCheck">Environment Pre-check</UI-TERM>** page.

6. Configuration confirmation

   OCP will obtain related configurations from the MetaDB configurations and update the platform management service (COP Server) and all host agent services (OCP Agent) managed by the platform management service to ensure the consistency of the management features.

   Confirm whether the upgrade contents specified in the **Installation and Configuration** and **Upgrade Configuration Information** fields meet the expected requirements. You can click **<UI-TERM key="ocp-v2.Component.AddSamplingInspectStrategy.PreviousStep">Previous</UI-TERM>** to modify the upgrade contents if any issues are found. After the contents are verified, click **<UI-TERM key="ocp-v2.Credential.Component.ImportModal.NextStep">Next</UI-TERM>** to start the environment check before the upgrade.

   <!-- ![Configuration Confirmation](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/800.update-ocp-13.png) -->

7. Pre-check environment

   If the checks pass, click **<UI-TERM key="ocp-v2.Detail.TakeOver.Next">Next</UI-TERM>** to proceed with the upgrade of OCP. If any checks fail, the system allows you to either fix or ignore the failed items.

   * If you select **Repair**, after the fix is complete, click **<UI-TERM key="ocp-v2.Detail.TakeOver.ReCheck">Recheck</UI-TERM>**. The system will restart the pre-check process for the environment.

   * If you choose to ignore them, click **Ignore All Failed Checks**. All failed check items will be marked as **Ignored**, and you can click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>** to start the OCP upgrade.

   <main id="notice" type='notice'>
     <h4>Note</h4>
     <p>Ignoring all failed checks could result in an upgrade failure. We recommend that you fix any failed checks before proceeding to the next step.</p>
   </main>

   <!-- ![check](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V3.2.0/zh-CN/200.ui-operations/800.update-ocp-12.png) -->

8. Upgrade OCP

   During the O&M process of an OCP cluster, you can view detailed upgrade logs in the **Upgrade Logs** module.

   * If the OCP upgrade is successful, you can view the login information of OCP, including URL, username, and password, in the **Upgrade Log**.

   * If the OCP upgrade fails, check the log to find out the reason for the failure, and contact technical support. After the failure reasons are located and the issues are fixed, click **Upgrade Again** to re-execute the failed upgrade steps.

   <main id="notice" type='explain'>
     <h4>Notice</h4>
     <p>The OCP upgrade process may take some time. Please be patient.</p>
   </main>

   <!-- ![upgrade](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V3.2.0/zh-CN/200.ui-operations/800.update-ocp-11.png) -->

### (Optional) Step 3: Scale out OCP

1. Prepare the configuration file for scaling out OCP.

   ```shell
   [admin@test001 ~]$ vim ocp-scale-out.yaml
   ```

   The content of the file is as follows. The servers.name configuration cannot be repeated in the original OCP cluster:

   ```yaml
   ocp-server-ce:
     servers:
       - name: server2
         ip: 10.10.10.2
       - name: server3
         ip: 10.10.10.3
     server2:
       home_path: /home/admin/ocp
       soft_dir: /home/admin/ocp/software
       log_dir: /home/admin/ocp/logs
       port: 8080
       memory_size: 8G
     server3:
       home_path: /home/admin/ocp
       soft_dir: /home/admin/ocp/software
       log_dir: /home/admin/ocp/logs
       port: 8080
       memory_size: 8G
   ```

2. Execute the scaling-out command.

   ```shell
   [admin@test001 ~]$ obd cluster scale_out myocp -c ocp-scale-out.yaml
   ```

   If the command is executed successfully, the output is as follows:
