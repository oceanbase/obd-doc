# Upgrade OCP

This topic describes how to upgrade OceanBase Cloud Platform (OCP) by using the graphical interface of OceanBase Deployer (obd).

## Prerequisites

Before you start the upgrade, make sure that you meet the following conditions: 

* The current OCP version to be upgraded is V4.0.3 or later. 

* The OCP node has installed and configured the Java environment. Only JDK 1.8 is supported. For more information, see **How to configure the Java environment** in **Common Issues**.

## Considerations

When you upgrade OCP deployed in a Docker container, note the following considerations:  

* Make sure that all OCP containers are in the normal state. If multiple OCP containers are deployed, only one container needs to be in the running state, and the other containers need to be stopped.  

* The name of the running OCP container must contain the `ocp-all-in-one` field. If the field is not present, you need to rename the container.  

* If the original Docker deployment is for a multi-node OCP, you need to expand the OCP after the upgrade. For more information, see **Step 3: Expand OCP**.

## Procedure

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>OBOD supports upgrading OCP Enterprise Edition and OCP Community Edition. This topic describes how to upgrade OCP Community Edition. </p>
</main>

### Step 1: Obtain the installation package for upgrade

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>If the OCP to be upgraded is deployed as a Docker container, you must download and install the ocp-all-in-one package into the OCP container in the running state.</p>
</main>

1. Download the installation package.

   Go to the [OceanBase Download Center](https://en.oceanbase.com/softwarecenter), search for **OceanBase Cloud Platform**, and download the required installation package based on your actual situation. Upload the installation package to any directory on the OBDA control machine.

   If you cannot obtain the required version of the installation package from the download center, contact Technical Support for assistance.

2. Decompress the installation package.

   In the directory where the installation package is located, run the following command to decompress it:

   ```shell
   [admin@test001 ~]$ tar -xzf ocp-all-in-one-*.tar.gz
   ```

3. (Optional) Uninstall the original obd

   If the obd exists on the machine and was installed using the All in One package, you can run the following command to uninstall it first.

   ```shell
   [admin@test001 ~]$ cd ocp-all-in-one/bin && bash uninstall.sh
   ```

4. Start the installation program

   In the `bin` directory of the ocp-all-in-one installation directory, run the `install.sh` script to start the obd installation program.

   ```shell
   [admin@test001 bin]$ bash install.sh
   ```

   This script installs obd and copies all installation packages in the `rpms` directory of the installation directory to the local image library of obd, while closing the remote image library. After the execution is successful, the output is as follows. You can copy and execute the `source ~/.oceanbase-all-in-one/bin/env.sh` command in the output to apply the environment configuration.

   ```shell
   add auto set env logic to profile: /home/admin/.bash_profile

   #########################################################################################
    Install Finished
   =========================================================================================
   Setup Environment:              source ~/.oceanbase-all-in-one/bin/env.sh
   Quick Start:                    obd demo
   Use Web Service to install:     obd web
   Use Web Service to upgrade:     obd web upgrade
   More Details:                   obd -h
   =========================================================================================
   ```

### Step 2: Upgrade OCP

1. Start the upgrade.

   ```shell
   [admin@test001 ~]$ obd web upgrade
   ```

   The output is as follows, and then you can access the IP address in the output to go to the upgrade wizard page, and click **Start Upgrade**.

   ```shell
   start OBD WEB in 0.0.0.0:8680
   please open http://10.10.10.1:8680/#/updateWelcome
   ```

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <ul>
     <li>
     <p>By default, the blank screen interface uses port 8680. You can use the <code>obd web upgrade -p &lt;PORT&gt;</code> command to specify the port. </p>
     </li>
     <li>
     <p>In an Alibaba Cloud or other cloud environment, it is possible that the public IP address cannot be obtained, resulting in the use of an intranet IP address. This IP address is not a public one, so you must use the correct IP address to access the graphical interface.</p>
     </li>
     <li>
     <p>You can run the <code>obd web</code> command to access the web console, which is bound to 0.0.0.0. When you deploy OceanBase Database across multiple network cards, you can use any accessible IP address to access the web console.</p>
     </li>
     </ul>
   </main>

2. Choose an upgrade product.

   You can click the **<UI-TERM key="ocp-v2.src.constant.obproxy.Upgrade">Upgrade</UI-TERM>** button on the **Welcome to OceanBase Database** page to proceed with the upgrade.

3. Deployment configurations

   On the deployment configuration page, select the OCP cluster to be upgraded and the upgrade target version. The system will automatically display all clusters managed by obd. You can select the cluster to be upgraded from the **Deployment Name** drop-down list. If the cluster to be upgraded is not managed by obd (such as a cluster deployed by using Docker), you can specify the cluster name. After the upgrade is completed, obd will automatically manage the cluster.

   <!-- ![deploy](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/800.update-ocp-06.png) -->

   After you set the options, click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>** to go to the **Connectivity Test** page.

4. Verify MetaDB connectivity.

   When you upgrade OCP in Docker, you must manually enter the MetaDB configuration information. If the OCP to be upgraded is managed by obd, the MetaDB configuration information will be automatically retrieved, and you need to check whether the information in the **Connection Information** section matches the target upgrade environment. After confirming that the MetaDB connection information is correct, enter the **Access Password** and click **<UI-TERM key="ocp-v2.page.Credential.Host.Verification">Verify</UI-TERM>**. The system verifies whether MetaDB can be successfully connected to.

   <!-- ![metadb](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V3.2.0/zh-CN/200.ui-operations/800.update-ocp-07.png) -->

5. Configure an OS user.

   After you verify the connectivity of MetaDB, you need to fill in the operating system user for automatic configuration in the installation program.

   <!-- ![user](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V3.2.0/zh-CN/200.ui-operations/800.update-ocp-08.png) -->

   | Parameter  | Description    |
   |-------|-------|
   | User name | Enter the username of a user on the host operating system. This user must have sudo privileges. |
   | SSH port | The default port is 22, but you can also set a custom port. |
   | Password  | The password corresponding to the **<UI-TERM key="ocp-v2.Alarm.Channel.Detail.Username">Username</UI-TERM>**. If the host is already configured for passwordless connection, this password is not required. After you specify the password, you can click **<UI-TERM key="ocp-v2.page.Credential.Host.Verification">Verify</UI-TERM>** to test the user's connectivity.  |

   After the settings are configured, click **<UI-TERM key="ocp-v2.Credential.Component.ImportModal.NextStep">Next</UI-TERM>** to go to the **Environment Precheck** page.

6. Verify the configuration

   The system acquires OCP-related configuration information based on the configuration information of MetaDB. For consistency of management capabilities, the upgrade program will upgrade the platform management service (COP Server) and all host agent services (OCP Agents) that it manages.

   Confirm that the upgrade content in **Installation Configuration** and **Upgrade Configuration Information** meets your expectations. If issues are found, you can click **<UI-TERM key="ocp-v2.Cluster.Import.PreviousStep">Previous</UI-TERM>** to modify the information. After confirmation, you can click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>** to perform the precheck.

   <!-- ![Configuration confirmation](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.1.0/800.update-ocp-13.png) -->

7. Environment Precheck

   If the check passes, click **<UI-TERM key="ocp-v2.Detail.TakeOver.Next">Next</UI-TERM>** to start upgrading OCP. If the check fails, you can fix or ignore the failed items.

   * If you select to fix the problem, click **<UI-TERM key="ocp-v2.Detail.TakeOver.ReCheck">Recheck</UI-TERM>** after the fix is completed. The system will re-run the environment pre-check.

   * If you choose to ignore the check item, click **Ignore All Failures** to change the check status to **Ignored**. You can then click **<UI-TERM key="ocp-v2.Credential.Component.ImportModal.NextStep">Next</UI-TERM>** to start upgrading OCP.

   <main id="notice" type='notice'>
     <h4>Notice</h4>
     <p>Ignoring all failed checks might result in an upgrade failure. We recommend that you fix the failed checks before proceeding. </p>
   </main>

   <!-- ![check](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V3.2.0/zh-CN/200.ui-operations/800.update-ocp-12.png) -->

8. Upgrade OCP

   During an OCP upgrade, you can view detailed upgrade logs in the **Upgrade Log** module.

   * If the upgrade of OCP is successful, you can view the OCP login information, including URL, username, and password, in **Upgrade Log**.

   * If the OCP upgrade fails, check the log information to identify the cause of the failure. Then contact Huawei Technical Support for assistance. After identifying and fixing the installation failure, click **Upgrade Again** so that the system will retry the failed upgrade step.

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <p>Upgrading OCP may take a while. Please wait a moment. </p>
   </main>

   <!-- ![upgrade](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V3.2.0/zh-CN/200.ui-operations/800.update-ocp-11.png) -->

### (Optional) Step 3: Scale out OCP

1. Prepare the configuration file for the scale-out operation.

   ```shell
   [admin@test001 ~]$ vim ocp-scale-out.yaml
   ```

   The following example shows the content of the file. The servers.name configuration cannot be duplicated with that in the original OCP cluster:

   ```yaml
   ocp-server-ce:
     servers:
       - name: server2
         ip: 10.10.10.2
       - name: server3
         ip: 10.10.10.3
     server2:
       home_path: /home/admin/ocp
       soft_dir: /home/admin/ocp/software
       log_dir: /home/admin/ocp/logs
       port: 8080
       memory_size: 8G
     server3:
       home_path: /home/admin/ocp
       soft_dir: /home/admin/ocp/software
       log_dir: /home/admin/ocp/logs
       port: 8080
       memory_size: 8G
   ```

2. Execute the scale-out operation.

   ```shell
   [admin@test001 ~]$ obd cluster scale_out myocp -c ocp-scale-out.yaml
   ```

   If the command is executed successfully, the output is as follows:

