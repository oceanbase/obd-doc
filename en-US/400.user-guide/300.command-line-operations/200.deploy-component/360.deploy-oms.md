# Deploy OMS

This topic introduces how to deploy OceanBase Migration Service (OMS) by using the obd profile in the CentOS Linux 7.9 image based on the x86 architecture.

<main id="notice" type='explain'>
  <h4>Description</h4>
  <p>Currently, OBD can only manage OMS Community Edition V4.2.11 and later versions.</p>
</main>

## Prerequisites

Before you begin, make sure that you meet the following prerequisites:

* You have installed obd V4.0.0 or later. We recommend that you install the latest version. For more information, see [Install obd](../../../200.quick-start/100.install-obd.md).

* The machine where the OMS is to be deployed meets the deployment requirements.

* The Docker runtime environment is installed on the OMS server.

* If you want OMS to collect and display monitoring data, you must deploy and configure a time series database. Currently, the only supported time series database is InfluxDB V1.8.

* If you plan to deploy OMS separately, make sure to prepare a database to store metadata of the OMS Community Edition. The database can be MySQL or OceanBase Database, and it is recommended to use OceanBase Database Community Edition.

  <main id="notice" type='explain'>
    <h4>Remarks</h4>
    <p>To enhance system reliability, we recommend implementing a highly available database solution for MetaDB. This approach ensures stable 7x24 hours operation for OMS core services and minimizes the risk of business disruptions.
  </main>

* If OceanBase Database is deployed as MetaDB, make sure that the OBServer nodes support the AVX instruction set (only applicable to servers with the x86 architecture). You can run the `lscpu | grep Flags | grep avx` command to check.

  <main id="notice" type='explain'>
    <h4>Notes</h4>
    <p>When you use an x86-64 architecture server, the server does not need to support the AVX instruction set provided that the major version of OceanBase Database to be deployed is v2.2.21 or later. </p>
    <ul>
    <li>For V4.2.x versions, it is required to use V4.2.5.6 or later.
    <li>For V4.3.x, V4.3.5.4 or later is required.</li>
    <li>For V4.4.x version, V4.4.1.0 or later must be provided.</li>
    </ul>
  </main>

* If OceanBase Database is deployed on a server with an ARM architecture in an offline deployment scenario, check whether the underlying hardware of the OBServer nodes supports the LSE instruction set. You can run the `lscpu | grep Flags | grep atomics` command to check whether the underlying hardware of the nodes support the LSE instruction set. If the underlying hardware does not support the LSE instruction set, you must download the OceanBase Database installation package that contains the `nonlse` parameter. Then, you can use the `obd mirror clone` command to upload the installation package to the local image library of obd.

  <main id="notice" type='explain'>
    <h4>Remarks</h4>
    <p>OceanBase All in One does not contain OceanBase Database packages with the <code>nonlse</code> option. </p>
  </main>

* While deploying an OceanBase cluster as the MetaDB at the same time, ensure that the necessary component installation packages (such as OceanBase Database) are present in the obd image library.

  If the server where you run `obd` can connect to the Internet, the community edition components will be automatically downloaded from the remote image repository. If it cannot, download all the installation packages from [OceanBase Database Download Center](https://en.oceanbase.com/softwarecenter) and upload them to the local image repository of `obd` by executing the `obd mirror clone` command. You can run the `obd mirror list local` command to view the installation packages in the local image repository.

## Considerations

The HA feature is disabled by default in the OceanBase Migration Community Edition. To enable the HA feature, set the value of `enable` in the `ha.config` parameter to `true` in the OMS console after the service is deployed.

## Procedure

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Operations guidance in this article are based on a CentOS Linux 7.9 image for an x86 architecture.</p>
</main>

Tab separately deploy OMS

### Step 1: Install OMS Community Edition

<main id="notice" type='explain'>
  <h4>Notes</h4>
  <p>If you plan to deploy a multi-node OMS, each node needs to follow the procedure below. </p>
</main>

1. Obtain the OMS installation package.

   You can download the Community Edition installation package of OMS from the [OceanBase download center](https://en.oceanbase.com/softwarecenter), which is usually a `tar.gz` file starting with `oms`, such as `oms_4.2.11-ce.tar.gz`.

2. Load the downloaded OMS installation package into the local image registry of the Docker container.

   ```shell
   [admin@test ~]$ sudo docker load -i oms_4.2.11-ce.tar.gz
   ```

3. Confirm the load succeeds.

   ```shell
   [admin@test ~]$ sudo docker images
   ```

   Output is as follows:

   ```shell
   REPOSITORY                                    TAG                 IMAGE ID       CREATED      SIZE
   reg.docker.alibaba-inc.com/oceanbase/oms-ce   feature_4.2.11_ce   26f5f1554fc5   2 days ago   12.5GB
   ```

### Step 2: Modify the configuration file

1. Create a configuration file

   Run the following commands to create a configuration file. Here is an example named `oms-only-config.yaml`, which you can customize.

   ```shell
   [admin@test ~]$ vim oms-only-config.yaml
   ```

2. Modify user information

   You can copy the following code and modify it based on your scenario.

   ```yaml
   ## Only need to configure when remote login is required
   user:
     username: admin
   #   password: your password if need
     key_file: /home/admin/.ssh/id_rsa
   #   port: your ssh port, default 22
   #   timeout: ssh connection timeout (second), default 30
   ```

   `username` is the username used to log in to the target host, and you must ensure that this username has write permissions for its home directory. `password` and `key_file` are both user verification options. Usually, you only need to specify one of them.

   <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>After you specify the secret key path, if your secret key does not require a password, comment or delete <code>password</code> to prevent it from being considered a secret key password for login, which can cause validation failures.</p>
   </main>

3. Modify OMS configurations

   You can copy the following sample content and then modify it based on your actual scenario. For more information about the configuration parameters, see **Parameter Description** in [Configuration File Description](../100.configuration-file-description.md).

   ```yaml
   oms:
     type: docker
     tag: feature_4.2.11_ce
     image_name: reg.docker.alibaba-inc.com/oceanbase/oms-ce
     servers:
       - name: server1
         ip: 10.10.10.1
       - name: server2
         ip: 10.10.10.2
       - name: server3
         ip: 10.10.10.3
     global:
       oms_meta_host: "10.10.10.1" # OMS meta database host address
       oms_meta_password: "******" # Password for OMS meta database user
       oms_meta_port: 2881 # Port number for OMS meta database connection
       oms_meta_user: root # Username for OMS meta database connection
       mount_path: /data/1/oms # Mount path for OMS data storage
       ghana_server_port: 8090 # Port for ghana server
       nginx_server_port: 8089 # Port for nginx server
       cm_server_port: 8088 # Port for cluster manager server
       # tsdb_enabled: "true"
       # tsdb_password: ""
       # tsdb_service: "INFLUXDB"
       # tsdb_url: "10.10.10.1:8086"
       # tsdb_username: "admin"
       regions:
         - cm_location: 1
           cm_is_default: true
           cm_region: hz
           cm_url: http://10.10.10.1:8088
           cm_nodes:
             - 10.10.10.1
             - 10.10.10.3
         - cm_location: 2
           cm_is_default: false
           cm_region: bj
           cm_url: http://10.10.10.2:8088
           cm_nodes:
             - 10.10.10.2
   ```

### Step 3: Deploy OMS

1. Deploy OMS

   ```shell
   [admin@test ~]$ obd cluster deploy oms -c oms-only-config.yaml
   ```

   `oms` in the command specifies the name of the cluster. You can customize the name of the cluster as needed. After the deployment is completed, the command line will output a command similar to the following:

   ```shell
   Open ssh connection ok
   +---------------------------------------------------------+
   |                         Packages                        |
   +------------+-------------------+---------+--------------+
   | Repository | Tag               | Release | Hash         |
   +------------+-------------------+---------+--------------+
   | oms        | feature_4.2.11_ce | -       | 26f5f1554fc5 |
   +------------+-------------------+---------+--------------+
   Repository integrity check ok
   Load param plugin ok
   Initializes OMS mount path ok
   Parameter check ok
   oms deployed
   Please execute ` obd cluster start oms ` to start
   Trace ID: 75241e2a-c133-11f0-910c-00163e1c4eb2
   If you want to view detailed obd logs, please run: obd display-trace 75241e2a-c133-11f0-910c-00163e1c4eb2
   ```

2. Start OMS

   ```shell
   [admin@test ~]$ obd cluster start oms
   ```

   After the cluster starts, the following information is displayed:

   ```shell
   Start oms ok
   OMS health check ok
   +-----------------------------------------------------------+
   |                            oms                            |
   +--------+-------------------+---------------+--------------+
   | region | url               | cm_is_default | nodes        |

   | bj     | 10.10.10.2:8089   | False         | 10.10.10.2   |

   If you want to view detailed obd logs, please run: obd display-trace 796b1a4c-c133-11f0-b9ac-00163e1c4eb2
   ```
