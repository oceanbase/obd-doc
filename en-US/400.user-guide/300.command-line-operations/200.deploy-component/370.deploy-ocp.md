# Deploy OCP

This topic describes how to deploy OceanBase Cloud Platform (OCP) by using the obd configuration file in a CentOS Linux 7.9 environment based on the x86 architecture.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Currently, obd supports only OCP Community Edition V4.2.1 and later and OCP Enterprise Edition V4.3.5 and later. </p>
</main>

## Prerequisites

* obd is installed on your local server. We recommend that you install the latest version of obd. For more information, see [Install obd](../../../200.quick-start/100.install-obd.md).

* The user and server resources required for OCP deployment are available. <!-- For more information, see the [Installation Planning](https://www.oceanbase.com/docs/common-ocp-1000000002078408) section in the OceanBase Cloud documentation. -->

* The required components (OCP, OceanBase Database, ODP, and so on) are available in the obd image repository.
  
  If the server where obd is installed has access to the Internet, the required components will be automatically downloaded from the remote image repository. If you plan to deploy OCP Enterprise Edition, contact Technical Support to obtain the installation package and use the `obd mirror clone` command to upload the package to the local image repository of obd. After the package is uploaded, you can run the `obd mirror list local` command to view the packages in the local image repository.

* The clockdiff command is installed on the server where OCP is to be deployed.

* If you deploy OCP by using OceanBase Database, make sure that the server where the OBServer nodes are deployed supports the AVX instruction set. You can run the `lscpu | grep Flags | grep avx` command to check whether the server supports the AVX instruction set. This restriction applies only to servers of the x86 architecture.
  
  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>If you use a server of the x86 architecture, the following OceanBase Database versions do not require the server to support the AVX instruction set: </p>
    <ul>
    <li>For OceanBase Database V4.2.x, the version must be V4.2.5.6 or later. </li>
    <li>For OceanBase Database V4.3.x, the version must be V4.3.5.4 or later. </li>
    <li>For OceanBase Database V4.4.x, the version must be V4.4.1.0 or later. </li>
    </ul>
  </main>

* If you deploy OCP by using OceanBase Database in an offline scenario and use a server of the ARM architecture, make sure that the server where the OBServer nodes are deployed supports the LSE instruction set. You can run the `lscpu | grep Flags | grep atomics` command to check whether the server supports the LSE instruction set. If the server does not support the LSE instruction set, download the OceanBase Database installation package with the `nonlse` option and use the `obd mirror clone` command to upload the package to the local image repository of obd.
  
  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>The OceanBase Database installation package with the <code>nonlse</code> option is not included in the OceanBase All-in-One package. </p>
  </main>

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This topic assumes that the server can access the Internet or has the required software (OceanBase Database, ODP, OCP, and so on) installed. </p>
</main>

## Configuration files

obd provides sample configuration files for deploying OCP, which you can modify based on your machine resources.

* If obd is installed by directly downloading it, you can view the sample configuration files provided by obd in the `/usr/obd/example` directory.

* If obd is installed by decompressing the all-in-one installation package, you can view the sample configuration files provided by obd in the `~/.oceanbase-all-in-one/obd/usr/obd/example` directory.

* You can also view the sample configuration files provided by obd in its [GitHub repository](https://github.com/oceanbase/obdeploy/tree/master/example).

The following are the sample configuration files provided by obd for deploying OCP:

* OCP-only deployment: ocp-only-example.yaml

* Distributed deployment + ODP + OCP: distributed-with-obproxy-and-ocp-example.yaml

## Procedure

This section describes how to deploy OCP by using the **standalone deployment** and **OCP deployment with OceanBase Database** methods:

* In standalone deployment, you need to create the meta database and tenants (`ocp_meta` and `ocp_monitor`) for OCP. For more information about how to create a database, see **Deploy OceanBase Database in standalone mode** or [Deploy OceanBase Database by using the graphical interface](../../200.ui-operations/200.use-ui-deploy-oceanbase.md). You can manually create a tenant or create a tenant by using the obd command. <!-- For more information about how to manually create a tenant, see [Create a tenant](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000639951).  -->For more information about how to create a tenant by using the obd command, see the **obd cluster tenant create** command in [Cluster commands](../../../300.obd-command/100.cluster-command-groups.md).

* In OCP deployment with OceanBase Database, you can configure both OceanBase Database and OCP in the configuration file. When you start OCP, it will start the meta database of OCP based on the configured OceanBase Database information.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>obd supports deploying both Community Edition and Enterprise Edition of OCP. This section describes how to deploy Community Edition of OCP. </p>
</main>

tab Standalone deployment of OCP

1. Create a configuration file.

   Run the following command to create a configuration file. Here is an example: ocp-only-example.yaml. You can customize the file name as needed.

   ```shell
   vim ocp-only-example.yaml
   ```

2. Modify the user information.

   You can copy the following content and modify it based on your actual scenario.

   ```yaml
   ## Only need to configure when remote login is required
   user:
     username: admin
   #   password: your password if need
     key_file: /home/admin/.ssh/id_rsa
   #   port: your ssh port, default 22
   #   timeout: ssh connection timeout (second), default 30
   ```

   `username` is the username for logging in to the target server. Make sure that your username has write permissions for the home directory. Both `password` and `key_file` are used for user verification. Usually, you only need to fill in one of them.

   <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>After you configure the key path, if your key does not require a password, comment out or delete <code>password</code> to prevent it from being considered as the key password for login, which may cause verification failure. </p>
   </main>

3. Modify the OCP configuration.

   You can copy the following content and modify it based on your actual scenario. For more information about the configuration items, see [Configuration file description](../100.configuration-file-description.md) under **Description of configuration items**.

   ```yaml
   ocp-server-ce:
     # version: 4.2.2
     # package_hash: 84a65bf0ec004e73b772938696b2b896a0ef2b2f
     # release: 20240315150922.el7
     servers:
       - 10.10.10.1
     global:
       home_path: /home/admin/ocp
       soft_dir: /home/admin/ocp/software
       log_dir: /home/admin/ocp/logs
       ocp_site_url: http://10.10.10.1:8080
       port: 8080
       admin_password: ********
       memory_size: 4G
       jdbc_url: jdbc:oceanbase://10.10.10.2:2881/test
       jdbc_username: root@sys
       jdbc_password: ********
       ocp_meta_tenant:
         tenant_name: ocp_meta
         max_cpu: 2.0
         memory_size: 4G
       ocp_meta_username: root
       ocp_meta_password: ********
       ocp_meta_db: meta_database
       ocp_monitor_tenant:
         tenant_name: ocp_monitor
         max_cpu: 2.0
         memory_size: 4G
       ocp_monitor_username: root
       ocp_monitor_password: ********
       ocp_monitor_db: monitor_database
   ```

4. Deploy OCP.

   ```shell
   obd cluster deploy ocp -c ocp-only-example.yaml
   ```

   In the command, `ocp` is the cluster name. You can customize the cluster name as needed. After the deployment is successful, the command line will output the corresponding startup command, as shown below:

   ```shell
   ocp deployed
   Please execute ` obd cluster start ocp ` to start
   Trace ID: 4e444844-0211-11ef-8e69-00163e0808cc
   If you want to view detailed obd logs, please run: obd display-trace 4e444844-0211-11ef-8e69-00163e0808cc
   ```

5. Start OCP.

   ```shell
   obd cluster start ocp
   ```

   After the startup is successful, the OCP login information will be output, as shown below:

   ```shell
   +----------------------------------------------------------+
   |                      ocp-server-ce                       |
   +---------------------------+----------+----------+--------+
   | url                       | username | password | status |
   +---------------------------+----------+----------+--------+
   | http://10.10.10.1:8080    | admin    | ******** | active |
   +---------------------------+----------+----------+--------+
   ocp running
   Trace ID: ed5a1f4c-0218-11ef-bda1-00163e0808cc
   If you want to view detailed obd logs, please run: obd display-trace ed5a1f4c-0218-11ef-bda1-00163e0808cc
   ```

tab OCP deployment with OceanBase Database

### Step 1: Create a configuration file

Run the following command to create a configuration file. In this example, the file is named `distributed-ocp.yaml`. You can customize the file name as needed.

```shell
vim distributed-ocp.yaml
```

### Step 2: Modify the configuration file

1. Modify the user information.

   You can copy the following content and modify it based on your specific scenario.

   ```yaml
   ## Only need to configure when remote login is required
   user:
     username: admin
   #   password: your password if need
     key_file: /home/admin/.ssh/id_rsa
   #   port: your ssh port, default 22
   #   timeout: ssh connection timeout (second), default 30
   ```

   `username` is the username used to log in to the target machine. Ensure that your username has write permissions for the home directory. Both `password` and `key_file` are used to verify the user. Typically, you only need to fill in one of them.

   <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>After configuring the key path, if your key does not require a password, please comment out or delete <code>password</code> to avoid it being considered the key password for login, which may cause verification failure.</p>
   </main>

2. Modify the OceanBase Database configuration.

   You can copy the following content and modify it based on your specific scenario.

   ```yaml
   oceanbase-ce:
     version: 4.3.5.3
     # release: 100000242024032211.el7
     # package_hash: c4a03c83614f50c99ddb1c37dda858fa5d9b14b7
     servers:
       - name: server1
         ip: 10.10.10.1
       - name: server2
         ip: 10.10.10.2
       - name: server3
         ip: 10.10.10.3
     global:
       appname: obcluster
       cluster_id: 1711955629
       mysql_port: 2881
       rpc_port: 2882
       home_path: /home/admin/oceanbase
       data_dir: /home/admin/oceanbase/data
       redo_dir: /home/admin/oceanbase/redo
       obshell_port: 2886
       scenario: htap
       memory_limit: 64G
       system_memory: 30G
       log_disk_size: 192G
       datafile_size: 192GB
       ocp_meta_tenant:
         tenant_name: ocp_meta
         max_cpu: 2.0
         memory_size: 4G
       ocp_meta_username: root
       ocp_meta_password: ********
       ocp_meta_db: meta_database
       ocp_monitor_tenant:
         tenant_name: ocp_monitor
         max_cpu: 2.0
         memory_size: 8G
       ocp_monitor_username: root
       ocp_monitor_password: ********
       ocp_monitor_db: monitor_database
       proxyro_password: ********
       root_password: ********
       enable_syslog_recycle: true
       enable_syslog_wf: false
       max_syslog_file_count: 4 
       cpu_count: 20
     server1:
       zone: zone1
     server2:
        zone: zone2
     server3:
        zone: zone3
   ```

   For more information about the configuration items of OceanBase Database, see [Configuration file description](../100.configuration-file-description.md) under **Configuration item description**. The following table lists the OCP-related configuration items:

   | Configuration Item  | Required  | Default Value  | Effective After Modification  | Description    |
   |---------|-----------|---------|-----------|-----------|
   | ocp_meta_tenant |  Required  |  tenant_name: meta_tenant</br>max_cpu: 1</br>memory_size: 2147483648 | Redeployment | The information of the OCP metadata tenant.<ul><li>tenant_name: specifies the tenant name of the OCP metadata tenant.</li><li>max_cpu: specifies the maximum number of CPU cores allocated to the OCP metadata tenant.</li><li>memory_size: specifies the memory capacity allocated to the OCP metadata tenant.</li></ul>  |
   | ocp_meta_username | Optional | meta | Restart process | The username for connecting to the OCP metadata tenant. |
   | ocp_meta_password | Required | A random string by default | Restart process  | The password corresponding to the username specified by `ocp_meta_username`. |
   | ocp_meta_db | Optional | meta_database | Redeployment | The name of the database that stores the OCP metadata. |
   | ocp_monitor_tenant | Required | tenant_name: monitor_tenant</br>max_cpu: 1</br>memory_size: 2147483648 | Redeployment  | The information of the OCP monitoring data tenant.<ul><li>tenant_name: specifies the tenant name of the OCP monitoring data tenant.</li><li>max_cpu: specifies the maximum number of CPU cores allocated to the OCP monitoring data tenant.</li><li>memory_size: specifies the memory capacity allocated to the OCP monitoring data tenant.</li></ul>  |
   | ocp_monitor_username | Optional | monitor_user | Restart process | The username for connecting to the OCP monitoring data tenant. |
   | ocp_monitor_password | Required | A random string by default | Restart process | The password corresponding to the username specified by `ocp_monitor_username`. |
   | ocp_monitor_db | Optional | monitor_database | Redeployment | The name of the database that stores the OCP monitoring data. |

3. Modify the ODP configuration.

   You can copy the following content and modify it based on your specific scenario. For more information about the configuration items, see [Configuration file description](../100.configuration-file-description.md) under **Configuration item description**.

   ```yaml
   obproxy-ce:
     # version: 4.2.3.0
     # package_hash: 7ca6c000887b90db111093180e6984bf4cf8f7380a948870f3eb2ac30be38f37

       - oceanbase-ce
     servers:
       - 10.10.10.1
     global:
       home_path: /home/admin/obproxy

       listen_port: 2883
       obproxy_sys_password: ********
       skip_proxy_sys_private_check: true
       enable_strict_kernel_release: false
       enable_cluster_checkout: false
       proxy_id: 5150
       client_session_id_version: 2
   ```

4. Modify the OCP configuration.

   You can copy the following content and modify it based on your specific scenario. For more information about the configuration items, see [Configuration file description](../100.configuration-file-description.md) under **Configuration item description**.

   <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>When deploying OCP based on OceanBase Database, obd will obtain the information of the OCP metadata database from the configuration items under the OceanBase Database component. In this case, the configuration items <code>jdbc_xxx</code> will report errors.</p>
   </main>

   ```yaml
   ocp-server-ce:
     # version: 4.2.2
     # package_hash: 84a65bf0ec004e73b772938696b2b896a0ef2b2f
     # release: 20240315150922.el7
     depends:
       - oceanbase-ce
       - obproxy-ce
     servers:
       - 10.10.10.1
     global:
       home_path: /home/admin/ocp
       soft_dir: /home/admin/ocp/software
       log_dir: /home/admin/ocp/logs
       ocp_site_url: http://10.10.10.1:8080
       port: 8080
       admin_password: ********
       memory_size: 8G
   ```
