# Deploy OCP

This topic describes how to deploy OCP by using an obd configuration file based on the CentOS Linux 7.9 image for the x86 architecture.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Currently, obd supports only OCP Community Edition V4.2.1 and later and OCP Enterprise Edition V4.3.5 and later. </p>
</main>

## Prerequisites

* You have installed obd on your local server. We recommend that you install the latest version of obd. For more information, see [Install obd](../../../200.quick-start/100.install-obd.md).

* The user and server resources required for deploying OCP are available. For more information, see the [Installation Planning](https://www.oceanbase.com/docs/common-ocp-1000000002078408) section in the OceanBase Cloud documentation.

* The clockdiff command is installed on the server where OCP is to be deployed.

* When you deploy OCP by relying on OceanBase Database, make sure that the server where the OBServer node is deployed supports the AVX instruction set (this restriction applies only to servers with the x86 architecture). You can run the `lscpu | grep Flags | grep avx` command to check whether the server supports the AVX instruction set.
  
  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>If you use a server with the x86 architecture, the server does not need to support the AVX instruction set when you deploy OceanBase Database of the following versions: </p>
    <ul>
    <li>V4.2.5.6 or later for V4.2.x. </li>
    <li>V4.3.5.4 or later for V4.3.x. </li>
    <li>V4.4.1.0 or later for V4.4.x. </li>
    </ul>
  </main>

* In an offline deployment scenario, if you deploy OCP by relying on OceanBase Database and use a server with the ARM architecture, check whether the server where the OBServer node is deployed supports the LSE instruction set. You can run the `lscpu | grep Flags | grep atomics` command to check whether the server supports the LSE instruction set. If the server does not support the LSE instruction set, you must download the OceanBase Database installation package with the `nonlse` option and use the `obd mirror clone` command to upload the installation package to the local image library of obd.
  
  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>The OceanBase All in One package does not contain the OceanBase Database installation package with the <code>nonlse</code> option. </p>
  </main>

## Configuration files

obd provides sample configuration files for deploying OCP. You can modify these files based on your machine's resources.

* If you installed obd by directly downloading it, you can view the sample configuration files in the `/usr/obd/example` directory.

* If you installed obd by decompressing the all-in-one installation package, you can view the sample configuration files in the `~/.oceanbase-all-in-one/obd/usr/obd/example` directory.

* You can also view the sample configuration files in the [GitHub repository](https://github.com/oceanbase/obdeploy/tree/master/example) of obd.

The following are the sample configuration files provided by obd for deploying OCP:

* Deploy OCP separately: ocp-only-example.yaml

* Deploy OCP in a distributed manner with ODP: distributed-with-obproxy-and-ocp-example.yaml

## Procedure

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>obd supports deploying both the Community Edition and Enterprise Edition of OCP. This topic describes how to deploy the Community Edition of OCP. </p>
</main>

### Step 1: Obtain the required installation package.

1. Download the installation package.

   Visit [OceanBase Download Center](https://en.oceanbase.com/softwarecenter) and search for **OceanBase Cloud Console**. Download the required installation package and upload it to a directory of the OBDA controller node.

   If you cannot obtain the required installation package from the Download Center, contact the technical support engineer.

2. Decompress the installation package.

   In the directory where the package is located, run the following command to decompress it:

   ```shell
   [admin@test001 ~]$ tar -xzf ocp-all-in-one-*.tar.gz
   ```

3. (Optional) Uninstall the original obd.

   If the obd is installed by using the All in One package, you can run the following command to uninstall obd.

   ```shell
   [admin@test001 ~]$ cd ocp-all-in-one/bin && bash uninstall.sh
   ```

4. Start the installation program.

   Run the `install.sh` script in the `bin` directory of the ocp-all-in-one installation directory to start the installation.

   ```shell
   [admin@test001 bin]$ bash install.sh
   ```

   This script installs obd and copies all packages in the `rpms` directory under the installation directory to the local image library of obd. It also disables the remote image library. After the execution is successful, you see the following output. You can copy and run the `source ~/.oceanbase-all-in-one/bin/env.sh` command to apply the environment configuration.

   ```shell
   add auto set env logic to profile: /home/admin/.bash_profile

   #########################################################################################
    Install Finished
   =========================================================================================
   Setup Environment:              source ~/.oceanbase-all-in-one/bin/env.sh
   Quick Start:                    obd demo
   Use Web Service to install:     obd web
   Use Web Service to upgrade:     obd web upgrade
   More Details:                   obd -h
   =========================================================================================
   ```

### Step 2: Deploy OCP

This section introduces how to deploy OceanBase Cloud in two ways: **Deploy OCP in isolation** and **Deploy OCP with OceanBase Database**.

* When OCP is deployed in isolation, you need to create a metadatabase for OCP and two corresponding tenants (`ocp_meta` and `ocp_monitor`). For more information about how to create a database, see [Deploy OceanBase Database in standalone mode](200.start-the-oceanbase-cluster-by-using-obd.md) or [Deploy OceanBase cluster by using the GUI](../../200.ui-operations/200.use-ui-deploy-oceanbase.md). You can create a tenant manually or run the obd commands. For more information, see [Create a tenant](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000639951) or the **obd cluster tenant create** command in [Cluster commands](../../../300.obd-command/100.cluster-command-groups.md).

* When OceanBase Database is used as the deployment mode of OCP, you can configure OceanBase Database and OCP information in the configuration file. When OCP is started, it starts the metadatabase of OCP based on the OceanBase Database information configured in the configuration file.

:::tab

tab Deploy OCP separately

1. Create a configuration file.

   Run the following command to create a configuration file. Here, ocp-only-example.yaml is used as an example; you can customize the file name as needed.

   ```shell
   vim ocp-only-example.yaml
   ```

2. Modify user information

   You can copy the following text and modify it as needed for your specific scenario.

   ```yaml
   ## Only need to configure when remote login is required
   user:
     username: admin
   #   password: your password if need
     key_file: /home/admin/.ssh/id_rsa
   #   port: your ssh port, default 22
   #   timeout: ssh connection timeout (second), default 30
   ```

   `username` specifies the username for logging in to the target machine. Make sure that your username has write permissions for the home directory. Typically, you need to specify only one of `password` or `key_file`.

   <main id="notice" type='notice'>
      <h4>Note</h4>
      <p>After you specify the key path, if no password is required, comment on or remove the <code>password</code> parameter to avoid the key login validation failure. Otherwise, the system considers the <code>password</code> parameter as the password of the key and logs in by using the key. However, the system fails to validate the key password. </p>
   </main>

3. Modify the OCP configurations.

   You can copy the following content and modify it according to your actual scenario. For more information about the parameters, see **Parameter Description** in [Description of parameters](../100.configuration-file-description.md).

   ```yaml
   ocp-server-ce:
     # version: 4.2.2
     # package_hash: 84a65bf0ec004e73b772938696b2b896a0ef2b2f
     # release: 20240315150922.el7
     servers:
       - 10.10.10.1
     global:
       home_path: /home/admin/ocp
       soft_dir: /home/admin/ocp/software
       log_dir: /home/admin/ocp/logs
       ocp_site_url: http://10.10.10.1:8080
       port: 8080
       admin_password: ********
       memory_size: 4G
       jdbc_url: jdbc:oceanbase://10.10.10.2:2881/test
       jdbc_username: root@sys
       jdbc_password: ********
       ocp_meta_tenant:
         tenant_name: ocp_meta
         max_cpu: 2.0
         memory_size: 4G
       ocp_meta_username: root
       ocp_meta_password: ********
       ocp_meta_db: meta_database
       ocp_monitor_tenant:
         tenant_name: ocp_monitor
         max_cpu: 2.0
         memory_size: 4G
       ocp_monitor_username: root
       ocp_monitor_password: ********
       ocp_monitor_db: monitor_database
   ```

4. Install OCP

   ```shell
   obd cluster deploy ocp -c ocp-only-example.yaml
   ```

   The `ocp` in the command is the name of the cluster. You can customize the name according to your business requirements. After the deployment is successful, a command for starting the cluster will be displayed in the command line, as shown in the following example:

   ```shell
   ocp deployed
   Please execute ` obd cluster start ocp ` to start
   Trace ID: 4e444844-0211-11ef-8e69-00163e0808cc
   If you want to view detailed obd logs, please run: obd display-trace 4e444844-0211-11ef-8e69-00163e0808cc
   ```

5. Start OCP.

   ```shell
   obd cluster start ocp
   ```

   After the startup is successful, the login information of OCP is output, as follows:

   ```shell
   +----------------------------------------------------------+
   |                      ocp-server-ce                       |
   +---------------------------+----------+----------+--------+
   | url                       | username | password | status |
   +---------------------------+----------+----------+--------+
   | http://10.10.10.1:8080    | admin    | ******** | active |
   +---------------------------+----------+----------+--------+
   ocp running
   Trace ID: ed5a1f4c-0218-11ef-bda1-00163e0808cc
   If you want to view detailed obd logs, please run: obd display-trace ed5a1f4c-0218-11ef-bda1-00163e0808cc
   ```

Deploy OCP on the basis of OceanBase Database.

### Step 1: Create a configuration file

Execute the following command to create a configuration file, here the configuration file is named `distributed-ocp.yaml`, but you can customize the file name.  Example command:

```shell
vim distributed-ocp.yaml
```

### Step 2: Modify the configuration file

1. Modify the user information

   You can copy the following content and modify it based on your actual scenario.

   ```yaml
   ## Only need to configure when remote login is required
   user:
     username: admin
   #   password: your password if need
     key_file: /home/admin/.ssh/id_rsa
   #   port: your ssh port, default 22
   #   timeout: ssh connection timeout (second), default 30
   ```

   `username` specifies the username for logging in to the target server. Make sure that the username has write permissions for the home directory. `password` and `key_file` are both used to verify the user. In most cases, you only need to specify one of them.

   <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>After you specify the key path, if your key does not require a password, comment on or delete <code>password</code> to avoid <code>password</code> being considered as the key password for login, which may cause verification failure. </p>
   </main>

2. Modify the OceanBase Database configuration

   You can copy the following content and modify it based on your actual scenario.

   ```yaml
   oceanbase-ce:
     version: 4.3.5.3
     # release: 100000242024032211.el7
     # package_hash: c4a03c83614f50c99ddb1c37dda858fa5d9b14b7
     servers:
       - name: server1
         ip: 10.10.10.1
       - name: server2
         ip: 10.10.10.2
       - name: server3
         ip: 10.10.10.3
     global:
       appname: obcluster
       cluster_id: 1711955629
       mysql_port: 2881
       rpc_port: 2882
       home_path: /home/admin/oceanbase
       data_dir: /home/admin/oceanbase/data
       redo_dir: /home/admin/oceanbase/redo
       obshell_port: 2886
       scenario: htap
       memory_limit: 64G
       system_memory: 30G
       log_disk_size: 192G
       datafile_size: 192GB
       ocp_meta_tenant:
         tenant_name: ocp_meta
         max_cpu: 2.0
         memory_size: 4G
       ocp_meta_username: root
       ocp_meta_password: ********
       ocp_meta_db: meta_database
       ocp_monitor_tenant:
         tenant_name: ocp_monitor
         max_cpu: 2.0
         memory_size: 8G
       ocp_monitor_username: root
       ocp_monitor_password: ********
       ocp_monitor_db: monitor_database
       proxyro_password: ********
       root_password: ********
       enable_syslog_recycle: true
       enable_syslog_wf: false
       max_syslog_file_count: 4 
       cpu_count: 20
     server1:
       zone: zone1
     server2:
        zone: zone2
     server3:
        zone: zone3
   ```

   For more information about the OceanBase Database configuration parameters, see **Configuration parameters** in [Configuration file description](../100.configuration-file-description.md). The following table describes the OCP-related configuration parameters.

   | Parameter  | Required  | Default value  | Effective after modification | Description    |
   |---------|-----------|---------|-----------|-----------|
   | ocp_meta_tenant |  Yes  |  tenant_name: meta_tenant</br>max_cpu: 1</br>memory_size: 2147483648 | Redeployment | The information about the OCP metadata tenant. <ul><li>tenant_name: specifies the tenant name of the OCP metadata tenant. </li><li>max_cpu: specifies the maximum number of CPU cores allocated to the OCP metadata tenant. </li><li>memory_size: specifies the memory size allocated to the OCP metadata tenant. </li></ul>  |
   | ocp_meta_username | No | meta | Restart the process | The username for connecting to the OCP metadata tenant. |
   | ocp_meta_password | Yes | A random string | Restart the process  | The password of the username specified by `ocp_meta_username`. |
   | ocp_meta_db | No | meta_database | Redeployment | The name of the database where OCP metadata is stored. |
   | ocp_monitor_tenant | Yes | tenant_name: monitor_tenant</br>max_cpu: 1</br>memory_size: 2147483648 | Redeployment  | The information about the OCP monitoring data tenant. <ul><li>tenant_name: specifies the tenant name of the OCP monitoring data tenant. </li><li>max_cpu: specifies the maximum number of CPU cores allocated to the OCP monitoring data tenant. </li><li>memory_size: specifies the memory size allocated to the OCP monitoring data tenant. </li></ul>  |
   | ocp_monitor_username | No | monitor_user | Restart the process | The username for connecting to the OCP monitoring data tenant. |
   | ocp_monitor_password | Yes | A random string | Restart the process | The password of the username specified by `ocp_monitor_username`. |
   | ocp_monitor_db | No | monitor_database | Redeployment | The name of the database where OCP monitoring data is stored. |

3. Modify the ODP configuration

   You can copy the following content and modify it based on your actual scenario. For more information about the ODP configuration parameters, see **Configuration parameters** in [Configuration file description](../100.configuration-file-description.md).

   ```yaml
   obproxy-ce:
     # version: 4.2.3.0
     # package_hash: 7ca6c000887b90db111093180e6984bf4cf8f7380a948870f3eb2ac30be38f37
     # release: 3.el7
     depends:
       - oceanbase-ce
     servers:
       - 10.10.10.1
     global:
       home_path: /home/admin/obproxy
       prometheus_listen_port: 2884
       listen_port: 2883
       obproxy_sys_password: ********
       skip_proxy_sys_private_check: true
       enable_strict_kernel_release: false
       enable_cluster_checkout: false
       proxy_id: 5150
       client_session_id_version: 2
   ```

4. Modify the OCP configuration

   You can copy the following content and modify it based on your actual scenario. For more information about the OCP configuration parameters, see **Configuration parameters** in [Configuration file description](../100.configuration-file-description.md).

   <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>When you deploy OCP based on OceanBase Database, obd obtains the information about the OCP metadata database from the configuration parameters of the OceanBase Database component. In this case, the configuration parameters <code>jdbc_xxx</code> will be reported as errors. </p>
   </main>

   ```yaml
   ocp-server-ce:
     # version: 4.2.2
     # package_hash: 84a65bf0ec004e73b772938696b2b896a0ef2b2f
     # release: 20240315150922.el7
     depends:
       - oceanbase-ce
       - obproxy-ce
     servers:
       - 10.10.10.1
     global:
       home_path: /home/admin/ocp
       soft_dir: /home/admin/ocp/software
       log_dir: /home/admin/ocp/logs
       ocp_site_url: http://10.10.10.1:8080
       port: 8080
       admin_password: ********
       memory_size: 8G
   ```

### Step 3: Deploy OCP

1. Deploy OCP

   ```shell
   obd cluster deploy ocp -c distributed-ocp.yaml
   ```

   In the preceding command, `ocp` specifies the cluster name, which you can customize as needed. After the deployment is successful, the command line outputs the corresponding startup command, as shown in the following example:

   ```shell
   ocp deployed
   Please execute ` obd cluster start ocp ` to start
   Trace ID: 990e7dba-0223-11ef-ab25-00163e0808cc
   If you want to view detailed obd logs, please run: obd display-trace 990e7dba-0223-11ef-ab25-00163e0808cc
   ```

2. Start OCP

   ```shell
   obd cluster start ocp
   ```

   After the startup is successful, the cluster information is output, as shown in the following example:

   ```shell
   +-------------------------------------------------+

   +-------------------------------------------------+
   ```
