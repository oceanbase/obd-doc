# Upgrade ODP

This topic describes how to upgrade ODP by using the obd CLI.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>obd supports upgrading ODP Community Edition and ODP Enterprise Edition. This topic uses ODP Community Edition as an example. </p>
</main>

## Prerequisites

Before you start, make sure that you meet the following conditions:

* OBD is installed. We recommend that you install the latest version. For more information, see [Install OBD](../../../200.quick-start/100.install-obd.md).

* The ODP to be upgraded is managed by OBD.

## Procedure

Before you upgrade ODP, make sure that the image repository contains the ODP installation package to be upgraded, and obtain the hash value of the target version. You can choose either of the following two methods based on your machine's situation.

:::tab

tab Online retrieval

If your machine can connect to the public internet, you can use obd to retrieve remote resources after upgrading obd. Follow the steps below.

1. Enable the remote image repository.

   ```shell
   obd mirror enable remote
   ```

   After execution, run the `obd mirror list` command to confirm whether the image repository is enabled. Check if the `Enabled` column for the row corresponding to Type=remote has changed to `True`. If so, the remote image repository is enabled. The output is as follows:

   ```shell

   +----------------------------+--------+---------+----------+------------------+
   | SectionName                | Type   | Enabled | Avaiable | Update Time      |
   +----------------------------+--------+---------+----------+------------------+
   | local                      | local  | -       | True     | 2025-03-25 14:04 |

   | oceanbase.development-kit  | remote | True    | True     | 2025-03-25 13:53 |
   +----------------------------+--------+---------+----------+------------------+
   ```

   ```shell
   obd mirror list oceanbase.community.stable | grep obproxy-ce
   ```

3. Upgrade ODP

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <p>Starting from V3.2.3, the open-source obproxy component has been officially renamed to obproxy-ce. Therefore, if you are upgrading an ODP version earlier than V3.2.3 to V3.2.3 or later, you need to first execute the following <b>script</b> under the obd execution user to modify the meta information. Then, proceed with the upgrade using the commands below.</p>


   In this example, the `obproxy-ce` component of the `test` cluster is upgraded to V4.3.2.0. You need to modify the example based on your actual situation.

   Run the following command in the installation directory of ODP:

   ```shell
   ./bin/obproxy -V
   ```

   The output is as follows, indicating that the current ODP version is V4.3.2.0.

   ```shell
   obproxy (OceanBase 4.3.2.0 42)
   REVISION: 1-local-f877a496d4c55b184ec568599ae565616437034d
   ```

tab offline download

If your machine cannot connect to the network, you can visit [OceanBase Software Download Center](https://en.oceanbase.com/softwarecenter) to search for **OceanBase Database Proxy** and download the ODP installation package. Upload the installation package to the machine where obd is installed. Then, you can follow the steps below to upgrade ODP in the installation package directory.

1. Upload the installation package to the local image library

   ```shell
   obd mirror clone obproxy-ce-*.rpm
   ```

   After uploading, you can execute the `obd mirror list local | grep obproxy-ce` command to view the installation packages in the local image library. The output is as follows:

   ```shell
   | obproxy-ce | 4.3.3.0 | 5.el7   | x86_64 | 19a002976e4de93a407afe6ab4323310edb936cf |
   ```

2. Disable the remote image library

   ```shell
   obd mirror disable remote
   ```

   After execution, you can execute the `obd mirror list` command to confirm whether the image library is closed. If the `Enabled` column of the corresponding line for Type=remote is `False`, it indicates that the remote image source has been disabled. The output is as follows:

   ```shell
   +-----------------------------------------------------------------------------+
   |                            Mirror Repository List                           |
   +----------------------------+--------+---------+----------+------------------+
   | SectionName                | Type   | Enabled | Avaiable | Update Time      |
   +----------------------------+--------+---------+----------+------------------+
   | local                      | local  | -       | True     | 2025-03-25 14:04 |
   | oceanbase.community.stable | remote | False   | False    | 2025-03-25 13:53 |
   | oceanbase.development-kit  | remote | False   | False    | 2025-03-25 13:53 |
   +----------------------------+--------+---------+----------+------------------+
   ```

3. Query the ODP version in the local image library

   ```shell
   obd mirror list local | grep obproxy-ce
   ```

   The output is as follows. The string in the last column is the hash value corresponding to the ODP version.

   ```shell
   | obproxy-ce | 4.3.3.0 | 5.el7   | x86_64 | 19a002976e4de93a407afe6ab4323310edb936cf |
   ```

4. Upgrade ODP

5. Check the ODP version

   Execute the following command in the ODP installation directory:


## FAQ

If you encounter the following issues during the upgrade of ODP:

```bash
Stop obproxy ok
Start obproxy ok
obproxy program health check ok
Connect to obproxy x
```

It indicates that the obd server cannot connect to ODP. The possible reasons are as follows:

1. The proxysys has disabled access from IP addresses other than `127.0.0.1`, preventing the obd server from connecting. In this case, connect to proxysys using the following command:

   ```bash
   obclient -h<obproxy_ip> -uroot@proxysys -P<obproxy_port> -p<obproxy_pwd>
   ```

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <p>If you cannot connect to proxysys using the password you set, try connecting with an empty password or <code>proxysys</code> as the password.</p>
   </main>

   Then execute the `alter proxyconfig set skip_proxy_sys_private_check = true` command.

2. The password for proxysys does not match the one stored in obd. In this case, connect to proxysys using the following command:

   ```bash
   obclient -h<obproxy_ip> -uroot@proxysys -P<obproxy_port> -p<obproxy_pwd>
   ```

   Then execute the `alter proxyconfig set obproxy_sys_password = <obproxy_pwd>` command to update the proxysys password.

   You can set the password to an empty string (`obproxy_sys_password = ''`) or match it with the password stored in the obd configuration file.

## Script

```shell
OBD_HOME=${OBD_HOME:-${HOME}}/.obd
obproxy_repository=${OBD_HOME}/repository/obproxy
obproxy_ce_repository=${OBD_HOME}/repository/obproxy-ce

function shadow_repo() {
    repository_path=$1
    ce_repository_path=$2
    [[ $repository_path =~ ^/  ]] && a=$repository_path || a=`pwd`/$repository_path
    while [ -h $a ]
    do
        b=`ls -ld $a|awk '{print $NF}'`
        c=`ls -ld $a|awk '{print $(NF-2)}'`
        [[ $real_patn =~ ^/ ]] && a=$b  || a=`dirname $c`/$b
    done
    instance_hash=`basename $a`
    ce_version_path=`dirname ${ce_repository_path}`
    ln -sf ${ce_version_path}/${instance_hash} ${ce_repository_path}
}

function copy_repository() {
    VS=(`ls $obproxy_repository`)
    for version in ${VS[@]}; do
        version_path="${obproxy_repository}/${version}"
        ce_version_path="${obproxy_ce_repository}/${version}"
        repositories=(`ls $version_path`)
        mkdir -p $ce_version_path
        for repository in ${repositories[@]}; do
            repository_path="${version_path}/${repository}"
            ce_repository_path="${ce_version_path}/${repository}"
            if [ -d "$ce_repository_path" ];
            then
                echo "${ce_repository_path} exist"
            else
                if [ -L ${repository_path} ];
                then
                    shadow_repo ${repository_path} ${ce_repository_path}
                else
                    cp -r ${repository_path} ${ce_repository_path}
                fi
            fi
        done
    done
}

function change_cluster_meta() {
    cluster_home_path=${OBD_HOME}/cluster
    CS=(`ls ${cluster_home_path}`)
    for cluster in ${CS[@]}; do
        cluster_path=${cluster_home_path}/$cluster
        if [ -f ${cluster_path}/.data ]; then
            sed -i 's/^  obproxy:/  obproxy-ce:/g' ${cluster_path}/.data
        fi
        sed -i 's/^obproxy:/obproxy-ce:/' ${cluster_path}/*.yaml
    done
}

copy_repository && change_cluster_meta && echo 'ok'
```
