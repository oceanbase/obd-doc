# Switch the synchronization mode between primary and standby tenants

This topic describes how to switch the synchronization mode between primary and standby tenants by using obd. You can switch the synchronization mode between **network-based** and **archiving-based**.

:::tab

tab Switch from network-based synchronization to archiving-based synchronization

## Prerequisites

The source tenant (the primary tenant or another standby tenant) must have performed data backup and log archiving. For more information, see the **Tenant backup** section in [Backup and restore](../1200.backup-and-recovery.md).

## Procedure

Assume that two clusters, clusterA and clusterB, exist, and that a primary tenant named A_a has been created in clusterA, while a standby tenant named B_a has been created in clusterB using the network method. This example demonstrates how to switch the synchronization method between the primary and standby tenants from network-based to archive-based.

1. Switch the synchronization method

   ```shell
   obd cluster tenant switch-log-source clusterB B_a --type=LOCATION -a 'oss://oceanbase-test-bucket/backup/log?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=delete&checksum_type=md5'
   ```

   For more information about the command, see [obd cluster tenant switch-log-source](../../../../300.obd-command/100.cluster-command-groups.md).

   The command output is as follows:

   ```shell
   Get local repositories ok
   obshell program health check ok
   Check obshell version ok
   Get deployment connections ok
   source type check ok
   standby uri checking ok
   switching log resource ok
   Trace ID: 588ffb14-42ab-11f0-b3d9-00163e49531b
   If you want to view detailed obd logs, please run: obd display-trace 588ffb14-42ab-11f0-b3d9-00163e49531b
   ```

2. View the tenant information

   ```shell
   obd cluster tenant show clusterB -t B_a -g
   ```

   The output is as follows, where `primary_tenant_info` displays the directory path for archive logs, indicating that the synchronization method has been switched to archive-based.

tab Switch to network-based synchronization

## Background information

If the primary tenant does not have complete logs but you want to use network-based synchronization, you can first create a standby tenant based on the archive. Once the standby tenant is created, you can follow the steps in this section to switch the synchronization method to network-based. For more information about how to create a standby tenant based on the archive, see [Create a standby tenant](100.deploy-physical-standby-database.md).

## Prerequisites

Log continuous synchronization is enabled for the standby tenant. The command is `obd cluster tenant recover`. For more information about this command, see [obd cluster tenant recover](../../../../300.obd-command/100.cluster-command-groups.md).



## Procedure

Assume that there are two clusters, clusterA and clusterB. A primary tenant named A_a is created in clusterA, and a standby tenant named B_a is created in clusterB by using the archive method. This example shows how to switch the synchronization method from the archive method to the network method.

1. Switch the synchronization method.

   ```shell
   obd cluster tenant switch-log-source clusterB B_a --type=SERVICE -p *******
   ```

   For more information about the command, see [obd cluster tenant switch-log-source](../../../../300.obd-command/100.cluster-command-groups.md) in the Cluster Command Groups topic.

   The execution output is as follows:

   ```shell
   Get local repositories ok
   obshell program health check ok
   Check obshell version ok
   Get deployment connections ok
   source type check ok
   Create standbyro user ok
   switching log resource ok
   Trace ID: 5b8a866e-42aa-11f0-8eff-00163e49531b
   If you want to view detailed obd logs, please run: obd display-trace 5b8a866e-42aa-11f0-8eff-00163e49531b
   ```

2. View the tenant information.

   ```shell
   obd cluster tenant show clusterB -t B_a -g
   ```
