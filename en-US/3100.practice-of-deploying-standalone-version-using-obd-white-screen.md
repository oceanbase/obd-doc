# Deploy a Community Edition cluster by using the obd GUI

This topic describes how to prepare resources and configure parameters before deployment and how to quickly deploy a Community Edition distributed cluster by using the obd GUI.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>obd supports deployment of OceanBase Database Community Edition and OceanBase Database Enterprise Edition. This topic describes how to deploy OceanBase Database Community Edition by using the obd GUI. </p>
</main>

## Server configuration

The following table describes the server configuration used in this example.

| Category | Configuration |
| ---- | ---- |
| Number of servers | 4 |
| CPU | 8 x86_64 cores |
| Operating system | CentOS Linux release 8.5.2111 |
| Kernel | 4.18.0-348.7.1 |
| Available memory | 32 GB |
| Disk | SSD storage. The installation directory occupies 196 GB, the log directory occupies 2 TB, and the data directory occupies 2 TB. |

<main id="notice" type='explain'>
  <h4>Note</h4>
  <ul>
  <li><p>In a production environment, the server must meet the minimum resource requirements (4 cores and 16 GB of memory). For long-term use, the available memory must be at least 32 GB. Note that the memory limit refers to the value in the <code>available</code> column of the output after you execute the <code>free -g</code> command. </p></li>
  <li><p>If the number of CPU cores is less than 8, the minimum CPU count for OceanBase Database is set to 8 by default. A low CPU count will negatively affect the performance of OceanBase Database. </p></li>
  </ul>
</main>

### Deployment mode

This example uses a three-replica deployment mode. We recommend that you deploy the system on four servers. You can choose a suitable deployment mode based on your actual situation. The following table describes the usage of the four servers:

|     Role      |                Server                |                   Remarks                    |
| ------------- | ---------------------------------- | ----------------------------------------- |
| obd           | 10.10.10.4                         | The automated deployment software installed on the control server.            |
| OBServer node | 10.10.10.1                         | The OceanBase Database zone 1.                    |
| OBServer node | 10.10.10.2                         | The OceanBase Database zone 2.                    |
| OBServer node | 10.10.10.3                         | The OceanBase Database zone 3.                    |
| ODP (also known as OBProxy)           | 10.10.10.1, 10.10.10.2, and 10.10.10.3                         | The proxy server for OceanBase Database.        |
| OBAgent       | 10.10.10.1, 10.10.10.2, and 10.10.10.3 | The monitoring and data collection framework for OceanBase Database.              |
| obconfigserver | 10.10.10.4                        | Provides metadata registration, storage, and query services for OceanBase Database. |
| Prometheus    | 10.10.10.4                         | An open-source service monitoring system and time series database. It provides a general data model and fast data collection, storage, and query interfaces. |
| Grafana       |  10.10.10.4    | An open-source data visualization tool. It can visualize various metrics from data sources to help you better understand the system status and performance. |

## Check the server's software and hardware configurations

Before you deploy OceanBase Database, you must check the server's software and hardware configurations to ensure the deployment is successful. 

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>You must check the server for each OBServer node. </p>

### Hardware environment

#### Check whether the CPU supports AVX instructions

<main id="notice" type='explain'>

  <p>This check applies only to servers with the x86 architecture. If you use a server with a different architecture, you can ignore this section. </p>

## Pre-deployment configuration

Before you deploy OceanBase Database Community Edition, you must perform the following configurations.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Each OBServer node must be configured as described in this section. </p>
</main>

### Plan the directories

To deploy OceanBase Database Community Edition, you need to plan the following three directories. The file system type must be XFS or EXT4.

* Installation directory: the directory for storing the software of OceanBase Database and system logs during its operation. The space should be at least 25 GB to ensure performance.
* Log directory: the directory for storing logs of OceanBase Database. The space should be at least twice the size of the memory. We recommend that you configure the space to be at least three times the size of the memory.
* Data directory: the directory for storing data. The space should be at least twice the size of the memory. The actual space depends on the size of the data to be stored.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>If the capacity of the directory of a mount point exceeds 16 TB, only the XFS file system is supported. </p>
</main>

To ensure the stability of the system, we recommend that you use different physical disks for the three directories. If physical resources are limited, OceanBase Database also supports the use of the same disk for the data directory and the log directory. However, we recommend that you do not use this configuration for business scenarios with high write pressure.

The IOPS requirements for disks are as follows:

* If the installation directory, log directory, and data directory are located on different disks, the IOPS of each disk must be at least 1000.
* If the installation directory, log directory, and data directory are located on the same disk, the IOPS of the disk must be at least 3000.

### Configure clock synchronization

When you deploy a distributed OceanBase cluster, you must ensure that the time is synchronized across all servers in the cluster. Otherwise, the cluster cannot be started, and services will encounter exceptions during operation. The maximum allowed time deviation in an OceanBase cluster is 2 seconds. If the time deviation exceeds 2 seconds, the cluster will be in a state without a leader. After restoring clock synchronization, you can restart the OceanBase cluster to restore normal operation.

<main id="notice" type='explain'>
   <h4>Note</h4>
   <p>This example only shows the operation on one server. You must perform the following steps on all servers in the cluster. </p>
</main>

1. Install the chrony service

   ```shell
   [root@test001 ~]# yum -y install chrony
   ```

2. Configure the chrony file

   ```shell
   [root@test001 ~]# vim /etc/chrony.conf
   ```

   Here is an example configuration:

   ```conf
   # Use Alibaba NTP server
   # Public NTP
   # Alicloud NTP
   ##Synchronize time with multiple NTP servers provided by Alibaba Cloud to improve the reliability and fault tolerance of time synchronization.
   ##minpoll 4 specifies the minimum synchronization interval between the NTP client and server as 16 seconds (when the time deviation is small).
   ##maxpoll 10 specifies the maximum synchronization interval between the NTP client and server as 1024 seconds (when the time deviation is large).
   ##iburst specifies that 4 NTP packets are sent quickly (with 2-second intervals) upon initial or reconnection to accelerate time synchronization and reduce the initial synchronization time deviation.
   server ntp.cloud.aliyuncs.com minpoll 4 maxpoll 10 iburst
   server ntp.aliyun.com minpoll 4 maxpoll 10 iburst
   server ntp1.aliyun.com minpoll 4 maxpoll 10 iburst
   server ntp1.cloud.aliyuncs.com minpoll 4 maxpoll 10 iburst
   server ntp10.cloud.aliyuncs.com minpoll 4 maxpoll 10 iburst
   server ntp11.cloud.aliyuncs.com minpoll 4 maxpoll 10 iburst
   server ntp12.cloud.aliyuncs.com minpoll 4 maxpoll 10 iburst
   server ntp2.aliyun.com minpoll 4 maxpoll 10 iburst
   server ntp2.cloud.aliyuncs.com minpoll 4 maxpoll 10 iburst
   server ntp3.aliyun.com minpoll 4 maxpoll 10 iburst
   server ntp3.cloud.aliyuncs.com minpoll 4 maxpoll 10 iburst
   server ntp4.aliyun.com minpoll 4 maxpoll 10 iburst
   server ntp4.cloud.aliyuncs.com minpoll 4 maxpoll 10 iburst
   server ntp5.aliyun.com minpoll 4 maxpoll 10 iburst
   server ntp5.cloud.aliyuncs.com minpoll 4 maxpoll 10 iburst
   server ntp6.aliyun.com minpoll 4 maxpoll 10 iburst
   server ntp6.cloud.aliyuncs.com minpoll 4 maxpoll 10 iburst
   server ntp7.cloud.aliyuncs.com minpoll 4 maxpoll 10 iburst
   server ntp8.cloud.aliyuncs.com minpoll 4 maxpoll 10 iburst
   server ntp9.cloud.aliyuncs.com minpoll 4 maxpoll 10 iburst
   
   # Ignore stratum in source selection.
   stratumweight 0.05
   
   # Record the rate at which the system clock gains/losses time.
   ##Calculate the rate at which the server gains or loses time based on the actual time and record it to /var/lib/chrony/drift. After the system restarts, the system will make the best time compensation adjustment.
   driftfile /var/lib/chrony/drift
   
   # Enable kernel RTC synchronization.
   ##Enable a kernel mode in which the system time is copied to the real-time clock (RTC) every 11 minutes.
   rtcsync
   
   # In the first three updates, the system clock is adjusted instead of slewed.
   # if the adjustment is larger than 10 seconds.
   makestep 10 3

   #allow 192.168/16

   bindcmdaddress 127.0.0.1
   bindcmdaddress ::1
   ```

    After saving the information, click **Create Business Tenant** in the lower-right corner of the deployment success page to enter the business tenant creation process.

    ![Deployment](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V4.0.0/zh-CN/200.use-ui-deploy-oceanbase-06.png)

11. Create a business tenant

    On the **Create Business Tenant** page, configure the corresponding parameters and click **Next: Create Business Tenant**. The system will create the corresponding tenant.

    ![Configuration](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V3.6.0/deploy-by-gui/200.use-ui-deploy-oceanbase-07.png)

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>In this example, the maximum resource usage is configured for the tenant. In actual deployment, you can choose the maximum, minimum, or custom resource usage based on your requirements. </p>
    </main>

    After the tenant is created, the business tenant information, including the tenant name, root user password, and connection string, will be displayed on the page. Click the **Copy** button next to **Tenant Root Password** and **Connection String** to save the corresponding information.

    ![Creation successful](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V3.6.0/deploy-by-gui/200.use-ui-deploy-oceanbase-10.png)

    After saving the information, click **Exit** in the lower-left corner to exit the tenant creation process. Then, click **Exit** on the deployment result page to exit the deployment program.
